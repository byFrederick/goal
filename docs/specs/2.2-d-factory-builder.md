# 2.2-D — Factory builder

Status: draft for review · depends on B (definitions and versions), C (app shell) · tag `builder` · (restructure) no longer depends on credentials: they arrive in phase 4

## 1. Summary

D ships one factory editor in the browser, used two ways:

- The **New factory** wizard (`/o/:org/new/:step`): Start → Basics → Line → Agents → Connections → Review and publish.
- **Definition** (`/o/:org/f/:factory/definition/:section`): the same sections on an existing factory's draft. You can jump to any section. Each section shows its state. It also has autosave, Discard draft, version history and publish.

Both have a Visual | YAML toggle over one draft, kept lossless by phase B's draft, factory-model and compare API.

D's backend is small:
- editor metadata (models, capabilities);
- a skills.sh skills catalog kept in the bucket and vendored into drafts;
- enforcement of the weekly budget (B ships its schema);
- the factory's purpose added to every agent task.

### 4.2 Weekly budget enforcement (B ships schema and model only)

- `config` → `domain.Runtime.WeeklyUSD float64` and `OnExhausted domain.BudgetPolicy` (`BudgetDrain` (default), `BudgetStop`).
- **Engine:**
  - Each tick, for each factory with `WeeklyUSD > 0`, the engine reads `Store.SpendSince(ctx, factory, now − 7×24h)` once.
  - At or over the cap, claims at agent stations are skipped. Queue and human stations still move, so approvals and merges continue.
  - `BudgetStop` also cancels the factory's running tasks through a per-run cancel each instance keeps for its own runs (D1 adds it; E10's `Interrupt` can reuse it). Items return to their queue with a new `agent_cancelled` event, data `{reason: "budget"}`.
  - When the spend falls under the cap (the window moves, or the cap is raised by a publish), claims resume.
  - Transitions log `budget_exhausted` / `budget_resumed`.
- Not an andon pull: no person needs to clear it. E shows `budget_exhausted` on the Board (contract).
- **Engine tests** (fake `Clock`, fake store): `TestWeeklyBudget_DrainSkipsAgentClaimsOnly`, `TestWeeklyBudget_StopCancelsRunningAndRequeues`, `TestWeeklyBudget_ResumesWhenWindowMoves`, `TestWeeklyBudget_UnsetMeansUnlimited`.

`ports.Store` gains:

```go
// SpendSince is the summed cost_usd of the factory's agent runs started at or after since.
SpendSince(ctx context.Context, factory domain.FactoryID, since time.Time) (float64, error)
```

### 4.3 Purpose in every task

`config` maps `metadata.purpose` (or legacy `description`) to `domain.Line.Purpose`. The engine puts it in `ports.TaskSpec.Purpose` and the task file (`purpose`). When it is non-empty, the worker (`worker/src/agent.ts`) prefixes the appended system prompt with `## This factory\n<purpose>\n\n`. This keeps the Basics promise "Agents read this before every item".

Tests: engine `TestStart_PurposeReachesTask`; worker Vitest `agentQuery` asserting the block and its absence when empty.

## 5. Ports and adapters

### 5.1 `ports.SkillSource` (new; used only by `goal catalog skills sync`)

```go
// SkillRef names one skill on skills.sh: owner/repo@skill, at a commit when Commit is set.
type SkillRef struct{ Owner, Repo, Skill, Commit string }

type SkillListing struct {
	Ref         SkillRef
	Description string
	Installs    int64
}

// SkillTree is a skill folder at one commit; SKILL.md is at its root.
type SkillTree struct {
	Ref   SkillRef          // Commit resolved
	Files map[string][]byte // relative, slash-separated paths
}

type SkillSource interface {
	// Search lists directory entries matching query, most installed first.
	Search(ctx context.Context, query string, limit int) ([]SkillListing, error)
	// Fetch resolves ref (the default branch head when Commit is empty) and returns its files.
	// Errors wrap ErrNotFound for an unknown skill and ErrTooLarge beyond the limits.
	Fetch(ctx context.Context, ref SkillRef) (SkillTree, error)
}
```

**`internal/adapters/skillssh`** implements it:
- `Search` calls the skills.sh API's documented `GET /api/v1/skills/search?q=&limit=` (`GOAL_SKILLS_DIRECTORY_URL`, default `https://skills.sh`). (D3) That API requires a bearer token (`GOAL_SKILLS_DIRECTORY_TOKEN`, optional); without one `--search` fails with a hint and the curated `sources.yaml` is the way in (open question 2's answer). Only GitHub-hosted entries are kept.
- `Fetch` resolves the commit and reads the skill folder through GitHub's REST API (`GOAL_GITHUB_API_URL`; `GOAL_GITHUB_TOKEN` from the operator's environment is optional and never logged). It uses the `skillPath` conventions of `skills-lock.json` (`<skill>/SKILL.md`, `skills/<skill>/SKILL.md`), else the one folder named `<skill>` with a SKILL.md in the commit's tree (two are ambiguous and refused). (D3) It reads git objects only (commit → tree → blobs), checks the limits from the tree before downloading, checks every blob's size and git object id, refuses symlinks and submodules, and leaves hidden files out (a definition may not hold them).
- **Limits:** 200 files, 1 MiB per skill, regular files only, no symlinks, no paths with `..`. Redirects are followed only within the API host. Timeouts are set and credentials are scrubbed from errors.
- Unit tests run against `httptest`.

### 5.2 `internal/builder` (new)

The package may import `domain`, `ports` and `config`. It never imports adapters, `engine`, `api`, `authoring`, `factorymodel` or cloud SDKs; a new depguard rule `builder` enforces this, and the `api` rule gains a deny for `internal/builder` (review). `internal/api` reaches it through a small `Builder` interface of its own, and `cmd/goald` wires `*builder.Service`. (D3) So that interface can name them, the catalog's types (`SkillKey`, `CatalogSkill`, `SkillPage`, `Model`, `EditorCapabilities`, `BuilderMeta`), its limits and its refusals (`ErrSkillNotFound` → 404 `skill-not-found`, `ErrCatalogUnavailable` → 503 `catalog-unavailable`) live in `internal/domain/skill.go`; `builder` gives them the names below as aliases.

```go
type Config struct {
	Models       []Model      // from GOAL_MODELS; first is the default
	Capabilities Capabilities // set in cmd/goald; Phase 4 flips its flags in its wiring PR
}
type Model struct{ ID, Label string }
type Capabilities struct{ Connectors, ToolApprovals bool }

func New(objects ports.ObjectStore, clock ports.Clock, cfg Config) *Service

func (s *Service) Meta(ctx context.Context) Meta
func (s *Service) SearchSkills(ctx context.Context, q string, limit int, after string) (SkillPage, error)
func (s *Service) SkillFiles(ctx context.Context, key SkillKey) (CatalogSkill, map[string][]byte, error)
// CLI only (platform credentials, like `goal storage init`):
func (s *Service) SyncSkills(ctx context.Context, src ports.SkillSource, refs []ports.SkillRef, search []string, top int) (SyncReport, error)
func (s *Service) ListSkills(ctx context.Context, q string) ([]CatalogSkill, error)
```

**Catalog reads**
- They read `catalog/skills/index.json` through `ObjectStore`. The parsed index is kept in memory keyed by the object's version id, re-listed at most every 5 minutes. That is a cache of immutable content, not state.
- A malformed index is logged and treated as empty.
- Search matches key, skill name and description as a case-insensitive substring, ordered by installs desc, then key; `after` is the last key.

**`SyncSkills`**
- Fetches each ref (plus the top N results of each search term).
- Writes `catalog/skills/<owner>/<repo>/<skill>/<commit>/…` when absent, then replaces `index.json` with one `Put`.
- Never deletes folders, because published drafts may have vendored them.

### 5.3 Wiring

- `cmd/goald`: `builder.New(objects, clock, builder.Config{Models: settings.Models, Capabilities: {}})` → `api.Deps.Builder`.
- New setting `GOAL_MODELS`: comma-separated model ids. The default lists the current Claude models, the first being the default, so it matches `runtime.model` defaults.
- `cmd/goal`: `catalog skills …` wires `s3store` (as `storage init` does) and `skillssh.New(...)`.

## 6. Data model

No migration. One query (`queries/runs.sql`) on the existing index `agent_runs_factory_started_idx`:

```sql
-- name: FactorySpendSince :one
SELECT coalesce(sum(cost_usd), 0)::float8 AS spend_usd
FROM agent_runs
WHERE factory_id = sqlc.arg(factory_id) AND started_at >= sqlc.arg(since);
```

- No `org_id` predicate is needed: A's row-level security scopes it. The engine runs it in the factory's org transaction.
- Conformance (`storetest`): it sums only that factory's runs at or after `since`; it returns 0 when there are none; under PostgreSQL, another org's runs are invisible.

### 10.3 The editor frame

**Header** (C's `PageHeader` + `Breadcrumbs` `Acme / goal / Definition`; wizard `Factories / New factory`)
- h1: "Definition" (wizard: the factory name). A `Chip` from B's `Draft`/`Factory` (review): "Draft of v9", "v8" with no draft, or "Draft" for a never-published factory.
- Actions:
  - Visual | YAML: in Definition a `nav aria-label="Editor view"` of two links with `aria-current="page"`; in the wizard a pressed-button group, as on the boards.
  - Versions (→ `versions`), Discard draft…, and Review and publish (primary → `review`).
  - Wizard: "Draft saved 14:32" (`role="status"`) and Save and exit.

**Status line** (`role="status"`, polite)
- "Based on v8, the version running now. Autosaved 14:32." (`Draft.base`, `Draft.current`). When base ≠ current (after a restore): "Based on v7; v8 is running. Review the differences" (→ `review?compare=current..draft`).
- Links: "3 changes in 2 sections" (`Draft.change_count`, sections with changes → `review`) and "⚠ 1 problem" (→ the first problem's section and entity).
- Save states: "Saving…", "Autosaved HH:MM", "Not saved: goald can't be reached. Retrying in 5 s" (backoff 1→30 s, Retry now), "Not saved: the same field changed in another tab or the CLI" (opens the conflict dialog), "Updated elsewhere at 14:35" (10 s after a remote save is merged). (no-auth) With one local user the other writer is another tab or the CLI; Phase 3 names the person.

**Section tiles** (`nav aria-label="Definition sections"`; in YAML mode "…, jump to a block in factory.yaml")
- Five tiles from `Draft.sections`:
  - **problem**: "1 change, 1 problem", rust warning icon, when `problems > 0`;
  - **edited**: "2 changes", pencil icon;
  - **unchanged**: "No changes", empty circle.
- Review and publish shows "Fix N problems first", "Ready to publish" or "No changes".
- In YAML mode the subtitle is the block and its `lines` ("board, lines 31–45").
- The accessible name carries the state ("Connections, 1 change, 1 problem"). The current tile has `aria-current="location"`.

**Wizard steps** (`nav aria-label="New factory steps"`)
- Start plus the five sections, numbered 1–6. Done steps show a check and ", done" in the accessible name. The current step has `aria-current="step"`.
- After step 1, every step is a link. The footer reads Back · "Step 3 of 6" · Continue to <next>.
- "Done" means visited and left with Continue. It is kept in `localStorage["goal.wizard.<factoryId>"]`, a per-viewer convenience; when it is absent, steps with content count as done.
- Resume (C's draft card "Continue setup") opens the first step not done.

**Discard draft…** (`ConfirmDialog`, tone danger)
- Copy: "Discard the draft of v9? 3 changes in 2 sections are lost. v8 keeps running." It calls `DELETE …/draft` with `If-Match` (412 → conflict path).
- Afterwards the frame shows the current version. The first edit opens a new draft (`POST …/draft`) before saving.
- For a never-published factory the wizard instead offers "Delete this draft factory…" (B `DELETE /factories/{factory}`).

**Save and exit:** flush, then go to `/o/:org`. **Cancel** on Start creates nothing.

**Read-only mode** (no-auth): not in 2.2. It exists for people who may not edit, which arrives with phase 3; the local user may edit every factory.

**Draft session** (`draft/session.ts`)
- One instance per mounted editor, provided by context and read through `useSyncExternalStore` selectors. It is not a library and not a global store.
- This is the scoped need ADR 0004 allows: optimistic edits must survive switching sections, and the save queue must outlive any one component.
- State per draft:
  - `revision`;
  - `sections: Record<Section, {server, serverEtag, local, dirty, inFlight}>`;
  - `files: Map<path, {serverSha, text, dirty, inFlight}>`;
  - `edited`, `ranges`, `sections` (B's counts), `validation`;
  - `status: saved | saving | retrying | conflict | offline`, `savedAt`;
  - `undo`/`redo` stacks of `{section, before, after}`.
- **Edits** replace the local value of one section (immutably, through typed helpers in `draft/ops.ts`: `setStationField`, `moveStation`, `addStation`, `removeStation`, `addAgent`, `renameAgent`, `addSkillFromCatalog`, `setBuiltin`, `setBudget`, and so on). They return `{section, value, files?, removeFiles?}`. Helpers that create or rename files (Add agent, Rename, vendoring a skill) return the files to send in the same section save, so B writes them in one revision (B §8.2).
- **Autosave** debounces 800 ms per section or file (B's figure), and also flushes on blur of a text field, on section change and before navigation. There is at most one request in flight per section or file:
  - a section goes to `PUT …/draft/model/{section}` with `If-Match` = the section etag;
  - a text file goes to `PUT …/draft/files/{path}` with `If-Match` = its sha.
  - When no draft exists, the first flush calls `POST …/draft` first.
- **On success** the session adopts `revision`, the new etag or sha and `sections`, then refetches `draftModel` once per burst. Meanwhile local dirty values keep precedence, so typing is never interrupted.
- **412 on a section** (the body carries the current section and etag): `merge.ts` does a three-way merge per leaf pointer (identity arrays matched by `id`/`name`) of base (our last `server`), theirs and ours.
  - Disjoint changes are merged and resent automatically.
  - Overlapping leaves open the conflict dialog, one row per field: "Build's WIP limit also changed elsewhere: theirs 4, yours 2", with Keep theirs / Keep mine per row and Keep all mine.
- **412 on a file:** if their sha equals the one we started from, resend. Otherwise a dialog shows their version beside yours, with Use theirs (yours is copied to the clipboard) or Overwrite with mine.
- **409 `yaml-invalid`** on a section save, when factory.yaml stopped parsing because someone edits it in YAML: the section's changes are held, and Visual shows the parse banner (§10.9).
- **Stream** (B's `definition` event, registered in C's `streamHandlers`):
  - `kind=draft` naming a draft (`version_id`) and a revision this tab saved → ignored (echo). The draft's id is part of the key: a new draft's revisions start again at 1.
  - Otherwise, with nothing dirty in a section, its data is refetched and adopted. Dirty sections keep their local value and merge on their next save.
  - `kind=current` → versions and status line refetch.
  - A discard elsewhere → dialog "This draft was discarded in another tab or the CLI" (Start a new draft / Leave).
  - From phase 4.1: its `credential` event invalidates the factory's credential query.
- **Undo:** Ctrl/Cmd+Z outside text fields and Monaco pops the session's undo stack and saves `before` as a new edit. The "Edited · Undo" link beside a field is different: it calls B's `POST …/draft/model/{section}/revert {pointers}` and reverts to the base version's value.
- **Unsaved-changes guard:** TanStack Router `useBlocker`, plus `beforeunload`, while anything is dirty, in flight, or in `retrying|conflict|offline`.
  - It first awaits a flush, up to 3 s.
  - If something is still unsaved, it shows a dialog: "Your last changes aren't saved yet" with Retry / Leave anyway / Stay.
- As built in D4 (build note): `draft/session.ts` (`DraftSession`: `adopt`, `adoptVersion`, `adoptMissing`, `adoptParseError`, `adoptFile`, `edit`, `editFile`, `flush`, `retryNow`, `resolveSection`, `keepTheirs`, `keepMine`, `resolveFile`, `revert`, `undo`, `redo`, `restart`, `hasUnsaved`, `subscribe`/`getSnapshot`), `draft/use-draft.ts` (`DraftSessionProvider {org, factory}` feeds it `draftModelQuery`, or `versionModelQuery(current)` without a draft; `useDraft(select)`, `useSection`), `draft/merge.ts` (`merge3`, `resolve`), `draft/ops.ts`, `draft/pointer.ts`, and `shared/definition/model.ts` (typed views of `FactoryModel`). Statuses add `held` (factory.yaml does not parse; Visual saves wait) and `failed` (a refusal retrying cannot fix, `error`) to `saved | saving | retrying | conflict | offline`; `offline` is goald unreachable, `retrying` a 5xx/429, both backing off 1, 2, 4, 8, 16, 30 s. Validation stays in B's `validationQuery(revision)` rather than in the session. Undo restores section values, not the files an edit wrote.

## 11. Security and tenancy

**Access** (no-auth)
- No role checks in 2.2: the local user may draft, publish, restore and discard everywhere, and D hides nothing by role. B's handlers pass A's `Authorizer` seam, where phase 3 adds checks.
- `catalog/skills/` is global, read-only and holds no org data.
- Copy-from-another-factory reads only what RLS shows (another org's factory is 404).

**Secrets**
- The editor never receives a secret value. Before phase 4 it shows `env:` reference names only; from phase 4.1, `CredentialSelect` lists names and references are written as `credential:<name>` (restructure).
- Literal header and env values in legacy connections are masked in Visual. YAML shows them because they are already plaintext in the draft; B's `literal-secret` warning says to move them to an `env:` reference (to the vault from phase 4).
- No secret or file content goes in URLs. Search params carry names, ids and line numbers only.

**Untrusted content**
- Prompt previews use `react-markdown` without raw HTML. SKILL.md previews are plain text.
- skills.sh skills are vendored at a pinned commit and show up in Review's diff before they can run. `SkillSource.Fetch` caps size and follows no off-host redirects. Folder paths are validated (no `..`, no absolute paths) on both sync and add. B validates draft paths again (`bad-path`).

**Audit:** none from D's endpoints (read-only). Publishing, restore and discard are B's audit entries. The catalog CLI logs to stdout (an operator action outside any org).
