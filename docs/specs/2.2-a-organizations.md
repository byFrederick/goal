Status: draft for review · migrations `00004–00009` (`00004–00007` used, `00008–00009` unused) · OpenAPI tag `orgs`

## 1. Summary

Goal becomes multi-tenant in its data: every org-owned row carries `org_id`, and PostgreSQL row-level security (RLS) enforces it for `goal_app`, the role goald runs as, while `goal_owner` owns the schema and runs migrations. Every API route moves under `/v1/orgs/{org}/...` with the organization taken from the path, the CLI (`--org`) and the typed TypeScript client follow, the bucket moves under `orgs/<org-id>/`, the stream carries only one organization's events, and the engine claims fairly across organizations within org and factory slot caps. The local install can create, rename and delete organizations; existing data lands in a default organization; an append-only audit log records what happened and by which actor (the local user, an agent or the system).

## 4. Domain and engine changes

### 4.1 Domain (`internal/domain/org.go`, new)

```go
type OrgID string

type Org struct { ID OrgID; Slug, Name, Mark string; MaxSlots int /* 0 = no cap */; CreatedAt time.Time }
type OrgSummary struct { Org; FactoryCount int }

type ActorKind string // "user" | "agent" | "system"
type Actor struct { Kind ActorKind; ID, Name string } // ID: "local", an agent name or a job name

// LocalUser is the only person in 2.2 (no-auth). Phase 4 adds real users; refs stay readable.
var LocalUser = Actor{Kind: ActorUser, ID: "local", Name: "Local user"}

// Ref is how other tables record who did something (`*_by text` columns): "user:local",
// "agent:investigator", "system:engine". ActorFromRef parses it back and fills Name.
func (a Actor) Ref() string
func ActorFromRef(ref string) (Actor, error)

type AuditEntry struct {
	ID int64; At time.Time; Actor Actor
	Action string                 // <noun>.<past_verb>, §11.4
	TargetKind, TargetID string
	FactoryID FactoryID           // optional
	Data map[string]any           // never secrets, tokens or credential values
}

// Org context: set by the API (from the URL, after the org middleware resolves it), by the engine
// (from the line) and by the gateway (from the task token); every Store, Tenancy and Audit method
// that touches org-owned rows reads it.
func WithOrg(ctx context.Context, id OrgID) context.Context
func OrgFrom(ctx context.Context) (OrgID, bool)

// Request actor: set once per request by the API (always LocalUser in 2.2), and by the engine
// and jobs for their own writes.
func WithActor(ctx context.Context, a Actor) context.Context
func ActorFrom(ctx context.Context) (Actor, bool)
```

`domain.Line` gains `OrgID OrgID` and `MaxSlots int`, `domain.Item` gains `OrgID`, and `TaskClaims` gains `OrgID OrgID \`json:"o"\``. A token without `o` fails verification, so tokens issued before the upgrade stop working. That is safe because goald releases runs on SIGTERM.

New errors in `domain`: `ErrInvalid` (a rule was broken: taken slug, reserved slug, confirmation mismatch) and `ErrNoOrg` (missing org context).

### 4.2 Decisions carry an actor

`engine.Approve`, `Reject`, `Retry` and `Merge` take `by domain.Actor` instead of `by string`. The event's `actor` stays the display name, and `data.actor` records `Actor.Ref()`. Request bodies lose `by`, and the CLI loses `--by`: the API passes `domain.ActorFrom(ctx)`, which is `domain.LocalUser` in 2.2 (no-auth). `web/src/shared/actor.ts` is deleted.

### 4.3 Engine across organizations

The engine runs as the system and never bypasses RLS:
- Every store call carries the org of the line it serves: `ctx = domain.WithOrg(ctx, line.OrgID)` for releases, claims, runs, heartbeats and transitions. `work()` keeps that context for the life of the run.
- `Submit`, the decisions and `Merge` require `OrgFrom(ctx) == line.OrgID` and otherwise return `ports.ErrNotFound`, so an API bug cannot submit into another org's factory.
- `SweepLeases` asks `Tenancy.ActiveOrgs` for the live orgs and calls `RequeueExpiredLeases` once per org. A lease on a factory that is no longer loaded is still swept.

**Fair claiming.** `Tick` first releases queue stations line by line, as today. It then claims with two-level round-robin, with `engine.Config.MaxRuns` (`GOAL_MAX_RUNS`, 0 = unlimited) as this instance's cap on concurrent runs:

```
orgs   := orgs of the loaded lines, sorted, rotated by a tick counter
for pass := 0; ; pass++ {
    progress := false
    for each org in orgs, skipping exhausted ones {
        if running >= MaxRuns (MaxRuns > 0) { return }
        try that org's factories round-robin (rotated per org per tick), each factory's agent
        stations in line order, skipping stations already seen empty this tick:
            ClaimNext → start the run; progress = true; next org
            ErrNoWork / ErrSlotTaken → next station
            ErrFactoryFull → skip this factory for the rest of the tick
            ErrOrgFull → mark the org exhausted
        nothing claimed → mark the org exhausted
    }
    if !progress { return }
}
```

Each pass gives every org at most one claim. With `MaxRuns` set, a busy org cannot fill the instance before a quiet org's first item starts. Without it, orgs compete only for their own slots. Any goald instance can run this; the counter and run count are local scheduling hints, not state.

**Why not a SECURITY DEFINER claim function.** A definer function runs as the owner, so every statement inside it bypasses RLS: one bug leaks across orgs. It would also move the claim (slot check, `SKIP LOCKED` pull order, lease insert, event) from sqlc-checked Go into plpgsql, the conformance suite could not run it against the fake, and a global `SKIP LOCKED` across orgs is FIFO by age, so one org's backlog starves the others. Iterating orgs adds no queries: the tick already queries per line and station, and the org is one `set_config` per transaction. The only definer functions return org rows and ids (§6.4), never work rows.

### 4.4 Slot caps

`organizations.max_slots` (all agents running at once across the org's factories) and `factories.max_slots` (per factory) are NULL when unset. `ClaimNext` enforces them in the claim transaction: when either cap is set it takes `pg_advisory_xact_lock(hashtextextended('goal.slots.' || goal_org(), 0))`, counts the org's and the factory's leases and returns `ports.ErrOrgFull` or `ports.ErrFactoryFull` without changing anything. Per-factory caps may add up to more than the org cap, as the board says ("factories wait for each other at peak"). The station WIP rule (the unique `(factory_id, station, slot)` lease) is unchanged.

### 5.2 New (`internal/ports/ports.go`)

```go
// Tenancy keeps organizations. Methods marked (org) act on the organization in ctx; each mutating
// method appends its audit entry (§11.4) in the same transaction, so a change is never unaudited.
type Tenancy interface {
	// Cross-organization reads (SECURITY DEFINER functions, §6.4); they never return work rows.
	Orgs(ctx context.Context) ([]domain.OrgSummary, error)       // every live org of the install, by name
	Org(ctx context.Context, ref string) (domain.Org, error)     // slug or id; ErrNotFound when unknown or deleted
	ActiveOrgs(ctx context.Context) ([]domain.OrgID, error)

	CreateOrg(ctx context.Context, by domain.Actor, n NewOrg) (domain.Org, error)
	UpdateOrg(ctx context.Context, by domain.Actor, u OrgUpdate) (domain.Org, error) // (org)
	DeleteOrg(ctx context.Context, by domain.Actor, now time.Time) error             // (org) soft delete
	// PurgeDeletedOrgs hard-deletes organizations deleted before cutoff and returns their ids. System.
	PurgeDeletedOrgs(ctx context.Context, cutoff time.Time, limit int) ([]domain.OrgID, error)
}

type NewOrg struct { Slug, Name, Mark string }
type OrgUpdate struct {
	Name, Slug, Mark *string
	MaxSlots         *int                     // 0 clears
	FactorySlots     map[domain.FactoryID]int // 0 clears; factories must belong to the org
}

// Audit reads the audit log and appends entries that come with no other change. Other ports
// append their own entries in their transactions. (org)
type Audit interface {
	Append(ctx context.Context, e domain.AuditEntry) error
	AuditLog(ctx context.Context, q AuditQuery) ([]domain.AuditEntry, error) // newest first
}
type AuditQuery struct { Before int64; Limit int; Action, TargetKind, TargetID string; FactoryID domain.FactoryID }
```

`CreateOrg` generates the id, sets `goal.org_id` to it in its transaction and inserts under RLS. Phase 4 narrows `Orgs` to the caller's organizations and adds membership checks behind `Org`; their signatures can stay.

### 5.3 The seams phase 4 builds on (`internal/api`) (no-auth)

**Request actor** (`internal/api/actor.go`). One middleware on every `/v1` route puts `domain.WithActor(ctx, domain.LocalUser)` into the request context. It is the only place a request's actor is created; handlers and the engine read `domain.ActorFrom(ctx)`. Phase 4 replaces this middleware's source (session or token) and nothing else.

**Authorizer** (`internal/api/authz.go`). The single place an authorization decision will go:

```go
// Authorizer decides whether the request's actor may run an operation. 2.2 wires AllowAll,
// which allows everything; phase 4 supplies the real implementation and its permission table.
type Authorizer interface {
	Authorize(ctx context.Context, r AccessRequest) error
}
type AccessRequest struct {
	Actor     domain.Actor
	Operation string           // OpenAPI operationId
	Org       domain.OrgID     // "" for /v1/orgs list and create
	Factory   domain.FactoryID // "" for org-level operations
}
type AllowAll struct{}
func (AllowAll) Authorize(context.Context, AccessRequest) error { return nil }
```

Call sites, all through one helper `s.authorize(ctx, factory)`:
- the `/v1` router middleware, once per request, after the org is resolved (factory "");
- the only two resolvers that turn a path into a factory or item, `s.factory(ctx, ref)` and `s.item(ctx, ref)`, with that factory.

A non-nil error stops the request before the handler acts: an error wrapping `ports.ErrNotFound` answers 404, any other error 403 `forbidden`. `AllowAll` never returns one. Phase 4 decides what its implementation returns.

## 6. Data model

### 6.0 Database roles (outside migrations)

`internal/adapters/postgres/roles.sql` (embedded) is run by `goal db init`, by the integration-test harness and by `task migrate-check` before the migrations. It is idempotent and safe to run concurrently (`duplicate_object` is ignored):

```sql
DO $$ BEGIN
  CREATE ROLE goal_owner NOLOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE;
EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN
  CREATE ROLE goal_app NOLOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE NOINHERIT;
EXCEPTION WHEN duplicate_object THEN NULL; END $$;
```

`goal db init` (admin URL `GOAL_DATABASE_ADMIN_URL`, default compose's `goal` superuser) then:
- runs `ALTER ROLE goal_owner LOGIN PASSWORD …` and `ALTER ROLE goal_app LOGIN PASSWORD …`, with passwords from `GOAL_PG_OWNER_PASSWORD` and `GOAL_PG_APP_PASSWORD` (dev defaults, quoted, never logged);
- runs `GRANT CONNECT, CREATE ON DATABASE <db> TO goal_owner`, `GRANT CONNECT ON DATABASE <db> TO goal_app` and `GRANT USAGE, CREATE ON SCHEMA public TO goal_owner`;
- transfers every table, view, sequence and function in `public`, plus `goose_db_version`, from the bootstrap user to `goal_owner` with `ALTER … OWNER TO`, one object at a time (`REASSIGN OWNED` cannot be used on the bootstrap superuser).

`goal db init` also grants `USAGE ON SCHEMA` to `goal_app`. (A1) `00004_app_role.sql` grants `goal_app` the tables and view of `00001–00003` (`SELECT, INSERT, UPDATE` on `factories`, `work_items`, `agent_runs`; plus `DELETE` on `leases`, `andon_pulls`; `SELECT, INSERT` on `item_events`; `SELECT` on `station_wip`), so goald runs as `goal_app` from A1 on. The integration-test harness connects as compose's superuser and switches with the `role` startup parameter (`?role=goal_owner` / `goal_app` in the URL), so tests never set or change the roles' passwords.

`goal up` runs it every time; in the cloud (later, the AWS deployment) Terraform does the same. Migrations run as `goal_owner`. The owner is subject to no policy because tables are not `FORCE ROW LEVEL SECURITY`, which keeps backfills and definer functions working; `goal_app` is never an owner. Every migration grants explicitly what `goal_app` needs: there are no default privileges, so a table someone forgot to grant fails loudly instead of being open.

### 6.1 `00005_organizations.sql`

```sql
-- +goose Up
-- Phase 2.2 A: organizations and the audit log. Runs as goal_owner; goald connects as goal_app,
-- which row-level security binds to the organization of each transaction.

-- The organization of the current transaction: goald runs set_config('goal.org_id', $1, true) in
-- every transaction. Unset (or reset to '' after an earlier transaction) the cast fails, so a
-- forgotten org is an error, never an empty or foreign answer. Policies call it as
-- (SELECT goal_org()) so it is evaluated once per statement, not per row.
CREATE FUNCTION goal_org() RETURNS uuid LANGUAGE sql STABLE PARALLEL SAFE
AS $$ SELECT current_setting('goal.org_id')::uuid $$;
-- (review) goal_org() stays strict. Phase 3.2's curated connector rows are the only policy that
-- must work without an org; its 00042 adds goal_org_or_null() and uses it there only.

CREATE TABLE organizations (
  id         uuid PRIMARY KEY,
  slug       text NOT NULL CHECK (slug ~ '^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$'),
  name       text NOT NULL CHECK (length(name) BETWEEN 1 AND 80),
  mark       text NOT NULL CHECK (length(mark) BETWEEN 1 AND 2),
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz                         -- soft delete; purged after the retention window
);
-- Unique across live and deleted orgs until purge; reserved words are refused in Go (§8.2).
CREATE UNIQUE INDEX organizations_slug_key ON organizations (slug);

-- Append-only: goal_app may insert and read, never update or delete.
-- (no-auth) actor_id is a text id (Actor.ID: "local", an agent name, a job), not a users FK;
-- phase 4 adds users and keeps these rows readable.
CREATE TABLE audit_log (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  org_id      uuid NOT NULL DEFAULT goal_org() REFERENCES organizations (id) ON DELETE CASCADE,
  at          timestamptz NOT NULL DEFAULT now(),
  actor_kind  text NOT NULL CHECK (actor_kind IN ('user', 'agent', 'system')),
  actor_id    text NOT NULL,
  actor_name  text NOT NULL,
  action      text NOT NULL CHECK (action ~ '^[a-z_]+\.[a-z_]+$'),
  target_kind text NOT NULL,
  target_id   text NOT NULL,
  factory_id  uuid,                              -- no FK: the log outlives factories
  data        jsonb NOT NULL DEFAULT '{}',
  request_id  text
);
CREATE INDEX audit_log_org_idx    ON audit_log (org_id, id DESC);
CREATE INDEX audit_log_target_idx ON audit_log (org_id, target_kind, target_id, id DESC);

ALTER TABLE organizations ENABLE ROW LEVEL SECURITY;
CREATE POLICY org_isolation ON organizations
  USING (id = (SELECT goal_org())) WITH CHECK (id = (SELECT goal_org()));
ALTER TABLE audit_log ENABLE ROW LEVEL SECURITY;
CREATE POLICY org_isolation ON audit_log
  USING (org_id = (SELECT goal_org())) WITH CHECK (org_id = (SELECT goal_org()));

GRANT SELECT, INSERT, UPDATE ON organizations TO goal_app;      -- purge is goal_purge_org()
GRANT SELECT, INSERT ON audit_log TO goal_app;

-- Backfill: every existing row belongs to one default organization. The id is fixed so Go
-- (postgres.DefaultOrgID) and the bucket migration agree.
INSERT INTO organizations (id, slug, name, mark)
VALUES ('019a1c00-0000-7000-8000-000000000001', 'default', 'Default', 'De');
```

### 6.2 `00006_org_scope.sql`

`ADD COLUMN … NOT NULL DEFAULT <constant>` is a catalog-only change in PostgreSQL 11+, with no table rewrite. The default then switches to `goal_org()` for new rows.

```sql
-- +goose Up
-- Every org-owned table gets org_id (existing rows: the default organization) and row-level security.

-- 1. org_id, backfilled without rewriting tables.
ALTER TABLE factories   ADD COLUMN org_id uuid NOT NULL DEFAULT '019a1c00-0000-7000-8000-000000000001';
ALTER TABLE work_items  ADD COLUMN org_id uuid NOT NULL DEFAULT '019a1c00-0000-7000-8000-000000000001';
ALTER TABLE leases      ADD COLUMN org_id uuid NOT NULL DEFAULT '019a1c00-0000-7000-8000-000000000001';
ALTER TABLE agent_runs  ADD COLUMN org_id uuid NOT NULL DEFAULT '019a1c00-0000-7000-8000-000000000001';
ALTER TABLE item_events ADD COLUMN org_id uuid NOT NULL DEFAULT '019a1c00-0000-7000-8000-000000000001';
ALTER TABLE andon_pulls ADD COLUMN org_id uuid NOT NULL DEFAULT '019a1c00-0000-7000-8000-000000000001';
ALTER TABLE factories   ALTER COLUMN org_id SET DEFAULT goal_org();
-- … the same SET DEFAULT goal_org() for the other five tables.

-- 2. Composite keys: a row can only point at a parent of its own organization, even through a bug.
ALTER TABLE factories  ADD CONSTRAINT factories_org_fkey FOREIGN KEY (org_id) REFERENCES organizations (id) ON DELETE CASCADE;
ALTER TABLE factories  ADD CONSTRAINT factories_org_id_key UNIQUE (org_id, id);
ALTER TABLE work_items ADD CONSTRAINT work_items_org_id_key UNIQUE (org_id, id);
ALTER TABLE agent_runs ADD CONSTRAINT agent_runs_org_id_key UNIQUE (org_id, id);
ALTER TABLE work_items  DROP CONSTRAINT work_items_factory_id_fkey,
  ADD CONSTRAINT work_items_factory_fkey  FOREIGN KEY (org_id, factory_id) REFERENCES factories (org_id, id);
ALTER TABLE leases      DROP CONSTRAINT leases_item_id_fkey, DROP CONSTRAINT leases_factory_id_fkey,
  ADD CONSTRAINT leases_item_fkey     FOREIGN KEY (org_id, item_id)    REFERENCES work_items (org_id, id) ON DELETE CASCADE,
  ADD CONSTRAINT leases_factory_fkey  FOREIGN KEY (org_id, factory_id) REFERENCES factories (org_id, id);
ALTER TABLE agent_runs  DROP CONSTRAINT agent_runs_item_id_fkey, DROP CONSTRAINT agent_runs_factory_id_fkey,
  ADD CONSTRAINT agent_runs_item_fkey    FOREIGN KEY (org_id, item_id)    REFERENCES work_items (org_id, id),
  ADD CONSTRAINT agent_runs_factory_fkey FOREIGN KEY (org_id, factory_id) REFERENCES factories (org_id, id);
ALTER TABLE item_events DROP CONSTRAINT item_events_item_id_fkey, DROP CONSTRAINT item_events_factory_id_fkey,
  DROP CONSTRAINT item_events_run_id_fkey,
  ADD CONSTRAINT item_events_item_fkey    FOREIGN KEY (org_id, item_id)    REFERENCES work_items (org_id, id),
  ADD CONSTRAINT item_events_factory_fkey FOREIGN KEY (org_id, factory_id) REFERENCES factories (org_id, id),
  ADD CONSTRAINT item_events_run_fkey     FOREIGN KEY (org_id, run_id)     REFERENCES agent_runs (org_id, id);
ALTER TABLE andon_pulls DROP CONSTRAINT andon_pulls_factory_id_fkey,

CREATE OR REPLACE FUNCTION notify_item_event() RETURNS trigger LANGUAGE plpgsql AS $$
```

## 7. Bucket layout changes

**Prefix rule (A owns):** every org-owned object lives under `orgs/<org-id>/`, built only by `factorystore.OrgPrefix(org domain.OrgID) string`. The org id always comes from the database (the request's org as the org middleware resolved it, or the line), never from user input. Outside `orgs/` there is only Goal's own `catalog/` (templates B, skills D, connectors phase 3).

Until B replaces files with blobs, a factory's files move from `factories/<id>/` to `orgs/<org-id>/factories/<id>/`, through `factorystore.Prefix(org, id)`. `List` walks `orgs/*/factories/*/factory.yaml` and returns `(OrgID, factory)`. B owns `orgs/<org-id>/blobs/<sha256>` and migrates `orgs/<org-id>/factories/<id>/` into blobs and `definition_versions`. `knowledge/` moves with its factory (it is empty today); a knowledge layout is later work.

**Migration of existing objects:** `factorystore.MigrateLegacy(ctx, store, defaultOrg)` runs in goald at startup, before the first refresh:
1. For every current object under `factories/`, `Get` it, compare it with `orgs/<default>/factories/…` (missing or a different SHA-256), and `Put` it there.
2. When every key is present and equal, `Delete` the legacy keys. They become delete markers, so earlier versions stay restorable.

The steps are idempotent and convergent, so concurrent instances need no lock; a legacy key another instance already deleted is skipped. All pre-2.2 factories go to the default org, which matches the database backfill. `goal factory push`, `pull` and `list` (direct bucket access, until B moves publishing into the API) take `--org` and write under the org prefix.

## 8. API

Every path below is under `/v1`. Errors are RFC 9457 `Problem`. Lists are newest first or name-ordered, with an opaque `next` cursor where they page. (no-auth) Every operation is allowed to the local user and passes the `Authorizer` seam (§5.3); there is no permission per operation in 2.2.

### 8.1 Status codes (all routes)

| Status | When |
| --- | --- |
| 404 | Unknown or deleted org: one identical body (`title: "Organization not found"`). The same applies to a factory or item not in the org. |
| 409 | A domain rule was violated (`domain.ErrInvalid`: a taken or reserved slug, a confirmation mismatch), or a conflict as today. |
| 400 | Malformed request, as today. |
| 403 | Reserved for the `Authorizer` (§5.3); `AllowAll` never produces it. |

### 8.2 Organizations

| Method and path | Request → response |
| --- | --- |

| `POST /v1/orgs` | `NewOrg{name, slug, mark?}` → 201 `Org`. The slug is lowercase and not one of `new, settings, api, v1, o, me, orgs, auth, invite, admin, default` (`me`, `auth`, `invite` stay reserved for phase 4). `mark` defaults to the initials. A taken slug is 409. |
| `GET /v1/orgs/{org}` | → `Org{id, slug, name, mark, factory_count, created_at}` |

## 14. Rollout and migration

From today's single tenant (one `goal` superuser, global rows, `factories/<id>/` in the bucket):
1. **`goal up`** (or `goal db init` by hand) creates `goal_owner` and `goal_app`, sets their passwords from `.env` (dev defaults otherwise) and transfers ownership of the existing objects to `goal_owner`. `.env.example` gains `GOAL_PG_OWNER_PASSWORD`, `GOAL_PG_APP_PASSWORD`, `GOAL_MIGRATE_DATABASE_URL` and `GOAL_DATABASE_ADMIN_URL`, and the defaults of `GOAL_DATABASE_URL` and `GOAL_MIGRATE_DATABASE_URL` switch to the two roles.
2. **goald** migrates 00004–00007 as `goal_owner`: the default org is created and every row is backfilled into it without rewriting tables. It then refuses to run unless `GOAL_DATABASE_URL` is a goal_app-like role.
3. **goald** copies the bucket's `factories/` to `orgs/<default>/factories/` and leaves the legacy keys as delete markers.
4. **The new binary** serves `/v1/orgs/{org}/...`. The CLI resolves the org (the install has exactly one, so no flag is needed) and the web UI uses the first org. Items keep their numbers and refs (`goal#12`).
5. **The user renames** the default org in Settings (e.g. to `acme`) when C ships the screen, or with `goal org update default --slug acme --name Acme` before that.

Nothing is lost. A rollback to the previous binary is not supported once 00006 has run, because migrations are forward-only. Back up first (`pg_dump`) and keep the bucket's object versions.

- **SQL tenancy kit:** `goal_org()`; the policy `org_isolation … USING/WITH CHECK (org_id = (SELECT goal_org()))`; `org_id uuid NOT NULL DEFAULT goal_org() REFERENCES organizations (id) ON DELETE CASCADE` on every new org-owned table; explicit `GRANT`s to `goal_app` in each migration; definer functions only with `SET search_path FROM CURRENT`; views with `security_invoker = true`; `TestSchema_EveryOrgTableHasRLS` guarding all of it. The README's literal policy is wrapped in `(SELECT …)` for performance only.
- **Actor columns:** a table recording who did something uses `<x>_by text` holding `Actor.Ref()` (no users FK in 2.2, no-auth).
- **Database roles:** `goal_owner` runs migrations, `goal_app` runs goald, and `goal db init` creates them.
- **Go context:** `domain.OrgID`, `domain.WithOrg`/`OrgFrom`, `domain.ErrNoOrg`; `domain.Actor`, `LocalUser`, `WithActor`/`ActorFrom`, `Ref`/`ActorFromRef`. Postgres `inTx` sets the org, and `appendAudit(ctx, q, entry)` is shared within `internal/adapters/postgres`.
- **Ports:** `Tenancy` (incl. `ActiveOrgs` for B's refresh and cross-org jobs) and `Audit`.
- **Seams:** the request actor middleware and `api.Authorizer` with `s.factory(ctx, ref)`/`s.item(ctx, ref)` (§5.3); 404 for unknown orgs.
- **API:** `/v1/orgs`, `/v1/orgs/{org}`, `/settings` (phase 3 adds model access and the vault on its own `/settings/vault`; restructure), `/audit` and `/stream`. Schemas `Org, OrgSummary, OrgSettings, AuditEntry, Actor`, `Problem.code`.
- **Events:** every NOTIFY payload carries `org_id`. The `goal_org_events` channel, `ItemNotice.OrgID` and `ItemNotice.Org` exist. (review)
- **Bucket:** `factorystore.OrgPrefix(org)`, with the interim `orgs/<org-id>/factories/<id>/` that B migrates into `orgs/<org-id>/blobs/`.
- **Engine:** `Line.OrgID`, `Line.MaxSlots`, `ports.ErrOrgFull`/`ErrFactoryFull`, `engine.Config.MaxRuns` (`GOAL_MAX_RUNS`), and decisions taking `domain.Actor`.
- **Task token:** claim `o` (org).
- **Web:** query keys under `['org', org, …]`, the client functions in §10 and the first-org shim for C to replace.
- **CLI:** `--org`, `GOAL_ORG`, `~/.config/goal/config.json`, `goal org …` and `goal db init`.

**A needs**
- **B:** keep `Factories(ctx)`/`Lookup(ctx, ref)` org-scoped; take a factory's org from `factories.org_id`; use `Tenancy.ActiveOrgs` for cross-org refresh; migrate `orgs/<org>/factories/<id>/` to blobs; record authors as actor refs.
- **C:** build Org settings, the org menu (desktop and mobile sheet) and `/o/:org` routes on A's endpoints; replace the first-org shim.
- **E:** use `domain.Actor` on decisions and its new engine methods; keep stream invalidation under `['org', org, …]`.

Later phases (nothing in A waits for them):
- **Phase 3:** serve model access and the vault on its own `/settings/vault` (not inside `OrgSettings`) (review); give credential tables the tenancy kit and actor columns; extend `goal_purge_org` or rely on CASCADE; extend the schema-test allowlist in its PRs; verify the token's `o` claim in the gateway; scope connections by org; write its audit entries with `appendAudit`.
- **Phase 4:** add people and access at the seams of §5.3 (README "Out of 2.2").
