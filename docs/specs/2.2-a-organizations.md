# Phase 2.2 A — Organizations and identity

Status: draft for review · migrations `00004–00009` · OpenAPI tag `orgs`

## 1. Summary

Goal becomes multi-tenant: every org-owned row carries `org_id` and PostgreSQL row-level security (RLS) enforces it for `goal_app`, the role goald runs as, while `goal_owner` owns the schema and runs migrations. Every API route moves under `/v1/orgs/{org}/...` behind one authentication and authorization pipeline (organization membership, then one permission table), the CLI and the typed TypeScript client follow, the bucket moves under `orgs/<org-id>/`, and the stream only carries a subscriber's organization. Goal keeps working as today in local single-user mode (one implicit user who owns a default organization holding all existing data). OIDC sign-in with sessions, a cookie and CSRF protection is built last, and API tokens are designed here for later.

## 2. Scope

**In**
- Tables `organizations`, `users`, `memberships`, `factory_roles`, `invitations`, `audit_log`, `sessions`. `org_id` and RLS on `factories`, `work_items`, `leases`, `agent_runs`, `item_events`, `andon_pulls`, with every existing row backfilled into one default organization.
- Database roles `goal_owner` and `goal_app`, `goal db init` to create them, two connection strings, a startup guard that refuses a role that bypasses RLS, and RLS-aware migrations, sqlc and conformance suites.
- Org context per transaction: the store sets `goal.org_id` from `ctx`. The engine claims across organizations by iterating them with fair round-robin. No SECURITY DEFINER claim (see §4.3).
- Ports `Identity`, `Tenancy`, `Audit`, `SignIn`, plus the org context helper `domain.WithOrg` / `domain.OrgFrom`.
- Authentication: local mode now and OIDC last. Authorization: non-members get 404, and roles are checked per operation from one permission table.
- The route move to `/v1/orgs/{org}/...`, with the CLI (`--org`, a config file, `goal org`) and `@goal/api-client` and `web/src/api` updated in the same pull request.
- The bucket prefix rule `orgs/<org-id>/` and the migration of the existing `factories/<id>/` objects.
- NOTIFY payloads carry `org_id`, the SSE stream is filtered by org and visible factory, and a stream ends when its user's access changes.
- Backends for Members, Org-Settings (General, slots, Danger zone) and the org parts of the Org-Switcher: org CRUD, members, factory roles, invitations, ownership transfer, deletion, audit.
- Organization and per-factory slot caps, enforced at claim time.

**Out**
- All UI screens, which phase D builds. A only keeps today's screens working against the new routes (§10).
- Model access (subscription or API key), the subscription token and the vault backend choice, all phase C. C extends A's settings endpoint.
- The definition blob layout and `definition_versions`, both phase B. A only moves today's files under the org prefix.
- Credentials, connectors, connections and tool approvals (C, G). A only defines their permissions.
- Email delivery of invitations: 2.2 gives the inviter a link to copy.
- API tokens: designed in §8.6 and built after OIDC, outside this phase's pull requests unless the review pulls them in.
- Terraform, IAM by prefix and KMS (phase 3).

## 4. Domain and engine changes

### 4.1 Domain (`internal/domain/org.go`, new)

```go
type OrgID string
type UserID string

type OrgRole string     // ordered: OrgMember < OrgAdmin < OrgOwner
const (OrgOwner OrgRole = "owner"; OrgAdmin = "admin"; OrgMember = "member")

type FactoryRole string // ordered: FactoryViewer < FactoryApprover < FactoryEditor; "" = none
const (FactoryViewer FactoryRole = "viewer"; FactoryApprover = "approver"; FactoryEditor = "editor")

type Org struct { ID OrgID; Slug, Name, Mark string; MaxSlots int /* 0 = no cap */; CreatedAt time.Time }
type OrgSummary struct { Org; Role OrgRole; FactoryCount int }
type User struct { ID UserID; Email, Name string; Local bool; CreatedAt time.Time }
type Member struct { User User; Role OrgRole; FactoryRoles map[FactoryID]FactoryRole; JoinedAt time.Time; LastActiveAt *time.Time }

// Access is what one user may do in one organization; the API puts it in the request context.
type Access struct { Org Org; User User; Role OrgRole; FactoryRoles map[FactoryID]FactoryRole }
func (a Access) FactoryRole(f FactoryID) FactoryRole   // owner and admin: FactoryEditor on every factory
func (a Access) Can(p Permission, f FactoryID) bool    // f is "" for org-level permissions
func (a Access) Visible(f FactoryID) bool              // FactoryRole(f) != ""

type ActorKind string // "user" | "agent" | "system"
type Actor struct { Kind ActorKind; ID, Name string }   // ID: user UUID, agent name or "engine"

type AuditEntry struct {
	ID int64; At time.Time; Actor Actor
	Action string                 // <noun>.<verb>, see §11.4
	TargetKind, TargetID string
	FactoryID FactoryID           // optional
	Data map[string]any           // never secrets, tokens or credential values
}

// Org context. WithOrg is set by the API (from the URL, after the membership check), by the engine
// (from the line) and by the gateway (from the task token); every Store, Tenancy and Audit method
// that touches org-owned rows reads it.
func WithOrg(ctx context.Context, id OrgID) context.Context
func OrgFrom(ctx context.Context) (OrgID, bool)
```

`domain.Line` gains `OrgID OrgID` and `MaxSlots int`, `domain.Item` gains `OrgID`, and `TaskClaims` gains `OrgID OrgID \`json:"o"\``. A token without `o` fails verification, so tokens issued before the upgrade stop working. That is safe because goald releases runs on SIGTERM.

**Permission table** (`internal/domain/permission.go`) is the only place roles map to rights. The rules are in §11.2. Its shape:

```go
type Permission string
type rule struct{ org OrgRole; factory FactoryRole } // exactly one is set
var permissions = map[Permission]rule{ /* §11.2 */ }
func PermissionScope(p Permission) (factoryScoped bool, ok bool)
func Permissions() []Permission // sorted; the OpenAPI Permission enum is tested against it
```

**Membership rules** are pure functions, and the API calls them before writing:

```go
func CheckRoleChange(by Access, target Member, to OrgRole) error   // ErrForbidden / ErrInvalid
func CheckRemoval(by Access, target Member) error
func CheckFactoryRole(by Access, target Member, to FactoryRole) error
func CheckTransfer(by Access, to Member) error
```

The rules:
- An organization has exactly one owner.
- Only the owner transfers ownership, and only to an admin. The old owner becomes an admin.
- Admins change roles between member and admin, never touch the owner and never change their own role.
- Factory roles are set only for members, because owners and admins already have editor everywhere.
- Anyone but the owner may leave.

New errors in `domain`: `ErrForbidden`, `ErrInvalid`, `ErrNoOrg`, the last for a missing org context.

### 4.2 Decisions carry an actor

`engine.Approve`, `Reject`, `Retry` and `Merge` take `by domain.Actor` instead of `by string`. The event's `actor` stays the display name, and `data.user_id` records the user. Request bodies lose `by`, and the CLI loses `--by`, because the API takes the actor from the authenticated user. `web/src/shared/actor.ts` is deleted.

### 4.3 Engine across organizations

The engine runs as the system and never bypasses RLS:
- Every store call carries the org of the line it serves: `ctx = domain.WithOrg(ctx, line.OrgID)` for releases, claims, runs, heartbeats and transitions. `work()` keeps that context for the life of the run.
- `Submit`, the decisions and `Merge` require `OrgFrom(ctx) == line.OrgID` and otherwise return `ports.ErrNotFound`, so an API bug cannot submit into another org's factory.
- `SweepLeases` asks `Tenancy.ActiveOrgs` for the active orgs and calls `RequeueExpiredLeases` once per org. A lease on a factory that is no longer loaded is still swept.

**Fair claiming.** `Tick` first releases queue stations line by line, as today. It then claims with two-level round-robin, with `engine.Config.MaxRuns` (`GOAL_MAX_RUNS`, 0 = unlimited) as this instance's cap on concurrent runs:

```
orgs   := orgs of the loaded lines, sorted, rotated by a tick counter
for pass := 0; ; pass++ {
    progress := false
    for each org in orgs, skipping exhausted ones {
        if running >= MaxRuns (MaxRuns > 0) { return }
        try that org's factories round-robin (rotated per org per tick), each factory's agent
        stations in line order, skipping stations already seen empty this tick:
            ClaimNext → start the run; progress = true; next org
            ErrNoWork / ErrSlotTaken → next station
            ErrFactoryFull → skip this factory for the rest of the tick
            ErrOrgFull → mark the org exhausted
        nothing claimed → mark the org exhausted
    }
    if !progress { return }
}
```

Each pass gives every org at most one claim. With `MaxRuns` set, a busy org cannot fill the instance before a quiet org's first item starts. Without it, orgs compete only for their own slots, so the order doesn't matter. Any goald instance can run this, and the counter and run count are local scheduling hints, not state.

**Why not a SECURITY DEFINER claim function.** A definer function runs as the owner, so every statement inside it bypasses RLS: one bug leaks across orgs, and that is the leak RLS exists to stop. It would also move the claim (slot check, `SKIP LOCKED` pull order, lease insert, event) from sqlc-checked Go into plpgsql, which duplicates `ClaimNext`. The conformance suite could not run it against the fake, and a global `SKIP LOCKED` across orgs is FIFO by age, so one org's backlog starves the others.

Iterating orgs adds no queries: the tick already queries per line and station, and the org is one `set_config` in each transaction. The only definer functions return org ids, memberships or one acceptance (§6.4), never work rows.

### 4.4 Slot caps

`organizations.max_slots` (all agents running at once across the org's factories) and `factories.max_slots` (per factory) are NULL when unset. `ClaimNext` enforces them in the claim transaction. When either cap is set it takes `pg_advisory_xact_lock(hashtextextended('goal.slots.' || goal_org(), 0))`, counts the org's and the factory's leases and returns `ports.ErrOrgFull` or `ports.ErrFactoryFull` without changing anything. Per-factory caps may add up to more than the org cap, as the board says ("factories wait for each other at peak"). The station WIP rule (the unique `(factory_id, station, slot)` lease) is unchanged.

## 6. Data model

### 6.0 Roles (outside migrations)

`internal/adapters/postgres/roles.sql` (embedded) is run by `goal db init`, by the integration-test harness and by `task migrate-check` before the migrations. It is idempotent and safe to run concurrently (`duplicate_object` is ignored):

```sql
DO $$ BEGIN
  CREATE ROLE goal_owner NOLOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE;
EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN
  CREATE ROLE goal_app NOLOGIN NOSUPERUSER NOBYPASSRLS NOCREATEROLE NOINHERIT;
EXCEPTION WHEN duplicate_object THEN NULL; END $$;
```

`goal db init` (admin URL `GOAL_DATABASE_ADMIN_URL`, default compose's `goal` superuser) then does three things:
- It runs `ALTER ROLE goal_owner LOGIN PASSWORD …` and `ALTER ROLE goal_app LOGIN PASSWORD …`, with passwords from `GOAL_PG_OWNER_PASSWORD` and `GOAL_PG_APP_PASSWORD` (dev defaults, quoted, never logged).
- It runs `GRANT CONNECT, CREATE ON DATABASE <db> TO goal_owner`, `GRANT CONNECT ON DATABASE <db> TO goal_app` and `GRANT USAGE, CREATE ON SCHEMA public TO goal_owner`.
- It transfers every table, view, sequence and function in `public`, plus `goose_db_version`, from the bootstrap user to `goal_owner` with `ALTER … OWNER TO`, one object at a time. `REASSIGN OWNED` cannot be used on the bootstrap superuser.

`goal up` runs it every time. In the cloud (phase 3) Terraform does the same.

Migrations then run as `goal_owner`. The owner is subject to no policy because tables are not `FORCE ROW LEVEL SECURITY`, which keeps backfills and definer functions working. `goal_app` is never an owner.

Every migration grants explicitly what goal_app needs. There are no default privileges, so a table someone forgot to grant fails loudly instead of being open.

### 6.1 `00004_organizations.sql`

```sql
-- +goose Up
-- Phase 2.2 A: organizations, people, invitations and the audit log. Runs as goal_owner; goald
-- connects as goal_app, which row-level security binds to the organization of each transaction.

-- The organization of the current transaction: goald runs set_config('goal.org_id', $1, true) in
-- every transaction. Unset (or reset to '' after an earlier transaction) the cast fails, so a
-- forgotten org is an error, never an empty or foreign answer. Policies call it as
-- (SELECT goal_org()) so it is evaluated once per statement, not per row.
CREATE FUNCTION goal_org() RETURNS uuid LANGUAGE sql STABLE PARALLEL SAFE
AS $$ SELECT current_setting('goal.org_id')::uuid $$;
-- (review) goal_org() stays strict. The only policy that must work without an org is G's read
-- policy on curated connector rows; G's 00040 adds goal_org_or_null()
-- (nullif(current_setting('goal.org_id', true), '')::uuid) and uses it there only.

CREATE TABLE organizations (
  id         uuid PRIMARY KEY,
  slug       text NOT NULL CHECK (slug ~ '^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$'),
  name       text NOT NULL CHECK (length(name) BETWEEN 1 AND 80),
  mark       text NOT NULL CHECK (length(mark) BETWEEN 1 AND 2),
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz                         -- soft delete; purged after the retention window
);
-- Unique across live and deleted orgs until purge; reserved words are refused in Go (§8.2).
CREATE UNIQUE INDEX organizations_slug_key ON organizations (slug);

-- People. Not org-owned (one person, many orgs), so no org_id and no RLS; only the Identity
-- adapter and the member queries (joined through memberships, which RLS filters) read it.
CREATE TABLE users (
  id           uuid PRIMARY KEY,
  email        text NOT NULL CHECK (length(email) BETWEEN 3 AND 320),
  name         text NOT NULL CHECK (length(name) BETWEEN 1 AND 120),
  local        boolean NOT NULL DEFAULT false,   -- the implicit single user of local mode
  oidc_issuer  text,
  oidc_subject text,
  created_at   timestamptz NOT NULL DEFAULT now(),
  last_seen_at timestamptz,
  disabled_at  timestamptz,
  CHECK ((oidc_issuer IS NULL) = (oidc_subject IS NULL)),
  CHECK (NOT (local AND oidc_subject IS NOT NULL))
);
CREATE UNIQUE INDEX users_oidc_key  ON users (oidc_issuer, oidc_subject) WHERE oidc_subject IS NOT NULL;
CREATE UNIQUE INDEX users_email_key ON users (lower(email)) WHERE disabled_at IS NULL;
CREATE UNIQUE INDEX users_local_key ON users (local) WHERE local;

CREATE TABLE memberships (
  org_id         uuid NOT NULL DEFAULT goal_org() REFERENCES organizations (id) ON DELETE CASCADE,
  user_id        uuid NOT NULL REFERENCES users (id),
  role           text NOT NULL CHECK (role IN ('owner', 'admin', 'member')),
  created_at     timestamptz NOT NULL DEFAULT now(),
  last_active_at timestamptz,
  PRIMARY KEY (org_id, user_id)
);
-- At most one owner; "at least one" is kept by TransferOwnership swapping roles in one transaction.
CREATE UNIQUE INDEX memberships_owner_key ON memberships (org_id) WHERE role = 'owner';
CREATE INDEX memberships_user_idx ON memberships (user_id);

CREATE TABLE invitations (
  id            uuid PRIMARY KEY,
  org_id        uuid NOT NULL DEFAULT goal_org() REFERENCES organizations (id) ON DELETE CASCADE,
  email         text NOT NULL CHECK (length(email) BETWEEN 3 AND 320),
  role          text NOT NULL CHECK (role IN ('admin', 'member')),
  factory_roles jsonb NOT NULL DEFAULT '{}',   -- factory id → viewer|approver|editor, applied on acceptance
  token_hash    bytea NOT NULL UNIQUE,         -- sha256 of the link token; the token is shown once
  invited_by    uuid NOT NULL REFERENCES users (id),
  created_at    timestamptz NOT NULL DEFAULT now(),
  expires_at    timestamptz NOT NULL,
  accepted_at   timestamptz,
  accepted_by   uuid REFERENCES users (id),
```

## 7. Bucket layout changes

**Prefix rule (A owns):** every org-owned object lives under `orgs/<org-id>/`, built only by `factorystore.OrgPrefix(org domain.OrgID) string`. The org id always comes from the database (the request's `Access` or the line), never from user input. Outside `orgs/` there is only Goal's own `catalog/` (G owns it).

Until phase B replaces files with blobs, a factory's files move from `factories/<id>/` to `orgs/<org-id>/factories/<id>/`, through `factorystore.Prefix(org, id)`. `List` walks `orgs/*/factories/*/factory.yaml` and returns `(OrgID, factory)`. Phase B owns `orgs/<org-id>/blobs/<sha256>` and migrates `orgs/<org-id>/factories/<id>/` into blobs and `definition_versions`. `knowledge/` moves with its factory (it is empty today), and phase 3's `orgs/<org-id>/knowledge/<factory-id>/` is out of scope.

**Migration of existing objects:** `factorystore.MigrateLegacy(ctx, store, defaultOrg)` runs in goald at startup, before the first refresh:
1. For every current object under `factories/`, `Get` it, compare it with `orgs/<default>/factories/…` (missing or a different SHA-256), and `Put` it there.
2. When every key is present and equal, `Delete` the legacy keys. They become delete markers, so earlier versions stay restorable.

The steps are idempotent and convergent, so concurrent instances need no lock. A legacy key another instance already deleted is skipped. All pre-2.2 factories go to the default org, which matches the database backfill. `goal factory push`, `pull` and `list` (direct bucket access, until B moves publishing into the API) take `--org` and write under the org prefix.

### 8.5 Stream

`GET /v1/orgs/{org}/stream` sends `event: item` only for notices whose `org_id` is the subscriber's org and whose factory is visible to the subscriber, a set taken when the stream starts. `StreamEvent` gains `org_id`.

Other event names on the same stream (`definition`, `credential`, `factory`, `approval`, `connection`; README registry) are filtered the same way: by org, and by visible factory when they carry a `factory_id`. (review)

A second channel, `LISTEN goal_access`, on the same listening connection carries `{org_id, user_id}` whenever a membership or factory role changes or is removed. The feed ends every stream of that user in that org, the client reconnects, and the reconnect re-authorizes, which gives a new visible set or a 404. ### 8.6 Authentication

**Local mode** (`GOAL_AUTH=local`, the default, loopback listen only, as today): every request is the local user (`Identity.LocalUser`, cached per process with no state). There are no cookies and no CSRF exposure beyond today's. `/v1/auth/*` returns 404.

**OIDC mode** (`GOAL_AUTH=oidc`, built last):

| Method and path | Does |
| --- | --- |
| `GET /v1/auth/login?return_to=/o/acme` | Creates `state`, `nonce` and a PKCE verifier. Stores them in a 10-minute `__Host-goal_oidc` cookie (AES-GCM with a key derived from `GOAL_SESSION_KEY_REF`, so any instance can read it). Answers 302 to the IdP. `return_to` must be a path starting with a single `/`. |
| `GET /v1/auth/callback?code&state` | Checks `state` against the cookie and runs `SignIn.Exchange` (PKCE S256 and the nonce). Requires a verified email in `GOAL_OIDC_ALLOWED_DOMAINS` when that is set. Runs `UpsertOIDCUser`; if the email is `GOAL_BOOTSTRAP_OWNER_EMAIL` and the local user still owns orgs, runs `MergeLocalUser`. Then creates a new session (32 random bytes; sha256 stored), sets `__Host-goal_session` (HttpOnly, Secure, SameSite=Lax, Path=/, no Domain, Max-Age = absolute TTL) and answers 302 to `return_to`. |
| `POST /v1/auth/logout` | Revokes the session, clears the cookie and answers 204. |
| `GET /v1/auth/sessions`, `DELETE /v1/auth/sessions/{id}` | The caller's own sessions (later; not on a board). |

Sessions expire after `GOAL_SESSION_TTL` (7d absolute) and `GOAL_SESSION_IDLE` (24h). A singleton job (`pg_try_advisory_lock('goal.sessions.gc')`) deletes sessions that expired more than 30 days ago.

**CSRF:** goald wraps every unsafe method in `net/http.CrossOriginProtection` (Fetch Metadata `Sec-Fetch-Site`, else `Origin` against `Host`), with `GOAL_PUBLIC_URL`'s origin added as trusted. Bodies must be `application/json`, which a cross-site form cannot send without a preflight. The session cookie is SameSite=Lax. Requests with `Authorization: Bearer` carry no ambient credential and pass CrossOriginProtection (no `Sec-Fetch-Site`/`Origin`). A UI hosted on Vercel reaches goald through a same-origin rewrite of `/v1/*`, so cookies never need `SameSite=None`.

**API tokens (designed, built later):**
- Format: `goal_pat_<26 base32 chars>`, sent as `Authorization: Bearer`.
- Storage: the table in §6.3.
- Scope: a token is optionally restricted to one org and to a maximum org role. Its effective rights are the minimum of that and the user's current membership, so removing a member also disables their tokens.
- Endpoints: `GET`/`POST`/`DELETE /v1/me/tokens`, with the token shown once.
- CLI: `goal auth token set` stores the token in the config file with mode 0600, or reads `GOAL_TOKEN`.
- Audit: `api_token.created` and `api_token.revoked` in the restricted org.

### 8.7 OpenAPI

- Tag: `orgs`.
- New schemas: `UserRef` (`{id, name}`, no email, for authors and deciders in other phases' schemas) (review); `Me, User, Org, OrgSummary, OrgSettings, OrgSettingsPatch, Member, MemberPage, FactoryRoleGrant, Invitation, InvitationCreated, AuditEntry, AuditPage, Actor, Permission` (an enum equal to `domain.Permissions()`), `OrgRole`, `FactoryRole`.
- Changed schemas: `Factory` (+`role`, `can`), `StreamEvent` (+`org_id`), `Problem` (+ optional `code`, kebab-case; B adds `problems[]`) (review), and `Decision` bodies without `by`.
- Security schemes: `sessionCookie` (apiKey in the cookie `__Host-goal_session`) and later `bearerToken`. Local mode needs none.

## 11. Security and tenancy

### 11.1 Layers

| Layer | How |
| --- | --- |
| Sign-in | Local: loopback only. OIDC: session cookie or (later) bearer token, resolved to a user in `api/auth.go` before routing. |
| Membership | The strict middleware reads `r.PathValue("org")` and calls `Tenancy.Access`; ErrNotFound becomes 404. It puts `ctx = domain.WithOrg(ctx, org)` plus `Access` in the context and calls `TouchMember`. |
| Permission | Org-scoped operations are checked in the middleware from `operations[operationID]`. Factory-scoped ones are checked in the only two resolvers that turn a path into a factory or item, `s.factory(ctx, ref, perm)` and `s.item(ctx, ref, perm)`: not visible is 404, visible but not allowed is 403. A handler cannot reach a factory without naming a permission. |
| Database | `goal_app` without BYPASSRLS. Every transaction sets `goal.org_id`. Policies are on every org table, with composite FKs, `security_invoker` views and definer functions limited to §6.4. `CheckAppRole` runs at startup. |
| Engine | The org comes from the line (from the bucket path, later B's `factories.org_id`), never from item data. |
| Gateway | The task token's `o` claim becomes `domain.WithOrg` for its event writes. G serves only that org's connections. |
| Bucket | Keys only through `factorystore.OrgPrefix`. IAM by prefix comes in phase 3. |
| Events | NOTIFY payloads carry `org_id`, and the feed filters by org and visible factory. |

### 11.5 Secrets and personal data

- Session, invitation and API tokens are stored only as SHA-256 hashes and looked up by hash, so no plaintext token is stored or compared.

- Logs carry `user_id` and `org_id`, never emails, tokens or cookies.
- Emails appear only in API responses to members of the same org, and in invitation audit data.

## 14. Rollout and migration

From today's single tenant (one `goal` superuser, global rows, `factories/<id>/` in the bucket):
1. **`goal up`** (or `goal db init` by hand) creates `goal_owner` and `goal_app`, sets their passwords from `.env` (dev defaults otherwise) and transfers ownership of the existing objects to `goal_owner`. `.env.example` gains `GOAL_PG_OWNER_PASSWORD`, `GOAL_PG_APP_PASSWORD`, `GOAL_MIGRATE_DATABASE_URL` and `GOAL_DATABASE_ADMIN_URL`, and the defaults of `GOAL_DATABASE_URL` and `GOAL_MIGRATE_DATABASE_URL` switch to the two roles.
2. **goald** migrates 00004–00006 as `goal_owner`: the default org and local user are created and every row is backfilled into the default org without rewriting tables. It then refuses to run unless `GOAL_DATABASE_URL` is a goal_app-like role.
3. **goald** copies the bucket's `factories/` to `orgs/<default>/factories/` and leaves the legacy keys as delete markers.
4. **The new binary** serves `/v1/orgs/{org}/...`. The CLI resolves the org (the user has exactly one, so no flag is needed) and the web UI uses `me.default_org`. Items keep their numbers and refs (`goal#12`).
5. **The user renames** the default org in Settings (e.g. to `acme`) when D ships the screen, or with `PATCH /settings` or `goal org` before that.
6. **OIDC (later):** set `GOAL_AUTH=oidc` with the issuer settings and `GOAL_BOOTSTRAP_OWNER_EMAIL`. The first sign-in with that email takes over the local user's ownerships, and the local user is disabled.

Nothing is lost. A rollback to the previous binary is not supported once 00005 has run, because migrations are forward-only. Back up first (`pg_dump`) and keep the bucket's object versions.

## 17. Open questions

1. Are factory roles ordered (editor ⊇ approver ⊇ viewer, as the segmented control implies), or should an editor be unable to approve their own changes (separation of duties)?
2. In OIDC mode, who may create organizations: any signed-in user, users in `GOAL_OIDC_ALLOWED_DOMAINS`, or nobody but an operator (`GOAL_ORG_CREATION`)?
3. Invitations are copy-a-link in 2.2. Is email delivery (SES/SMTP) wanted later, and should "Resend" then send mail?
4. Slug changes break links. Keep a redirect from old slugs (`organization_slugs` history) or accept the break?
5. Org deletion: is a 7-day retention with operator-only restore right, and should the bucket prefix be purged at once or by lifecycle rules?
6. Slot caps (A7) sit on Org-Settings next to model access (C). Keep them in A, or move them to C with the subscription's shared-slot count as the org default?
7. The default org's name and slug for existing data: `default`/"Default", or ask at `goal up` (e.g. `acme`)?
8. Should API tokens (A9) be org-bound only (simpler RLS story) or user-wide with an optional org restriction, as designed here?
9. RP-initiated logout (ending the IdP session) on `POST /v1/auth/logout`: wanted?
