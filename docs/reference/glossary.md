# Glossary

The words Goal's code, API and UI use, one sentence each, with the place in the repository where each one lives. Where a term is planned, removed or only partly built, the entry says so.

| Term | What it means | Where it lives |
| --- | --- | --- |
| Access | The organization's read-only view of every factory's environments: the tools each reaches, the secret each uses, the last test and what is about to expire. `GET /v1/orgs/{org}/access` computes it from each factory's current published version, the environment tests and the secrets, and needs the `access:read` permission. | `contracts/api/permissions.yaml` (`access:read`), `apps/web/src/features/access/`; [ADR 0037](../adr/0037-secrets-and-environment-files.md) |
| Actor | Who did something (a user, an API key, an agent or a job), stored as `Actor.Ref()` such as `user:<id>` or `agent:<name>`. | `internal/core/domain/org.go` (`Actor`) |
| Agent | A model with its prompt, skills and environment (the secrets, files and MCP servers its box gets) that works at an agent station. | `internal/core/domain/line.go` (`AgentSpec`); `agents/*.md` and `environments/*.yaml` in a definition |
| Andon | A stop of a factory's whole line, pulled by a person and open until someone clears it; while it is open the engine releases and claims nothing there. | `internal/core/domain/attention.go` (`AndonPull`), `internal/core/domain/andon.go` |
| API key | An organization's service account, acting with its scopes and at most its role ceiling on the factories it reaches. | `internal/core/domain/apikey.go` (`APIKey`) |
| Ask first | An MCP tool's mode (`ask`, one of `allow`, `ask` and `off`) that stops an agent's call to the tool until a person approves or denies it as a tool approval; a factory sets the modes per MCP server and tool in its environment file (ADR 0037). | `domain.ConnectionToolMode` (`ToolModeAllow`, `ToolModeAsk`, `ToolModeOff`), `engine.DecideToolApproval`, `internal/api/toolapproval.go`; [ADR 0031](../adr/0031-tool-calls-ask-first-and-standing-rules.md) |
| Assembly | An item split into parts that are worked as separate items and ship together. | `internal/core/domain/item.go` (`Assembly`, `StateAssembly`), `internal/core/domain/part.go`; [ADR 0012](../adr/0012-assemblies-and-parts.md) |
| Attention | What a factory needs from people right now, as the counts behind the app's badges. | `internal/core/domain/attention.go` (`Attention`) |
| Board | The UI screen that shows a factory's items in columns by station. | `apps/web/src/features/board`, `apps/web/src/app/screens.ts` |
| Box | The disposable container one run works in, started through the `Sandboxes` port. | `internal/core/ports/sandboxes.go`; `apps/worker` (the image) |
| Bridge | The explanation of the gap between a factory's actual lead time and its target, largest step first. | `internal/core/domain/bridge.go` (`Bridge`) |
| Budget | A factory's weekly spending limit and what the engine does once it is used up. | `internal/core/domain/budget.go` (`BudgetPolicy`, `BudgetStatus`) |
| Check | A schedule trigger's agent that looks at a source and answers what to file, instead of the trigger filing an item each time it fires (`check:` in `board.triggers`). Each firing queues a check, run as a run of kind `check` without an item; its answer (`file`, `note`, `skip`, `state`) is applied by goald in one transaction under the trigger's lock: a new key files an item (origin `trigger`, by the check's agent, untrusted unless `create.trusted`), a key whose item is open takes a note instead (one per key an hour, no repeats), a key whose item closed is filed again only with `reopen`, and `limits.perCheck` (default 5) and `perDay` skip the rest "over the limit". `trigger_keys` keeps each key's last item. A try check (Try, `goal triggers try`) shows what it would do without filing, noting or saving state. Three failures in a row, and a check over its limit, show in Needs you. | `internal/core/engine/checks.go`, `domain.ApplyCheck` in `internal/core/domain/checkapply.go`, `Intake.FinishCheck`, `goal triggers checks`; [ADR 0040](../adr/0040-one-door-for-every-source.md) decision 19 |
| CI wait | goald holding an item at a station with `waitFor: ci` until CI on one repository's commit finishes, before its run starts (phase before) or on what its run pushed and, at an `action: merge` station, on the heads of the pull requests its merge takes (phase after). The waits of one commit share one leased poll of the code host. While one is open, a queued or ready item with no open need reports waiting kind `ci` with its commits, checks and counts. | `internal/core/domain/ciwait.go` (`CIWaitRecord`, `CIPoll`), `internal/core/domain/waiting.go` (`WaitingCI`), `ports.Store` (`CIWaits`); [ADR 0044](../adr/0044-goald-waits-for-ci.md) |
| Class of service | The pull order of an item: expedite items are pulled before any standard item. | `internal/core/domain/item.go` (`ClassOfService`) |
| Code host | A site that serves an organization's repositories: github.com and gitlab.com are built in, and an owner adds a GitHub Enterprise or self-managed GitLab host with its kind. goald sends repository tokens and knowledge secrets only to listed hosts. Set with `PUT /v1/orgs/{org}/code-hosts`. | `internal/core/domain` (`CodeHost`, `BuiltInCodeHosts`); table `code_hosts` |
| Connection | Removed. An organization's sign-in to an outside system that factories named, until ADR 0037 replaced connections with secrets and environment files: migration 00135 dropped their tables, and the connections API and the `goal connection` and `goal credential` commands are gone. A factory reaches outside systems through its environments. Names of credentials, intake sources, triggers and standing rules still follow a connection's naming rule. | `domain.CheckConnectionName`; [ADR 0037](../adr/0037-secrets-and-environment-files.md) |
| Constraint | The agent station that limits how fast a factory's line can deliver, measured over a window. | `internal/core/domain/constraint.go` (`Candidate`) |
| Contract | A file that two parts of the system agree on, such as the API, the permissions, the sandbox protocol, the environment registry or the definition schemas. | `contracts/` |
| Credential | The old name of an organization's stored secret (ADR 0017). ADR 0037 replaced credentials with secrets (see Secret): each credential is stored as a secret and reads back through the credentials API as an `api_key` with no agents and nothing that uses it, and no agent receives one directly. | `internal/core/domain` (`Credential`), `ports.Credentials`; [ADR 0017](../adr/0017-credentials.md), [ADR 0037](../adr/0037-secrets-and-environment-files.md) |
| Definition | A factory's files (`factory.yaml`, agents, rules, skills, contracts, environments and `memory.yaml`), stored as content-addressed blobs in the bucket. | `internal/core/domain/definition.go` (`Manifest`), `internal/config`, `internal/definitions`; [factory-definition.md](../engineering/factory-definition.md) |
| Delivery | One request a webhook received, kept 30 days with its headers (never a signature) and body: refused with a reason and metadata only, or accepted with its delivery id, event, receipt and duplicates; an accepted one no enabled trigger names keeps only its ledger id and a daily count. | `webhook_deliveries` (00071, 00118), `internal/core/domain/intake.go` (`WebhookDelivery`); [ADR 0026](../adr/0026-intake-triggers.md), [ADR 0040](../adr/0040-one-door-for-every-source.md) decision 12 |
| Denied commands | The Claude Code Bash permission patterns, such as `Bash(terraform apply:*)`, that an organization policy forbids every agent to run. Built: the engine adds them to the deny rules of every run. Set them on Models and policies in the web app, with `goal policy set --deny-command`, or in `PUT /v1/orgs/{org}/policy`. | `internal/core/domain/orgpolicy.go` (`OrgPolicy.DeniedCommands`), `internal/core/engine/work.go` (`applyPolicy`), `apps/web/src/features/models/`, `internal/cli/policy.go`; [ADR 0024](../adr/0024-organization-policy.md) |
| Digest | The daily message sent at 08:00 in each person's time zone, by email and Slack as they choose, with what Needs you lists and the items done, andons and spend since the last one, across their organizations; at most one per person per local date. | `internal/core/domain` (the digest's contents), `internal/notify` (`DigestJob`, run by goald), `db/migrations/00084_digests.sql`; [ADR 0023](../adr/0023-notifications-and-sign-up-by-domain.md) |
| Draft request | A request, from the Definition screen's Ask bar or an agent's Ask Jonah for a fix, that an agent in a box with no repository changes a factory's definition files and goald writes the result into the draft, never publishing it. A factory has at most one queued or running request; goald claims the oldest queued one of any organization under a lease fenced by a token, and a request whose lease ended goes back to the queue. Not built yet: the store (the `draft_requests` table and the `DraftRequests` port) and the API routes exist, but no runner is wired into goald, so the API refuses every new request with 501 `not-built` and `goal factory ask` prints that refusal. Migration 00146 ended every request queued before then as failed. | `internal/core/domain/draftrequest.go` (`DraftRequest`), `internal/core/ports/draftrequests.go`, `internal/adapters/store/postgres/draftrequests.go`, `db/migrations/00080_draft_requests.sql`; [ADR 0021](../adr/0021-asked-definition-changes-draft-requests.md) |
| Drum-buffer-rope | A release policy that lets work in at the pace of the constraint; the policy can be chosen, but its enforcement is not built yet. | `internal/core/domain/policy.go` (`ReleaseDBR`) |
| Edge, need | A stored dependency between two items: an item needs another item before it can be pulled. | `internal/core/domain/edge.go` (`Edge`, `OpenNeed`) |
| Environment | A file of a factory definition, `environments/<name>.yaml`, that says what an agent's box installs (size, image, tools, setup) and what it reaches (env, files, MCP servers), with keys as `{{secret}}` references; every factory has `default`, which an agent that names none gets. At run start the engine opens the file's secrets from the pinned version and gives the box its env, its files in `GOAL_FILE_<n>` variables, its MCP servers' secrets in `GOAL_SECRET_<NAME>` variables, its size and its image. | `internal/config/environment.go` (`Environment`); `internal/core/domain/environment.go`; `internal/core/engine/environment.go`; `contracts/definitions/environment.schema.json`; [ADR 0037](../adr/0037-secrets-and-environment-files.md) |
| Event | One recorded change of an item, run or factory, which the stream and the audit read. | `internal/core/domain/event.go` (`Event`) |
| Evidence | The folder of Markdown files a Jonah review reads, which goald writes from the line's milestone events with no model call: `items/<number>.md` for each item that finished in the review's window and needed help (a send-back, a person's touch, a failed run, or a run at least three times its station's median cost or turns), `README.md` with the counts across them and the gate and person disagreements, and `versions.md` with the versions published in the window. | `internal/core/domain/evidence.go` (`BuildEvidence`, whose comment lists the events that count), `internal/gateway/jonah.go` (`jonahEvidence`), `JonahStore.EvidenceItems` and `StationRunMedians`; [ADR 0039](../adr/0039-jonah-learns-from-the-line.md) decisions 1 and 2 |
| Export | A CSV file of one list, streamed by a `GET` at the list's path plus `/export` with the same filters and permission, and capped at 100000 rows. Built for runs (`/v1/orgs/{org}/runs/export`) and spend (`/v1/orgs/{org}/spend/export`). | `internal/api/export.go`, `contracts/api/openapi.yaml` (the two `/export` paths); [ADR 0020](../adr/0020-saved-views-and-csv-exports.md) |
| Factory | One organization's configured production line of stations and agents, keyed by its `metadata.id` UUID and never by name. | `internal/core/domain/item.go` (`FactoryID`), `internal/factorymodel` |
| Factory memory | A factory's short facts that its runs should know, in `memory.yaml` beside `factory.yaml`: each entry is one fact of at most 300 characters with the items it came from and the date it was added, and the file holds at most 8 KB and 50 entries. The UI calls it "factory memory", never "memory" alone, which could mean a box's memory. `config.Check` loads and checks the file, and each run's prompt carries it under "### Factory memory". | `internal/config/memory.go` (`MemoryEntry`), `internal/core/domain/knowledge_section.go`, `contracts/definitions/memory.schema.json`; [factory-definition.md](../engineering/factory-definition.md#factory-memory-memoryyaml); [ADR 0038](../adr/0038-knowledge-is-files.md) |
| Factory role | A member's role on one factory, lowest first: Viewer (reads), Approver (also files and operates items, decides and pulls the andon) and Editor (also edits and publishes the definition and manages the factory). Each role includes the one before it. Owners and admins are editors in every factory by their organization role. | `internal/core/domain/identity.go` (`FactoryRole`), `contracts/api/permissions.yaml` (`factory_roles`) |
| Floor | The UI screen that shows a factory's line live: its stations, their load and what needs people. | `apps/web/src/features/floor`, `apps/web/src/app/screens.ts` |
| Follow-up | Work an agent noticed outside its item, written in the output field `board.flow.outputs.followUps` maps and kept on the item in `follow_ups`: a note for an open item (delivered as an `item_note`), a start for an item of its own (filed when the work lands, with origin `follow-up`, standard class, priority one below its source's and generation one above, at most 20 a day per receiving factory, never from a generation-3 source), or text for the triage item. A person can Drop a waiting one and File a dropped one or one in a closed triage item. | `internal/core/domain/followup.go` (`FollowUp`), `internal/core/domain/followupfile.go` (`LandFollowUp`, `FollowUpFileRequest`), `ports.Store` (`FileFollowUps`, `DropFollowUp`, `FileFollowUp`), `internal/core/engine/followupfiling.go`; [ADR 0040](../adr/0040-one-door-for-every-source.md) decisions 5 to 10 and 21 |
| Gate | A check at a station that sends rejected work back to an earlier station, at most a set number of times per item. | `internal/core/domain/line.go` (`Gate`), `internal/core/domain/andon.go` (`GateVerdict`) |
| Hands-off | The touchless rate: the share of a factory's finished items that no person touched, shown by `goal status` and on the item's touches card (the Floor shows four other figures). The API calls it `touchless_rate`; getTouchMetrics computes it over the range (`stats`) and for each of the last 7 days (`daily`). | `internal/api/touches.go` (the metrics), `internal/core/domain/touch.go` (the touches it counts), `apps/web/src/features/floor/flow-stats.tsx` (the four figures it is not among) |
| Item | One unit of work flowing through a factory's line, with a state at its current station. | `internal/core/domain/item.go` (`Item`, `ItemState`) |
| Jonah | Goal's learning from the line in `internal/jonah`: a daily review of the evidence that writes observations and proposals, tries of each proposal on past items and kept tests, and a watch on every published change. Jonah only proposes; a person approves every change. | `internal/jonah`; [ADR 0034](../adr/0034-jonah-proposals.md), [ADR 0039](../adr/0039-jonah-learns-from-the-line.md); the Jonah pages in `apps/web/src/features/jonah/` |
| Jonah review | One agent run of kind `jonah` per factory, queued once a day when the factory has new evidence (at an hour set by its id) or at once by a person, that reads the evidence, the current version's files, the proposals and the open observations in a read-only box with the Read, Grep and Glob tools and the model key only, and returns observations, proposals and memory facts. Its row is pending, running under a lease, done or failed, with at most one in flight per factory. | `internal/core/domain/jonah.go` (`JonahReview`), `internal/core/ports/jonah.go` (`JonahStore`), `internal/jonah/reviews.go` (`Reviews`), `internal/gateway/jonah.go` (its bundle), `apps/worker/src/jonah.ts`; [ADR 0039](../adr/0039-jonah-learns-from-the-line.md) decisions 3 to 5 |
| Kept test | A past item a person keeps as a test at a station it passed the first time. Every change that reaches the station is tried on it, each proposal and the draft in the publish dialog, and a try passes when its run succeeds, satisfies the station's contract and checks and, at a gate, approves. A failing kept test warns and never blocks a publish. | `internal/core/domain/kepttest.go` (`KeptTest`), `internal/core/ports/jonah.go` (`KeptTests`), `internal/adapters/store/postgres/kepttests.go`, `internal/jonah/keptdraft.go` (`KeptDrafts`, at publish), `internal/api/kepttests.go`, `internal/cli/test.go` (`goal test`); [ADR 0039](../adr/0039-jonah-learns-from-the-line.md) decision 12 |
| Knowledge source | An organization's folder of Markdown files, kept in sync from one place and named by the definitions that list it: an upload, a repository or a Confluence space, with a read-when line that tells agents when to open it. Each sync that changes something writes a snapshot, and the database keeps the current snapshot's files and the daily read counts. The sync (`internal/knowledge`) reads a source with its kind's reader and converts what is not Markdown; an upload source keeps each file's name and content hash in `knowledge_uploads` and its original in the bucket. | `internal/core/domain/knowledge.go` (`KnowledgeSource`, `KnowledgeUpload`), `internal/knowledge`; [ADR 0038](../adr/0038-knowledge-is-files.md) |
| Knowledge pin | A knowledge snapshot a claim's runs read: the newest snapshot of a source that applies to the run, decided once when the item is claimed, carried in the task token and recorded by a `knowledge_pinned` event. A run gets each pinned snapshot as read-only files under `/knowledge/<source>/` and a line about it in its prompt's Knowledge section. Once the run ends, a `knowledge_read` event lists the files of its pinned sources it read and the folders it searched. | `internal/core/domain/knowledge_files.go` (`KnowledgePin`, `KnowledgeTally`), `internal/core/engine/work.go` (`pinKnowledge`), `internal/core/engine/runtask.go` (`countReads`), `internal/gateway/knowledge.go`; [ADR 0038](../adr/0038-knowledge-is-files.md) |
| Lane | A route through a station that intake or an earlier output chooses, so that items of one lane go to that lane's agents. A person can also set the lane of an open item that is not in progress and not an assembly (`goal lane`, `POST …/items/{item}/lane`); on a line with routed stations it must be one of their lanes. | `internal/core/domain/run.go` (`LaneFrom`), `internal/core/domain/line.go` (`ErrNoRoute`), `internal/core/engine/human.go` (`SetLane`) |
| Lease | An agent slot's hold on an item; it expires unless renewed, so the work of a crashed instance returns to the queue. | `internal/core/domain/run.go` (`Lease`) |
| Learned | Removed. It was a planned built-in knowledge source of facts learned from retros; factory memory (`memory.yaml`) replaced it in ADR 0038. | [ADR 0038](../adr/0038-knowledge-is-files.md) |
| Ledger | A webhook's list of the delivery ids it accepted, without bodies, kept a year, so a delivery replayed with an id already taken is a duplicate even after its 30-day row is gone. | `webhook_delivery_ids` (00118), `internal/core/ports/intake.go` (`Intake.Receive`); [ADR 0040](../adr/0040-one-door-for-every-source.md) decision 12 |
| Line | A factory's stations in order, with its agents and flow policy, as the engine reads them. | `internal/core/domain/line.go` (`Line`) |
| Merge turn | The rule that a station with `action: merge` integrates one item per merge target at a time, so that items landing on the same branch do not race. The target is the default branch, or an assembly's integration branch for its parts. `merges: serialize` (the default) takes turns and `merges: allow` lets several items merge at once. An item that waits for its turn has waiting kind `turn`. | `contracts/definitions/factory.schema.json` (`merges`), `internal/core/domain/line.go` (`Station.TakesTurns`); [ADR 0043](../adr/0043-merge-stations-take-turns-per-target.md) |
| Model allowlist | The models of `GOAL_MODELS` that an organization policy lets agents use, exactly one of them the default. Built: publishing a version that names another model is refused with `model-not-allowed`, and a run whose model the policy no longer allows does not start. Set it on Models and policies in the web app, with `goal policy set --models` and `--default`, or in `PUT /v1/orgs/{org}/policy`. | `internal/config/policy.go` (`ModelProblems`, `CodeModelNotAllowed`), `internal/core/domain/orgpolicy.go`, `internal/core/engine/work.go` (`applyPolicy`), `apps/web/src/features/models/`; [ADR 0024](../adr/0024-organization-policy.md) |
| Model key | The secret that gives every run of a factory its model, named by `runtime.modelKey` of its definition and shown on the factory's Settings page. It reaches a run even when the organization policy turns off the use of secrets. | `contracts/definitions/factory.schema.json` (`runtime.modelKey`), `internal/core/engine/work.go` (`applyPolicy`); [Factory settings](/docs/guides/factory-settings/) |
| Model check | A trigger's last "only if" check, `only.modelAgrees`, removed by ADR 0040: the key stays in the schema, deprecated, and a trigger that has it skips every event that reaches the step, with a `field-ignored` warning to turn it into a check. | `domain.TriggerOnly.ModelAgrees`, `domain.ModelCheckRemoved`; [ADR 0028](../adr/0028-trigger-try-and-model-check.md), [ADR 0040](../adr/0040-one-door-for-every-source.md) decision 18 |
| Needs you | The screen of what waits on a person, in four tabs by type: Approval (a tool approval), Decision, Question and Alert. Alerts cover andon, budget, rework warnings, blocked and expedite items, knowledge sources, conversion and `watch_worse`. The API keeps its own names for the entries (kinds such as `tool_approval`, `decision` and `question`). | `apps/web/src/features/needs-you/types.ts`, `apps/web/src/app/screens.ts`, `internal/core/domain/inbox.go` (`AttentionItem`) |
| Notification | A message to a person about an event (an approval, a question, an andon or a budget passing 80%) on the channels they turned on: In Goal, email or Slack. | `internal/core/domain` (the events, channels and preferences), `internal/core/ports` (`Mailer`), `internal/notify` (`Sender`), `internal/adapters/mailer/smtp`, `internal/adapters/directmessage/slack`; [ADR 0023](../adr/0023-notifications-and-sign-up-by-domain.md) |
| Observation | A cause a Jonah review found in the evidence: a summary, a detail line, the items it rests on and a count that grows across reviews. It is *watching* until its count reaches `learning.jonah.proposeAfter` (shown as "Watching, n of proposeAfter"), *proposed* once a proposal addresses it, or *not Jonah's* when the cause is not a definition problem. | `internal/core/domain/jonah.go` (`Observation`, `ObservationState`), `jonah_observations`; [ADR 0039](../adr/0039-jonah-learns-from-the-line.md) decision 5 |
| Onboarding | The setup a new person follows from signing up to a first factory, in eight steps: Organization, Factory, Code, Line, Budget, Intake, People and First item. Its progress is read from existing data. | `apps/web/src/features/onboarding/steps.ts`, `docs/design/screens/get-started/`; [ADR 0032](../adr/0032-self-serve-onboarding.md) |
| Organization | The tenant: every org-owned row carries its id and is scoped by row-level security. | `internal/core/domain/org.go` (`Org`, `OrgID`) |
| Organization role | A person's role in an organization: Owner (every permission), Admin (every permission except deleting or transferring the organization, setting the sign-up domain and setting the code hosts) or Member (reads it, and each factory as their factory role says). The People step of setup offers four invite roles: Owner, Admin, Builder (a member with the Editor factory role on the new factory) and Viewer (a member with the Viewer factory role). | `internal/core/domain/identity.go` (`OrgRole`), `apps/web/src/features/onboarding/people-roles.ts` |
| Organization policy | An organization's one set of limits over every factory (allowed models, denied commands, tool policy defaults and the box time limit), stored as a row in PostgreSQL, which a definition or an agent may narrow but never widen.
