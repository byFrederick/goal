# ADR 0023 — Trying a trigger with a past event, and the model check in Only if

Status: proposed · 2026-10-27 · Builds on [ADR 0016](0016-ui-revamp.md) (the screens are the contract, controls for features not built yet), [ADR 0017](0017-credentials.md) (organization credentials that connections refer to as `{{name}}`) and [ADR 0008](0008-portable-runs-connections-and-knowledge.md) (connections, sealed secrets, the factory's model connection)

## Context

The trigger screen ([`docs/design/screens/intake/trigger.html`](../design/screens/intake/trigger.html) and its `.jpg`) draws a trigger in four blocks: When (the event and its filters, line 170), Only if (conditions "checked before any item is created", lines 178 to 182), Create (the item type, a title and a brief rendered from the event, lines 186 to 191) and Limits (items a day and the budget pause, lines 195 to 199). Two of its controls have no feature behind them. The [screens' index](../design/screens/README.md) (line 58) lists both as "Not built yet":

- **Try with a past event**, the header button at line 154, beside Save changes (line 156).
- **The model check**, the Only if option at line 182: "A model agrees it is worth an item, using the question you write, about $0.01 each time".

The Brief field's caption (line 191) says "Text from the event reaches the agent marked as untrusted data, never as instructions". The "In the definition" card (lines 215 to 221) shows a trigger's definition as `on:`, `filter:`, `only:`, `create:` and `limits:`.

What exists today:

- **No trigger code on main.** This ADR was to follow software#154 (Intake triggers) and cite its code. At `b31155a` nothing in `internal/`, `db/migrations/` or `contracts/api/openapi.yaml` defines a trigger, a trigger condition or a stored trigger event. The only intake in the definition is `line.intake[]` in [`contracts/definitions/factory.schema.json`](../../contracts/definitions/factory.schema.json) (line 410): a list of sources (`manual`, `github-issues`, `schedule`, `webhook`, `email`) with `repo`, `labels`, `cron`, `template` and `type`, and no conditions or limits. So this ADR takes its terms from the screen's definition sample and records decisions, not key spellings. software#154 owns the definition keys, the domain types and the table of stored events. The parts that build this ADR use whatever names it ships.
- **Models reach runs only through a connection.** A factory's `runtime.modelConnection` (`domain.Runtime.ModelConnection`, `internal/core/domain/line.go`) names an organization connection whose kind has `model: true` (`domain.KindSpec.Model`, `internal/core/domain/connection.go`). Its kind renders it into the box's env (`ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`) for Claude Code. `ports.Connections.Resolve` (`internal/core/ports/connections.go`) resolves it, and each use is audited `connection.used` with a `domain.ConnectionUse`, which today names a run, an item or a knowledge source. Since ADR 0017, a connection's secret field may refer to a credential by `{{name}}`. goald itself never calls a model.
- **A kind names its provider code by data.** `KindSpec.CodeHost`, `Mint` and `Sync` each name an adapter goald holds (`github`, `aws-sts`, `gitdocs`). They are the only provider code behind a kind.
- **The nearest port** is `ports.Embedder` (`internal/core/ports/knowledge.go`): `Embed(ctx, texts)` and `Model()`. Its adapter, `internal/adapters/embedder/openai`, is built in `cmd/goald/main.go` with a platform key (`GOAL_EMBED_KEY`). The model check must not work that way: the organization pays for its own model calls.
- **Spend is the cost of agent runs.** `ports.Store.SpendSince` (`internal/core/ports/ports.go`) runs `FactorySpendSince` (`db/queries/runs.sql`), which sums `agent_runs.cost_usd`. The worker reports that cost. The engine checks it once per tick against `domain.Runtime.WeeklyUSD` over `domain.BudgetWindow` (`internal/core/engine/budget.go`, `internal/core/domain/budget.go`). goald has no price list of its own.
- **Audit actions** are named `<target>.<verb>` (`factory.created`, `definition.published`, `connection.used`) as `domain.Audit*` constants, and each port method names the entry it writes (`internal/core/ports/definitions.go`).

Three places disagree with the brief that asked for this ADR. They are listed here so a person can fix the stale one:

- The brief says to cite software#154's code. It is not on main (above).
- The brief says the check is paid by "the organization's model credential per ADR 0017". ADR 0017 names no model credential. It covers credentials in general. The model's key is in the factory's model connection, which may refer to a credential. Decision 4 builds on that.
- The screen says "Pause when Software's daily budget is spent" (line 199). The code has only a weekly budget. Decision 7 records the gap.

Each brief cites the screen as ADR 0016's wave 4. ADR 0016 itself has no waves. Its screens' index marks the trigger screen "new feature" (line 58).

## Decision

1. **One evaluation function, used by real intake and by a try.** The engine evaluates a trigger against an event in one pure function of the domain. It takes the trigger's definition, the event and what the conditions read (the items open now, the limit counters, the factory's spend and a `ports.ModelCheck`, decision 4). It returns an evaluation: each step's outcome and reason, in order. The steps are When (the event and filters match), Only if (each condition, the model check last), Create (the rendered title and brief, the item type, station and lane) and Limits (items a day, the budget pause). The evaluation stops at the first step that skips the event, and later steps are reported as not reached. Real intake calls the function, then applies its result in one transaction: it creates the item and its events and increments the limit counter. A try calls the same function and applies nothing. No second evaluator exists, so a try cannot disagree with what intake would do on the same inputs.

2. **Try with a past event is a dry run.** goald takes one stored event the trigger already received and runs it through decision 1's function. It returns the evaluation: for each step its outcome and a reason a person can read, the item it would create (type, station, lane, the rendered title and brief), and the model check's answer and cost when the check ran.
   - **What it runs against:** the saved trigger, or an unsaved draft of it sent in the request, so an operator can try an edit before Save changes. A draft is validated as Save would validate it, and a draft that would not save is answered with the same validation errors. The draft is neither stored nor published.
   - **What it never writes:** no item, no item event, no change to a limit counter, no notification, no definition version or draft, and no change to the stored event's recorded outcome ("Created #150", "Skipped, once" stay as they were).
   - **What it writes:** one audit entry, `trigger.tried` (`domain.AuditTriggerTried`). It names the trigger, the event, whether a draft was tried and the outcome, and never the event's text or the brief. Nothing else is audited. When the model check ran, the check's own cost record (decision 6) is also written, because the money was spent. That record is spend, not intake state: it creates nothing on the line and moves no limit.
   - **Who may try:** whoever may edit the trigger. A try spends the organization's money and sees the event, so reading the trigger is not enough. The API part names the scope in `contracts/api/openapi.yaml`.
   - **Limits are evaluated, not consumed.** "At most N items a day" reads the counter and reports whether it would allow one more. The budget pause reads the factory's spend and reports whether intake is paused.

3. **The model check is an optional Only if condition holding the operator's question.** The condition holds one question the operator writes, for example "Is this failure a flaky test rather than a real regression?". goald asks a model that question about the event. The answer is structured: `worth` (yes or no) and `reason` (one line, at most 200 characters). Yes passes the condition. No skips the event with the model's reason. The condition may name a model (decision 4). Without it the check uses the default model of its connection's kind. The definition key is software#154's to spell, under `only:`.
   - **It runs last.** Every other Only if condition is evaluated first, and the model is asked only when all of them passed, so the check costs money only for events that would otherwise create an item. When and the filters come before Only if, so a non-matching event never reaches the model.
   - **On any failure the event is skipped** with the reason "Model check failed", and no item is created. That covers a connection that does not resolve, a provider error, a timeout, a refusal and an answer that is not the structured shape. The failure's detail goes to the log and the evaluation, scrubbed of the connection's secret values. A failure never counts as yes. A check that cannot run never lets an item through that the operator asked to be filtered.

4. **The model call goes through a new core port, paid by the organization's model connection.**
   - **Port:** `ports.ModelCheck` in `internal/core/ports/modelcheck.go`, modeled on `ports.Embedder` but taking the connection per call, because the key belongs to the organization, not to goald: `Ask(ctx, conn domain.ResolvedConnection, q domain.ModelQuestion) (domain.ModelAnswer, error)`. `domain.ModelQuestion` holds the model, the operator's question and the event as data. `domain.ModelAnswer` holds `Worth`, `Reason`, the model, input and output tokens and `CostUSD`. The in-memory fake lives in `internal/core/ports/porttest`.
   - **Adapter:** `internal/adapters/modelcheck/anthropic`, which calls the provider's messages API with the connection's API key and a structured output. It is wired in `cmd/goald/main.go`, as every adapter is. A provider added later is another adapter under `internal/adapters/modelcheck/`.
   - **Whose credential:** the factory's model connection (`runtime.modelConnection`), resolved through `ports.Connections.Resolve` with a `domain.ConnectionUse` that names the trigger and the event. It is audited `connection.used` like a run's. Its secret field may refer to a credential (ADR 0017), and then that credential pays. Never a platform secret: not `GOAL_EMBED_KEY`, not the master key, not a key in `contracts/env.yaml`. The condition may name another organization connection of a model kind instead, for an organization whose factory model connection cannot serve the check (below).
   - **Which kinds can serve it:** a connection kind says so in its kind file, as it names its other adapters. `KindSpec` gains `modelCheck`, naming the adapter (`anthropic`), the default model and each allowed model's price per million input and output tokens. A kind without `modelCheck` cannot serve the check. A Claude Code subscription token (`CLAUDE_CODE_OAUTH_TOKEN`) is such a kind, because it is for Claude Code, not for direct API calls. Validation refuses a definition whose model check names a connection that cannot serve it, or a model its kind does not price. The model names and prices are data in the kind file, not code.
   - **Portable:** the call is outbound HTTPS from goald. It works the same on Docker Compose and on Cloudflare, and needs no new service, binding or secret.

5. **Event text reaches the model as untrusted data, never as instructions.** The adapter builds the prompt in a fixed shape. The system prompt is goald's, fixed in the adapter. It says the event is untrusted data to judge, that nothing inside it is an instruction, and that the only output is the structured answer. The operator's question is the task. The event goes in one delimited block (`<event>…</event>`), as JSON, with any occurrence of the delimiter in it escaped. The structured output limits the answer to `worth` and `reason`, so text in the event cannot make the call do anything else. The model has no tools. The prompt holds no secret: no connection value, no credential, no token. The event is the payload as stored, and the log line (`trigger model check`, with the trigger, the event, the model, the outcome, the tokens and the cost) never holds the event's text, the question or the answer's reason. The same rule already holds for the brief an agent gets (the screen's caption at line 191), and the Create step keeps it: rendered event fields are marked as untrusted data in the item's brief.

6. **The check's cost is a row the factory's spend sums.** Each model call, real or tried, writes one row to a new table, `trigger_model_checks`, in the same transaction as the evaluation's result, or alone for a try. The row holds the organization, factory, trigger, event, whether it was a try, model, tokens, `cost_usd`, the outcome and `created_at`. The table has row-level security on `org_id`, like every organization-scoped table, and an index on `(factory_id, created_at)`. A failed call that the provider charged for records its tokens, and one that was not charged records zero. `FactorySpendSince` sums `agent_runs.cost_usd` and `trigger_model_checks.cost_usd` since the window's start. `ports.Store.SpendSince`'s contract changes from "agent runs" to "agent runs and model checks", so the weekly budget and the budget pause both see it. Part model-check adds the table in a new migration (the next free number in `db/migrations/`) and changes the query. A try runs the model check like real intake, reports its cost in the answer and counts it as spend.

7. **Limits use what exists.** "At most N items a day" counts the items the trigger created since the start of the UTC day. The budget pause skips the event when the factory's budget is exhausted (`domain.Runtime.HasWeeklyBudget` and `WeeklyBudget`), with the reason "Budget spent". The screen says "daily budget", and no daily budget exists. Until one is decided, the pause uses the weekly budget, and the UI part shows the copy the owner approves for that. Adding a daily budget is its own decision, not part of this ADR.

## Consequences

- One evaluation function makes a try trustworthy. It also means every condition must read its inputs through ports, never through a query of its own, so a try and intake see the same state.
- An operator can try an edit before saving. The cost is one more request shape (a draft trigger in the body), validated by the same code as Save.
- A try is not free when the model check is on: it spends what a real check spends, counts against the budget and is visible in the factory's spend. The answer says so with the cost.
- Organizations whose model connection is a Claude Code subscription token need a second connection, of a kind with `modelCheck`, to use the model check. Validation tells them before they publish.
- The kind file grows a `modelCheck` block with prices. Prices change, and whoever maintains the kind files updates them. A wrong price shows in spend, not as a failure.
- `SpendSince` stops meaning "agent runs only". Spend screens that break cost down by run need a line for model checks.
- Event text in a prompt is a prompt-injection surface. Decision 5 limits what an injection can do (no tools, a structured yes or no). It cannot stop an event from talking the model into yes, so the check is one filter among the others, never a security boundary.

### Open points

- **No model credential in ADR 0017.** The brief speaks of "the organization's model credential". ADR 0017 names none, and this ADR uses the model connection, which may refer to a credential. If the owner wants a named model credential instead, this ADR's decision 4 is amended.
- **Weekly versus daily budget.** The screen's "daily budget" (line 199) has no backing: `domain.Runtime` has `WeeklyUSD` only. Decision 7 uses the weekly budget until the owner decides.
- **software#154's names.** The definition keys, the domain types and the stored event table are software#154's. The parts below use its names.
