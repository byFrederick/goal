# ADR 0008 — Portable deployment, sandboxes, connections and the knowledge base

Status: accepted · 2026-10-24 · Supersedes the deployment targets of [ADR 0003](0003-hexagonal-architecture-and-deployment.md) (decisions 4, 5 and 7) and decisions 2–5 of [ADR 0006](0006-workspaces-and-command-checks.md) · Amends [ADR 0009](0009-agent-network-isolation.md) and [ADR 0005](0005-factory-definitions-in-object-storage.md) · Spec: [phase 4](../history/specs/4-connections-runs-and-knowledge.md) · Amended in phase 6: decision 7 is changed by the [amendment](#amendment--phase-6-one-mcp-server-for-agents-and-clients) at the end ([spec 6](../history/specs/6-goal-mcp-server.md)) · Amended by [ADR 0017](0017-credentials.md): decision 5 is extended by the [amendment](#amendment--2026-10-27-connection-secret-fields-may-refer-to-a-credential) at the end

## Context

Goal runs on one laptop: goald and the auth service on the host, agents in hardened Docker containers, a repository cloned on the host and bind-mounted into the agent, command checks and stdio MCP servers in containers of their own, model and GitHub tokens as platform environment variables shared by every organization, and an AWS deployment (ECS, RDS, Secrets Manager, Bedrock knowledge bases provisioned by Terraform per factory) that was designed and never built. Phase 4 must give organizations their own credentials and a knowledge base, run the same code locally and in one cloud, and stay small. The owner runs it for themself: security proportionate to a personal platform that keeps organizations apart, with agents as free as a developer on their own laptop.

Constraints found while designing (research of 2026-10-24): Cloudflare Containers start one container per Durable Object, accept only HTTP inbound, cannot be networked to each other and must declare their images at deploy; Workers cannot run goald (no TCP for `LISTEN`, CPU limits); Hyperdrive drops `LISTEN/NOTIFY`, advisory locks and session settings; R2 implements neither object versioning nor `ListObjectVersions`; Secrets Store holds at most 100 secrets readable only through bindings.

## Decision

1. **Two deployment targets, one code base.** Local Docker Compose (PostgreSQL 18 with pgvector, RustFS, Mailpit, goald, the auth service, the egress proxy and agent containers) and Cloudflare (goald and the auth service as Cloudflare Containers behind a thin control Worker, R2 through the S3 adapter (`internal/adapters/objectstore/s3`), managed PostgreSQL over a direct TLS connection). Cloudflare is one target behind ports and adapters: its code is the control Worker under `deploy/cloudflare/` and one Go adapter, `internal/adapters/sandboxes/cloudflare`; there is no "if Cloudflare" in the engine. Standard interfaces wherever they exist: S3, the PostgreSQL wire protocol, OCI images, HTTP. AWS is dropped as a target; its Terraform is deleted.
2. **Terraform for the platform only.** `deploy/terraform/` holds the platform's own infrastructure (R2 bucket, DNS, Secrets Store, routes); wrangler deploys what Terraform cannot (the Worker, its Durable Objects, container images). Creating an organization, a connection, a knowledge source or a factory provisions nothing.
3. **`ports.Sandboxes`: one container per run.** It replaces `Runner`, `Workspaces`, `Checker`, `Sidecars` and the Docker `Reaper`: create a run's box (image, size, settings, deadline), exec commands in it (prepare, the agent, its retries, the station's checks) with per-exec environment and runtime exit codes, delete it, list boxes for reaping. Adapters: `docker` (goald in Compose with the Docker socket mounted, or as a host binary) and `cloudflare` (the control Worker's small sandbox API; a Durable Object per run destroys its box at the deadline). The box is the isolation boundary and is disposable: writable, nothing mounted, deleted after the run. The repository is cloned inside it; agent files come from the gateway (`GET /run`). Autoscaling is the existing lease slots: zero boxes when nothing is claimable, at most a work center's agent count.
4. **One base image.** `goal-agent` carries the worker (Claude Agent SDK), git, gh, mise, Go, Node, Python and PostgreSQL server binaries. Tools come from the cloned repository's `mise.toml`/`.tool-versions` and the definition's `runtime.tools`, installed at prepare. `runtime.image` goes away, which Cloudflare's declared images also require.
5. **Connections carry credentials and hand them to runs.** A connection kind is data (fields, which are secret, an env mapping, an optional remote or stdio MCP server, an optional CLI tool, a git login, a docs hint); the platform ships a few and organizations add their own. Provider code exists only where it cannot be data: code hosts for the merge station (`github`, `gitlab`), AWS STS minting, knowledge sync readers (`gitdocs`, `confluence`). A connection is an org row whose secret values are sealed with AES-256-GCM under one platform master key with a key id (`ports.MasterKey`; from env or a file, on Cloudflare a Secrets Store value passed as env), write-only through the API, under row-level security and audited on create, change, test and use. A factory definition names the connections it uses; a run's box receives each one's values as the environment variables its kind declares, which API calls, CLIs and MCP servers use directly from the box: a remote MCP server is configured with its URL and a header rendered from those variables (`Authorization: Bearer ${DD_API_KEY}`), exactly like an API call (owner decision, 2026-10-24). AWS stored keys never reach a box: goald mints STS credentials per run. A token's own scope is the limit; Goal adds no repository allow-lists, branch rules or proxies in front of the code host.
6. **One knowledge base per organization, in PostgreSQL.** Sources are uploads (originals in the bucket under `orgs/<org-id>/knowledge/`), synced connections (text chunks, embeddings and a link back; originals stay at the source) and live connections (searched through their own tools, not indexed). One ingestion loop in goald claims due sources with leases. Chunks live in PostgreSQL with pgvector (`halfvec(1024)`, HNSW) and a `tsvector`; one query fuses vector and keyword ranks, filtered by the sources a factory lists, under row-level security. Embeddings come through `ports.Embedder` (OpenAI-compatible HTTP: Workers AI, a local model or any provider). Agents use the gateway's `knowledge__search` and `knowledge__read`. Phase 4 also measures human touches per item (spec 4 §4.9); [phase 5](../history/specs/5-continuous-learning.md) adds a built-in Learned source per organization through the same port and pipeline, so continuous learning needs no store of its own.
7. **The gateway is Goal's MCP server for runs.** It serves Goal's own tools (`knowledge__search`, `knowledge__read`, later item tools) and the run bundle (`GET /run`), authorized by the run's task token. It proxies no connection and adds no header. OAuth connections and approval-gated calls (deferred) may route through it when they arrive.

## Rejected

- **AWS as the cloud target** (ECS, RDS, Secrets Manager, Bedrock knowledge bases): more services to run and pay for than a personal platform needs, a knowledge base provisioned per factory by Terraform (against decision 2), Secrets Manager at about $0.40 per credential a month.
- **goald on Workers, or Hyperdrive to PostgreSQL**: no `LISTEN`, no advisory locks, no session settings.
- **Cloudflare's Sandbox SDK**: TypeScript only and still changing; plain Containers do what the port needs.
- **Gateway-only egress, a git proxy with ref rules, per-run egress allow-lists, placeholder credentials, AWS request re-signing** (proposed by the phase 4 reviews): each would make goald a proxy for every tool an agent uses, in exchange for protecting credentials that the token's own scope already bounds. Disproportionate for one owner.
- **Per-organization data keys or KMS now**: one master key with a key id gives rotation; a KMS adapter fits the same port later.
- **Vectorize or AI Search** for the knowledge base: Cloudflare-only, nothing to run locally; pgvector is the same on both targets and stays under row-level security.
- **Remote MCP servers behind the gateway, which adds the header**: it kept one mode's credential out of the box while the same tokens are in the box for APIs and CLIs, at the cost of per-connection host checks and forwarding in goald.
- **Sidecar containers for stdio MCP servers and CLIs**: Cloudflare cannot network containers, and the gateway's in-memory sidecar registry was its only state; they run inside the box.
- **A shared, run-written tool cache**: a cross-organization poisoning path; mise installs per run (a read-only cache filled by a trusted job may come later).

## Consequences

- An agent holds its connections' credentials for the run's life and has the public internet: a prompt-injected agent can misuse or exfiltrate what its tokens reach. Narrow tokens are the control; the spec lists this and the other accepted risks plainly (spec 4 §11.3).
- ADR 0006's host clone and bind mount, its token kept inside one git process, its separate check container and its dev image are gone; the branch per item survives as the default checkout. Checks run in the run's own box, with no connection environment, and their exit codes come from the runtime.
- goald in local Compose holds the Docker socket, which is root on that machine; acceptable on one's own laptop only. goald as a host binary keeps working with the same adapter.
- The gateway loses its sidecar registry and its upstream forwarding, so it holds no connection and any goald serves any agent request. `tools.allow/deny` on a connection's tools is the worker's, which a prompt-injected agent holding the token can bypass (spec 4 §11.3). A goald redeploy on Cloudflare ends its runs in flight; leases requeue them.
- ADR 0007's auth service stays a separate process; in the cloud it is a container that only goald reaches (through the Worker), with the proxy secret as today.
- The object store drops object versions (ADR 0005 amendment) and the legacy import goes with them.
- The definition's `evals/` folder, reserved since ADR 0002, gets its phase: phase 5 (continuous learning, Jonah) runs eval cases as ordinary runs in sandboxes pinned to a version, and ADR 0002 is amended to that smaller loop. Goal's own MCP server moves to phase 6.
- Prototypes come first: a real run on Cloudflare Containers (start, exec, internet, private addresses unreachable) and our migrations on a managed PostgreSQL (PlanetScale Postgres or Neon), which also chooses the provider.
- Rough cost of the lean Cloudflare install, model tokens excluded: Workers $5, goald container $10–30, auth $3–8, PostgreSQL $0–5, R2 about $0, about $0.04 per 15-minute run: $25–50 a month.

## Amendment — phase 6: one MCP server for agents and clients

Owner decision, 2026-10-25. Decision 7 changes: the gateway's MCP endpoint and Goal's MCP server for outside clients ([spec 6](../history/specs/6-goal-mcp-server.md)) become one server with one tool registry, one permission check and one audit, in `internal/api`. Callers decide what they may use: people and outside apps (OAuth through Better Auth, MCP-audience keys and personal tokens) act with their organization role at `/v1/mcp`; a run's task token is a restricted principal at `/mcp` (its organization, factory and item, its factory's `knowledge.sources`, the tools an agent may call, only while the run is live). The gateway's own registry and token check go; its listener (`gateway.internal` on Cloudflare, `goal-egress` locally), `GET /run` and goald minting one task token per run stay, so boxes still reach Goal only through their own route and never hold an OAuth token. Tool names keep the `<server>__<tool>` form agents use (`knowledge__search`).

Rejected: two servers with two registries (each tool written and permission-checked twice, and the agents' set drifting from the people's); OAuth tokens for runs (a run's rights come from its definition and its item, not a person's consent, and must end with the run).

## Amendment — 2026-10-27: connection secret fields may refer to a credential

Status: accepted · 2026-10-27 · Extends decision 5 · Decided in [ADR 0017](0017-credentials.md)

Decision 5 changes in one point: a connection's secret field may hold, instead of a sealed value, a reference `{{name}}` to an organization credential, stored in the clear and opened at run start under the credential's factory scope. Credentials are sealed under the same master key, and agents may also receive them directly. The rules are ADR 0017's decisions 5 to 8.
