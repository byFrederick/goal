# Change map

Keep this map accurate: every pull request that adds a new coupling between files adds or updates its row.

When you change X, also change Y, and run Z. Paths are today's; the moves of [ADR 0013](../adr/0013-repository-layout.md) update them.

| When you change | Also change | Run |
| --- | --- | --- |
| `contracts/api/openapi.yaml` | The handler in `internal/api` (never the generated `internal/api/gen`); the client in `packages/api-client` (its generated `src/schema.gen.ts` comes from the task, routes and helpers by hand); the callers in `apps/web/`; the spec and docs that describe the endpoint | `task api:gen`, `task gen:check`, `task test`, `task api-client:check`, `task web:check` |
| `contracts/api/permissions.yaml` | The operations' `x-goal-scope` in `contracts/api/openapi.yaml`; the generated table `internal/api/permissions.gen.go` and the auth roles `apps/auth/src/access.gen.ts` (both from the task); the permission tests (`internal/api/permissions_internal_test.go`, `tools/permgen`) | `task api:gen`, `task gen:check`, `task test`, `task auth:check` |
| A migration (a new file in `db/migrations/`, the highest number plus one) | The queries in `db/queries/` and the generated `internal/adapters/postgres/db` (`*.gen.go`); the `Store` port (`internal/ports/ports.go`) and its in-memory fake in `internal/ports/porttest`; the conformance suite `TestStore_Conformance`, which runs against the fake and PostgreSQL (`internal/adapters/postgres/store_integration_test.go`); row-level security for an org-scoped table | `task sqlc`, `task gen:check`, `task migrate-check`, `task test`, `task test-integration` |
| A new environment read (a variable any process, `compose.yaml` or a `Taskfile.yml` reads), or one that stops being read | Its entry in `contracts/env.yaml` (readers, class, required, meaning; `indirect:` when the name is computed at run time); the generated `docs/reference/environment.md`. `tools/envcheck` finds reads by their syntax (`os.Getenv`, `os.LookupEnv`, `getenv`, `lookup`, `or`, `env:NAME` constants in Go; `process.env.X`, `env.X`, `env['X']`, `get('X')`, `required(env, 'X')` in TypeScript; wrangler.jsonc vars and Secrets Store bindings): a read through a helper with another name is not seen, so declare it with `indirect:` | `task env:check -- -write`, then `task env:check` |
| `.env.example` | Every variable it shows, commented or not, is declared in `contracts/env.yaml`; a secret-class variable has an empty value or a `dev-only` placeholder | `task env:check` |
| A new environment variable or platform secret | Its entry in `contracts/env.yaml` (the row above); `.env.example`; `docs/engineering/cloudflare-operations.md`; for a secret, its Terraform secret and consumers in `deploy/terraform/secrets.tf`; the container environment in `deploy/cloudflare` (`wrangler.jsonc`, `src/env.ts`); reading it through the `Secrets` port (`internal/ports/ports.go`), wired in `cmd/<binary>/main.go` | `task env:check`, `task test`, `task cloudflare:check`, `task tf:check` |
| A definition schema in `contracts/definitions/` (factory, evals, connection kind) | `contracts/definitions/schema.go`; the loader and checks in `internal/config`; `internal/connkind` and its kind files; the builder's metadata in `internal/builder`; the test fixtures in `internal/config/testdata`; the docs and spec that describe the field | `task validate`, `task test`, `task web:check` when the builder's editor shows the field |
| A Dockerfile (`cmd/goald`, `cmd/goal-egress`, `auth`, `worker`) | Its `Dockerfile.dockerignore`; its inputs in `deploy/cloudflare/scripts/images.mjs`; the app paths list of `.github/workflows/deploy.yml` | `task cloudflare:check`, the image's task (`task goald:image`, `task egress:image`, `task auth:image`, `task worker:image`) |
| Moving a directory | The root `Taskfile.yml` and the area Taskfiles it includes (`apps/web/`, `apps/auth/`, `apps/worker/`, `db/`, `deploy/cloudflare/`, `deploy/terraform/`, `contracts/`, `packages/api-client/`): their paths, `dir:`, `sources:` and the root's `includes:`; `tools/checkplan`'s path table; the path filters and `working-directory` of `.github/workflows/ci.yml`, `deploy.yml`, `terraform-plan.yml` and `terraform-apply.yml`; Dockerfile `COPY` paths and `.dockerignore` files; `deploy/cloudflare/scripts/images.mjs`; `pnpm-workspace.yaml`; Go import paths; the `paths:` globs of `.claude/rules`; the repository map in `AGENTS.md`; the History of ADR 0013 (these three are `tools/layoutcheck`'s inputs, with the tracked files) | `task layout:check`, `task check`, `task migrate-check` when `db/migrations/` or `apps/auth/` moved |
| A new top-level directory, or a rule's `paths:` in `.claude/rules` | The repository map in `AGENTS.md` and the layout of ADR 0013 (a new top-level directory also needs the ADR's amendment, its decision 2); a glob must match at least one tracked file | `task layout:check` |
| Adding, renaming or moving a task (in the root `Taskfile.yml` or an area's) | `tools/layoutcheck/tasks.txt` (every name `task --list-all` shows, sorted); a new area Taskfile gets an `includes:` entry in the root with `flatten: true` and `dir: "{{.ROOT_DIR}}"`; for a rename, everything that calls it by name: `.github/workflows/`, `.githooks/`, `tools/checkplan`, the docs, `.claude/rules` and the `goal-*` skills | `task layout:check`, `task env:check` when it reads a variable |
| UI under `apps/web/` | Follow `docs/design/MASTER.md` exactly and `docs/engineering/frontend.md`; the Vitest tests beside the changed components | `task web:check`, `task web:e2e` where a browser is available |
| A generator, its config or its output name (`tools/permgen`, `internal/api/gen/oapi-codegen.yaml`, api-client's `gen` script, `db/sqlc.yaml`, the web build's router plugin, `tools/envcheck`) | The generated files below and their row; `task gen`; the `*.gen.*` exclusions of `.golangci.yml` and each `biome.json`; `tools/checkplan` | `task gen`, then `task gen:check` |

## Generated files

Every generated file has `.gen.` before its extension ([ADR 0013](../adr/0013-repository-layout.md), decision 4), and nobody edits one by hand: change its source and run its task. `task gen` runs every generator; `task gen:check` (part of `task check`) fails when any file below differs from the commit or is untracked, checked before the generators run (an uncommitted hand edit) and after. `.golangci.yml` and the `biome.json` files ignore `*.gen.*`.

| File | Generator | Source | Task |
| --- | --- | --- | --- |
| `internal/api/gen/api.gen.go` | oapi-codegen (pinned in `Taskfile.yml`, config `internal/api/gen/oapi-codegen.yaml`) | `contracts/api/openapi.yaml` | `task api:gen` |
| `internal/api/permissions.gen.go` | `tools/permgen` | `contracts/api/permissions.yaml`, the operations' `x-goal-scope` in `contracts/api/openapi.yaml` | `task api:gen` (`task api:permissions-check` checks it alone) |
| `apps/auth/src/access.gen.ts` | `tools/permgen` | `contracts/api/permissions.yaml` | `task api:gen` |
| `packages/api-client/src/schema.gen.ts` | openapi-typescript (api-client's `gen` script) | `contracts/api/openapi.yaml` | `task api:gen` (api-client's `check:gen` checks it alone) |
| `internal/adapters/postgres/db/db.gen.go`, `models.gen.go`, `batch.gen.go`, `<query>.sql.gen.go` | sqlc (`db/sqlc.yaml`; the names come from its `output_*_file_name` and `output_files_suffix` options) | `db/queries/`, `db/migrations/` | `task sqlc` |
| `apps/web/src/routeTree.gen.ts` | the TanStack router plugin in `apps/web/vite.config.ts`, during the web build | `apps/web/src/routes/` | `task web:build` (`task gen` runs the build directly) |
| `docs/reference/environment.md` (the one exception to the name rule: a reference page other docs link to) | `tools/envcheck -write` | `contracts/env.yaml` | `task env:check -- -write` |
