# Frontend and monorepo

The UI is a static React single-page app. `goald` embeds it for the laptop; the same build deploys to Vercel or S3 + CloudFront. One OpenAPI contract connects it to the Go backend, and generated types keep both sides in step. Decision: [ADR 0004](../adr/0004-frontend-and-monorepo.md).

## Monorepo layout

One repository, two toolchains: a Go module at the root and a pnpm workspace for TypeScript. The root `Taskfile.yml` and the area Taskfiles it includes (`apps/web/`, `apps/auth/`, `apps/worker/`, `packages/api-client/`… [ADR 0013](../adr/0013-repository-layout.md)) orchestrate both (Turborepo is not installed; it earns its place once workspace builds need caching), and `task check` runs both.

```
goal/
  go.mod                       Go module (goald, goal CLI, engine, adapters)
  cmd/  internal/  db/          Go code, and db/migrations/, db/queries/, db/sqlc.yaml
  contracts/api/openapi.yaml   THE contract between goald and every TypeScript client (incl. the SSE StreamEvent)
  contracts/definitions/       factory.schema.json, evals.schema.json (judges, eval cases), connection-kind.schema.json
  package.json                 private root: pnpm only, no app code
  pnpm-workspace.yaml          the apps (auth, web, worker) and packages/*; the catalog pins better-auth once
  apps/
    auth/                      the identity service (Node 22, Hono + Better Auth; phase 3, ADR 0007)
    web/                       the UI (React 19 + Vite)
    worker/                    the agent container (Node 22 + Claude Agent SDK)
  packages/
    contracts/                 generated: TS types from contracts/api/openapi.yaml and contracts/definitions/*.json
    api-client/                typed fetch client (openapi-fetch), errors as Problem, SSE subscription
    ui/                        design system: tokens from docs/design/MASTER.md + shadcn/Radix components
    config/                    shared Biome config and tsconfig bases (Node, browser, Workers); no Vitest preset
```

Rules:

- `web` and `worker` depend on `packages/*`, never on each other.
- `packages/contracts` is generated and committed; CI fails if regenerating it produces a diff, so the Go and TypeScript sides cannot drift.
- `packages/ui` has no knowledge of Goal's API; it only renders. Domain components live in `web`.
- Exact versions in `package.json`, one lockfile (`pnpm-lock.yaml`), `pnpm` pinned via `packageManager` and `.mise.toml`.

## The contract

`contracts/api/openapi.yaml` (OpenAPI 3.1) is written first, by hand, and reviewed like code.

- Go: `oapi-codegen` generates a strict server interface that `internal/adapters/http` implements. Handlers call the engine through ports, as everywhere else.
- TypeScript: `openapi-typescript` generates types into `packages/contracts`; `openapi-fetch` gives a typed client with no hand-written fetch code.
- Realtime: `GET /v1/orgs/{org}/stream?factory=` streams one organization's Server-Sent Events: `event: item` (data: the `StreamEvent` schema in `contracts/api/openapi.yaml`, `id:` the event id) and `event: resync` (data `{}`: events may have been missed). There is no replay, so a client re-reads what it shows after a reconnect or a resync. The client turns each event into a TanStack Query cache invalidation, so screens update without polling.
- Factory and eval files keep their JSON Schemas in `contracts/definitions/`; the same schemas drive Go validation, TS types and the YAML editor's autocompletion.

## Web app architecture

| Concern | Choice | Why |
| --- | --- | --- |
| Build | Vite, TypeScript strict | Fast, static output, no server to run |
| Routing | TanStack Router, file-based | Type-safe routes and search params; every filter, tab and selection lives in the URL so any view can be linked |
| Server state | TanStack Query | Caching, retries, optimistic updates; SSE events invalidate queries |
| Local state | React state; no global store | Server state and URL state cover nearly everything; add a store only when a measured need appears |
| Styling | Tailwind v4 with `@theme` tokens generated from MASTER.md | One source of truth for palette, type, radii; no hex values in components |
| Components | shadcn/ui on Radix, in `packages/ui` | Accessible primitives we own and can restyle |
| Board drag and drop | dnd-kit with keyboard sensors, plus a Move menu on every card | WCAG 2.2 dragging alternative |
| Factory editor | Monaco with monaco-yaml bound to `contracts/definitions/factory.schema.json`; the line preview is a plain HTML list, and stations reorder with dnd-kit plus ↑ ↓ buttons and Alt+Arrow | Autocompletion and inline errors while editing YAML; a linear line needs no graph canvas, and a list is accessible |
| Charts | Small SVG components in `packages/ui` (hatched bars, bridge, sparkline) | Exactly the design system's marks; no heavy chart library |
| Long lists | TanStack Virtual for traces and big boards | Keeps the main thread free |

### The API module and `@goal/api-client`

`packages/api-client` is the typed layer over the contract: `createGoalClient` (openapi-fetch over the types `openapi-typescript` generates into `src/schema.gen.ts`, with `--default-non-nullable=false` so request fields with a default stay optional), `unwrap` (data on success, else it throws `ApiError`, which carries the RFC 9457 `Problem` with its `code` (`slug-taken`, `confirmation-mismatch`, …) for screens to branch on, rebuilt from the status line when a proxy answers with something else), `subscribe(baseUrl, scope, handlers)` for the stream, and the schema types. Organization-owned routes are written relative to the organization with `orgPath("/factories/{factory}/board")`; `routes.ts` holds the one prefix (`orgRoutes`, `/v1/orgs/{org}`), and every such call passes `org` (slug or id) as a path parameter, as `StreamScope` does.

### Signing in (phase 3)

With `GOAL_AUTH=session` people sign in on `/sign-in` with an emailed code or Google (spec 3 §10). The account (`app/account-menu.tsx`, from `['me']` and the organization's `role`) names the person with a role pill (and Platform admin). Its body is one component for the popover and the phone's sheet, with four states: loading (`aria-busy`, sr-only "Loading"), error ("Can’t reach Goal"; the theme and the sign-out actions stay usable), sign-in off (the local user, no actions) and ready. ### Live updates

`shared/stream.tsx` (`OrgStream`, mounted by the `/o/$org` layout) opens one `EventSource` per open organization, on its stream. Each `item` event invalidates what it can change (`invalidationsFor` in `shared/invalidation.ts`): the organization's attention counts and inboxes, the factory's work keys named one by one (board, metrics, touches, items; only the board for tool calls; never the factory's bare prefix) and that item by ref and by id, batched over 300 ms so a burst of tool calls costs one refetch; the factory overviews at most every 5 s. The item's history refetch asks only for events after the last one cached. `resync`, and every reconnect after the first open, invalidate everything of the organization (`['org', org]`). A `factory` event (an andon pulled or cleared; the client's typed `onFactory`) invalidates the factory's work keys, the attention counts, the inboxes and the overviews (`factoryInvalidations`). A `connection` event (spec 4 §8.3) invalidates everything under `['org', org, 'connections']` (`connectionInvalidations`), a `knowledge` event (a source's sync started or ended) everything under `['org', org, 'knowledge']` (`knowledgeInvalidations`), and a definition's `current` event both, since what uses a connection or may search a source is read from the current versions. Other event names are handled through the `streamHandlers` registry; names nobody registered are ignored. Switching organization closes the old stream and opens the new one. `shared/stream-presence.ts` (`followPresence`) decides what `OrgStream` exposes. The shell says "Reconnecting" and the board's line status adds "reconnecting…" only after the stream has been down for 5 s (the grace period) while the page is visible; a short drop is silent, and a hidden page never counts as reconnecting. A return to the page (`visibilitychange`, or `pageshow` from the back/forward cache) reopens the stream at once, without waiting for EventSource's retry, closing the old one first; the reopened stream resyncs (every organization query refetches) so the screens are current without a banner. The board's line status still adds "connecting…" while the first open is pending.

### Decisions

Approve and retry act at once (they only move work forward); send back asks for a reason in a dialog, and merge asks for confirmation. Merge replaces approve at a human station whose `action` is `merge`; nothing is keyed by station names. Decisions carry no actor: goald records the request's (the local user until phase 4 adds sign-in).

The item page's question card (`features/items/question-card.tsx`, the you-tint `section` above the tabs, ADR 0018) renders `Item.question` and nothing else: no question, no card. Its choices are the quick answers, one secondary button each with `border-you/40`, and Write an answer (ghost, in you-ink) opens a textarea with Send (1 to 2000 characters, trimmed). A choice calls `answerItem(org, item, {choice: index})` and an answer `answerItem(org, item, {answer})` (`api/client.ts`, POST `…/items/{item}/answer`); both are disabled while the call runs. On success the card sets the item from the response and invalidates the item's queries (`itemChangeInvalidations`, plus its events). A refusal (409 `no-open-question`, 400 `bad-choice`) shows goald's problem detail inline in an alert. Without `item:decide` on the factory's `can`, the choices, Write an answer and Send render `aria-disabled` and point at `reasons.decide(<factory name>)`. ### Needs you

`/o/$org/needs-you` (`routes/o.$org._org.needs-you.tsx`, `features/needs-you/`) lists what waits on a person across the organization's factories. The kind-to-type mapping is in `features/needs-you/types.ts`, a pure function with its own test:

| Entry kind | Type | Shown |
|---|---|---|
| `decision` | Decision (violet) | Under All and Decisions |
| `question` | Question (you-ink) | Under All and Questions |
| `andon`, `rework_warning`, `blocked`, `expedite` | Alert (red ink) | Under All and Alerts |

### Colour theme (dark mode)

Type is Archivo (`@fontsource-variable/archivo`, the `wdth` axis file, self-hosted) for all text and JetBrains Mono (`@fontsource-variable/jetbrains-mono`) for code, paths and commands only; `html` sets tabular numerals. The scale and weights are in MASTER.md, Typography.

The colors are tokens: `apps/web/src/styles.css` defines the light values in `@theme` and the dark ones (MASTER.md, "Dark theme") under `:root[data-theme="dark"]` and under `prefers-color-scheme: dark` for `:root:not([data-theme="light"])`. Components use token names only, so a theme switches without edits; `apps/web/src/ui/raw-colors.test.ts` fails on a hex, `rgb()`, `rgba()` or `hsl()` outside the allow-list, which is empty now: the Monaco theme reads its colours from the tokens. The text on a run, violet or red fill is `--color-white` (#FFFFFF in both themes), and the selection is `run-tint`. The shadow is one token, `--shadow-pop`, for popovers and dialogs; everything else is a border. Radii are `--radius-andon` (18), `--radius-card` (14), `--radius-cell` (10), `--radius-control` (8) and `--radius-chip` (6).

The type scale is `--text-meta` (12), `--text-secondary` (13), `--text-body` (14), `--text-heading` (16), `--text-detail-title` (22), `--text-page-title` (26) and `--text-kpi` (28), each a `text-<role>` utility with its line height and weight; the tracking tokens are `--tracking-display` and `--tracking-numeral`; numbers at 112% width use the `font-numeral` utility (styles.css), so no component writes `font-stretch-[112%]`. New code uses these and the 4px spacing scale. `apps/web/src/ui/arbitrary-values.test.ts` counts the existing arbitrary font-size, off-scale spacing and radius classes per source file. The counts are one small JSON per file under `apps/web/src/ui/arbitrary-values/`, at the source's path with `.json` added (`features/board/board-card.tsx.json`), so two changes conflict only when they touch the same source file. A file may not gain a use, and a screen that clears its uses lowers its counts in the same change: run `pnpm --filter web baseline:arbitrary` (`apps/web/scripts/baseline-arbitrary.ts`), which rewrites the JSONs for the current counts, deletes those that reach zero, and refuses to raise any count. To settle a baseline conflict, take main's version of the conflicting JSONs and re-run that command.

The choice (Auto, Light or Dark; Auto is stored as `system`) is one localStorage key, `goal-theme`, per browser (`apps/web/src/shared/theme.ts`; a missing or unknown value is Auto). `apps/web/public/theme.js` is a classic script in `index.html`'s `<head>`, before the module, so it sets `data-theme` and `style.colorScheme` on `<html>` before first paint; it reads the same key and must stay in step with `theme.ts`. CSP is `script-src 'self'`, so it cannot be inline, and it must not be a module or deferred. `useTheme()` (in `theme.ts`) gives the choice, the resolved theme and the setter; the account menu's Theme choice sets it, and the toaster in `routes/__root.tsx` takes the resolved theme. `theme.test.ts` checks the persistence, fallbacks, live system changes and that the dark blocks define every token; `theme-boot.test.ts` runs `theme.js` against fake objects and checks its place in `index.html`.

### The intake trigger page

`…/f/$factory/intake/$trigger` (`features/intake/`, ADR 0016's `trigger` screen) shows one trigger of the
factory's current definition: its title with the on/off switch, this week's created, merged and spend,
the When, Only if, Create and Limits blocks, its recent events, and its YAML in the definition. Reads go
through `intakeTriggerQuery` (`GET …/intake/triggers/{trigger}`) and the definition's `factory.yaml`
(the open draft's when there is one, else the running version's).

Save changes writes `spec.board.triggers[name]` and nothing else. `trigger-save.ts` runs the draft files
API in order: open the draft, read `factory.yaml` for its sha256, put the file back with `If-Match`,
validate the draft, publish it. `trigger-yaml.ts` splices only the keys that changed into the text, so
every other line and comment stays byte for byte. A file with no `triggers` key, or an empty one, gets its first
trigger written in place (and `board` under `spec` when that is missing too). The draft-model API cannot carry `board.triggers`
yet (`internal/factorymodel/model.go`), which is why the page does not use it.

Rules the page follows:
- A draft with edits of its own blocks the save, with a link to the definition editor: the page never
  publishes someone else's draft. An invalid save leaves this page's own write in the draft, so that write does not
  block the fix; the page clears the mark once a save publishes or a 412 moves the draft.
- A 412 draft conflict keeps the typed edits and reloads the draft; the user saves again.
- The Create lane select offers Standard and Expedite, then the chosen station's route keys (`readBoard`'s `lanes`:
  a lane is a key of the station's `route`, factory.schema.json). A lane the file names stays selectable.
- Validation problems from `validateDraft` are placed by their line: a problem inside a trigger's key
  shows under that block, any other problem above the form. Save stays off while an error stands.
- A name the definition does not have opens a blank trigger when the URL has `?on=<event key>` (the New
  trigger picker's choice). The picker itself is not on this page.
- "Try with a past event", "A model agrees it is worth an item" and "+ Add another event" render disabled
  with "Not available yet" (ADR 0016, decision 4; ADR 0028 for the model check).

Stream events: a `definition` event and an `item` event both invalidate `intakeKeys.root`, so the
trigger's results and its YAML re-read.

### Intake

The Intake screens (ADR 0016, `intake/`; the triggers of ADR 0026) are `features/intake/`, under `…/f/$factory/intake`. `intake.index.tsx` renders the page and `intake.new.tsx` renders the same page with the New trigger picker over it (`new-trigger-dialog.tsx`). Both are leaf route files: the trigger page (`intake/new/$source`, `intake/$trigger`) and the Webhooks page add their own routes beside them.

- **Data**: `getIntake` (`api/intake.ts`) under `intakeQuery`, keyed `keys.intake(org, factory)`. Item events and the current version's publish (`definition` `current`) invalidate it (`shared/invalidation.ts`). The page owns its states: loading, error, empty (no items and no triggers) and ready. The suggestion tab is `?group=`, kept in the URL.
- **Sources bar** (`sources-bar.tsx`): the newest items' sources as one bar and its legend. The series take foundation tokens (`run`, `ok`, `ink-soft`, `run-soft`, `muted`), not the factory colours, which are for badges.
- **Triggers table** (`triggers-table.tsx`): a table from 768 px; below it each row's cells stack. A problem is named in red under the name. The switch (`trigger-toggle.ts`, `set-trigger-enabled.ts`) runs the definition's draft in order: open the draft, read `factory.yaml`, change only `spec.board.triggers[name].enabled` (`trigger-yaml.ts` edits the text at the parser's offsets, so comments and spacing stay), save the file with its sha256, then publish with `expected_current_version_id` set to the version shown. It refuses while a draft is open, and when the draft that `openDraft` returns already has saves or changes (someone else's edits: the switch says to publish or discard it in Definition) and is disabled without `definition:edit`. A failed step reverts the switch and shows the error.
- **Suggested triggers** (`suggested-triggers.tsx`, `suggestions.ts`): a fixed catalog. Add goes to the trigger page's address; a suggestion whose event the schema does not accept is disabled.
- **New trigger** (`new-trigger-dialog.tsx`, `sources.ts`): MASTER.md's two-pane picker. Schedule, Webhook, GitHub and Cloudflare are choosable; Slack, Linear, Jira and Sentry are disabled ("Not available yet", ADR 0016 decision 4). Only `github.issues.labeled`, `github.check_run.failed` and `schedule` can be chosen (the schema's accepted keys). Continue goes to `…/intake/new/<source>?on=<event key>`, built by `newTriggerHref`.

The Vitest suites are `intake-page.test.tsx` (the four states), `intake-switch.test.tsx` (the publish, the revert, the refusal while a draft is open and the permission), `trigger-yaml.test.ts` and `new-trigger-dialog.test.tsx`. `e2e/intake.spec.ts` covers the page at 1440 and 375 px and the picker; it was not run in the box. The mock's `software` factory has no seeded definition, so the switch's publish is covered by Vitest only.
### Webhooks page

`/o/$org/f/$factory/intake/webhooks` (`routes/o.$org.f.$factory.intake.webhooks.tsx`, `features/webhooks/`), the factory's Intake page for webhook endpoints (ADR 0026). The sidebar's Intake entry stays unavailable until the Intake list is built. The loader prefetches the list (`webhooksQuery`); the page shows its own loading, error, empty and ready states.

- **Data**: `api/webhooks.ts` calls the five webhook operations through the generated client. The list is `['org', org, 'factory', factory, 'webhooks']` (`keys.webhooks`), and each endpoint's deliveries sit under that prefix, so one prefix refreshes both. Addresses are `${origin}${address}`, where `address` is `/hooks/{endpoint id}` as the contract gives it.
- **The one-time secret**: a create or a rotate returns the secret once. Its mutation keeps the answer in the page's state, not in the mutation result or the query cache, and then invalidates the list. The secret dialog (`secret-dialog.tsx`) closes only on Done, and dropping the page's state drops the secret. `webhooks-page.test.tsx` checks that the secret is in no DOM and no query after Done.
- **Rotate** asks first (a confirmation that the sender stops until it has the new secret). A failed rotation keeps the confirmation open and says why inside it; the confirmation closes only when the new secret is shown. Create and Rotate need a sign-in from the last 10 minutes: the session wrapper (`session.ts`) opens the re-auth dialog on `reauth-required` and sends the request once more. `api/webhooks.test.ts` covers that path, and a 401 calls the unauthenticated handler.
- **Refresh**: the list refetches on the factory's item events (`'webhooks'` in `workKeys`, `shared/invalidation.ts`), on resync and on window focus. A created delivery makes an item, so item events cover it. A refused delivery makes no item, and the stream has no event for it, so it shows on the next refetch. The stream's `intake` event is an API follow-up.
- **Feeds**: an endpoint's triggers as chips, or "Nothing. n deliveries were kept but created no items." with a plain link to `…/intake/new` (the trigger page is built by the web-intake part). The count is the week's delivered and refused deliveries.
- **Deliveries**: the newest five of each endpoint, one page; paging is not built. A refused row is red and says its reason. View request opens the request's headers and body; a body that is not UTF-8 text is labelled base64.
- **Send a test**: a curl sample for the first endpoint, with `X-Goal-Signature` (`X-Hub-Signature-256` for a GitHub endpoint). The fields the trigger can read are the top-level keys of the newest accepted delivery's JSON body, or `event` alone. "Send a sample delivery" is `NotAvailable`: the browser never holds a secret, so it cannot sign a request to `/hooks/{id}`.

Differences from `docs/design/screens/intake/webhooks.jpg`, each for a reason:

- The address is `/hooks/{endpoint id}`, not `/hooks/<factory>/<name>`: ADR 0026 decision 3, since a name keys the factory (AGENTS.md rule 2).
- The secret is a sealed secret shown once with Rotate, not a credential "in Credentials": ADR 0026 decision 2.
- The endpoint's name stands where the picture's display title does ("cf-deploys", not "Cloudflare deploys"): the API has no display title.
- Each trigger is named but not placed ("fix at Spec, expedite lane" is left out): the API does not return the placement.
- A refusal has its reason only, with no second explanation line: the API gives no such text.
- The delivery row has no event name ("deploy.failed"): the API has none; the row says the outcome.
- The top bar's crumb reads "Webhooks" beside the factory badge, not "Intake › Webhooks": the Intake page is not built.
- Each day bar's tooltip names the day and its counts; the card's words give the week's totals.
- "Send a test" says the delivery shows "once the page refreshes", not "within seconds": the list refetches on item events and focus, not on a timer.
- Rotate asks for a confirmation, which the picture does not show.

### Models and policies

`/o/$org/models` (`features/models/`, `routes/o.$org._org.models.tsx`) is the organization's policy (ADR 0024): the defaults every factory is held to. `policyQuery` (`api/policy.ts`, key `keys.policy`) reads `getOrgPolicy` and keeps the answer's ETag, the policy's revision, as the If-Match of the next save. ### Credentials (ADR 0017)

`/o/$org/credentials` (`features/credentials/credentials-page.tsx`, `credentials:read`, in the sidebar under Connections) lists the organization's credentials by name: each with its type and icon, the factories whose runs may open it (letter badges, or "All factories"), the connections and agents that use it, its last use, and its expiry. A credential's value is never read back, so the screen has no value to show. The type tabs (All, API keys, OAuth tokens, SSH keys, Cloud roles, App keys, each with its count) are a segmented control in the URL as `?type=` (`api_key`, and so on); the search text is `?q=`. "N expires this week" is a red chip when any credential expires within seven days. Expiry reads from `expires_at` and `remind_days` (`words.ts`, `expiryOf`): no expiry says "Never expires"; outside the reminder window "Expires <date>"; inside it "Expires <date>, in N days" in the danger colour with a Replace button; past it "Expired <date>". Replace (owners and admins, `credential:manage`) opens `SecretReplaceDialog` (`features/connections/replace-secret-dialog.tsx`, the connections' dialog with the save passed in) and sends `PATCH {value}`. Delete asks first and, on a 409 `credential-in-use`, keeps the dialog open with goald's text, which names the blocking connections. Loading, empty, error (with Try again) and ready are rendered. The table scrolls in its own box on a phone.

`/o/$org/credentials/new` (`features/credentials/new-credential-page.tsx`, `credential-new.jpg`) creates one credential or imports many. The top bar carries the crumb "Credentials › New credential" and Cancel. Without `credential:manage` the page says so and shows no form. Its two cards sit side by side from `@[1100px]` and stack below.
- **Create one** (`create-credential-card.tsx`): Name (checked against the contract's `CredentialName` pattern, `nameProblem` in `words.ts`; the hint shows `{{name}}`), Type (a native select of the five types), Value (`SecretInput`, write-only, with "Shown only while you type"), What it is for (optional), the factories (toggle buttons, or "All factories, including new ones", which disables them), and the agents, grouped by the chosen factories. Each factory's agents come from `versionModelQuery(…, 'current')` through `agentNamesOf`; a factory with no current version shows "No agents defined yet". Expires (a date) and Remind me (14, 7 or 30 days before it, or Never; disabled without an expiry). The footer says "Replaces nothing. The old <name> keeps working until you remove it." only when `similarName` finds a credential with the same name before a `-suffix`. Create sends `POST …/credentials` with `scope`, `agents` by factory id, `expires_at` and `remind_days` (0 without an expiry). A 400 or 409 shows goald's text on the form. On success the list's credentials query is invalidated and the page returns to the list.
- **Or import many** (`import-credentials-card.tsx`): a file drop or a paste area, with the masked YAML sample as its placeholder. Pasted text is masked on screen with `-webkit-text-security`, which Chromium and Safari honour (Firefox does not, so there the text shows). After the text settles (300 ms) a dry run (`POST …/credentials/import`, `dry_run: true`) lists "N found", each name as New or Already exists, and "Used by N connections" for an existing one. Replace or Skip (`on_conflict`, Skip by default) and "Import N" write the import, where N counts the new names and, with Replace, the existing ones. The format (YAML or .env) is read from the text. `?panel=import` focuses the paste area and titles the page "Import credentials".

The pasted text, the typed value and the dry run's answer are component state only. Their mutations use `gcTime: 0`, and nothing reaches the URL or a query key, so the screen's tests check the query and mutation caches for them.

Where the screen differs from `credential-new.jpg`, and why:
- **No "Plain value" type.** The contract's `CredentialType` has five values.
- **No "Every 90 days" reminder.** `remind_days` counts days before the expiry, so the options are 14, 7 and 30 days, and Never.
- **Expires is a date input,** not a free text field showing "Oct 29, 2027". The contract takes a date-time.
- **Replace or Skip is one control for all the existing names,** not one per name. The contract takes one `on_conflict` per import.
- **Per-name chips in the import list** replace the picture's Replace/Skip under each name, for the same reason.
- **The Show button** is the shared `SecretInput`'s icon button, labelled "Show the value", not a text button.
- **Import N counts what it writes:** with Skip, the existing names are left out of N.
- **Empty and error states:** the factories' error has Try again; with no factories the scope asks for "All factories".

Mock data: `mock/credentials.ts` holds the seven rows of the picture, with `…/credentials` POST and `…/credentials/import` answering a dry run of the picture's sample as three names, two new and one existing with two connections. The Software and SRE factories define the agents the picture names (`mock/definition-seed.ts`). The Playwright flows (`e2e/credentials.spec.ts`) cover the create and the import; they are not run in the box.

## PWA

Goal installs to a phone's home screen as its own app (standalone, no browser chrome). It starts from the cached app shell, and it updates itself after a Reload prompt (below). Push notifications come later, so approvals can arrive that way.

**Manifest.** `apps/web/public/manifest.webmanifest` is served from the root and linked from `index.html`. Name and short name "Goal", `id`, `start_url` and `scope` "/", `display` "standalone", and `background_color` and `theme_color` `#FFFFFF` (the light `--color-shell`; the dark `theme-color` meta in `index.html` is `#0E1120`). A manifest takes one colour, so dark mode keeps the media-specific `theme-color` metas in `index.html`. goald serves it as `application/manifest+json` (`apps/web/webui.go` names the type, since Go's mime table lacks `.webmanifest` and the image has no `mime.types`) and revalidates it like the favicon.

**Icons.** `icons/icon-192.png` and `icons/icon-512.png` (purpose `any`) are the favicon itself. `icons/icon-maskable-512.png` (purpose `maskable`) is the mark on a full-bleed `#1d2733` square, the bars at 60% of its height so they sit inside the central 80% safe zone. `apple-touch-icon.png` (180x180) is the same full-bleed design, written as an opaque RGB PNG: iOS rounds the corners itself and shows transparent pixels as black. All of them are rendered from `apps/web/public/favicon.svg`, and only the PNGs are committed. To make them again, from the repository root:

```sh
mkdir -p /tmp/pwa/run && cd /tmp/pwa/run && npm init -y >/dev/null && npm i @resvg/resvg-js@2
# save the script below as /tmp/pwa/run/render.mjs, then from the repository root:
cd <repository root> && node /tmp/pwa/run/render.mjs
```

```js
// render.mjs: renders the home-screen icons from apps/web/public/favicon.svg. Run from the repository root.
import { readFileSync, writeFileSync, mkdirSync } from 'node:fs';
import { deflateSync } from 'node:zlib';
import { Resvg } from '@resvg/resvg-js';

const out = 'apps/web/public';
const favicon = readFileSync(`${out}/favicon.svg`, 'utf8');
// The three bars of the mark, without the rounded square.
const bars = favicon.match(/<rect x="8"[\s\S]*<\/svg>/)[0].replace('</svg>', '');
// A full-bleed #1d2733 square with the bars scaled to 60% of its height (the bars are 14x17 units),
// inside the central 80% that a maskable icon keeps clear.
const full = (size) => {
  const scale = (size * 0.6) / 17;
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${size} ${size}"><rect width="${size}" height="${size}" fill="#1d2733"/><g transform="translate(${size / 2} ${size / 2}) scale(${scale}) translate(-15 -14.5)">${bars}</g></svg>`;
};
const render = (svg, size) => new Resvg(svg, { fitTo: { mode: 'width', value: size } }).render();

mkdirSync(`${out}/icons`, { recursive: true });
writeFileSync(`${out}/icons/icon-192.png`, render(favicon, 192).asPng());
writeFileSync(`${out}/icons/icon-512.png`, render(favicon, 512).asPng());
writeFileSync(`${out}/icons/icon-maskable-512.png`, render(full(512), 512).asPng());

// apple-touch-icon.png is opaque: iOS shows transparent pixels as black, so it is written as RGB.
const crcTable = Array.from({ length: 256 }, (_, n) => {
  let c = n;
  for (let k = 0; k < 8; k++) c = c & 1 ? 0xedb88320 ^ (c >>> 1) : c >>> 1;
  return c >>> 0;
});
const crc = (buf) => {
  let c = 0xffffffff;
  for (const b of buf) c = crcTable[(c ^ b) & 0xff] ^ (c >>> 8);
  return (c ^ 0xffffffff) >>> 0;
};
const chunk = (type, data) => {
  const len = Buffer.alloc(4);
  len.writeUInt32BE(data.length);
  const body = Buffer.concat([Buffer.from(type), data]);
  const sum = Buffer.alloc(4);
  sum.writeUInt32BE(crc(body));
  return Buffer.concat([len, body, sum]);
};
const { width, height, pixels } = render(full(180), 180);
const raw = Buffer.alloc((width * 3 + 1) * height);
for (let y = 0; y < height; y++) {
  for (let x = 0; x < width; x++) {
    const s = (y * width + x) * 4;
    const d = y * (width * 3 + 1) + 1 + x * 3;
    raw[d] = pixels[s];
    raw[d + 1] = pixels[s + 1];
    raw[d + 2] = pixels[s + 2];
  }
}
const ihdr = Buffer.alloc(13);
ihdr.writeUInt32BE(width, 0);
ihdr.writeUInt32BE(height, 4);
ihdr[8] = 8; // bit depth
ihdr[9] = 2; // colour type RGB
const signature = Buffer.from([137, 80, 78, 71, 13, 10, 26, 10]);
writeFileSync(
  `${out}/apple-touch-icon.png`,
  Buffer.concat([signature, chunk('IHDR', ihdr), chunk('IDAT', deflateSync(raw)), chunk('IEND', Buffer.alloc(0))]),
);
```

**iOS.** `index.html` carries `apple-mobile-web-app-capable` and `mobile-web-app-capable` (yes), `apple-mobile-web-app-status-bar-style` (black-translucent) and `apple-mobile-web-app-title` (Goal), and the `apple-touch-icon` link. `viewport-fit=cover` lets the page draw under the status bar and the home indicator.

**Service worker.** `apps/web/src/sw/sw.ts` is written by hand (no Workbox, no plugin: no new dependency). `vite build` emits it as `/sw.js` at the root of `dist/`, a self-contained classic script that shares no chunk with the app and imports nothing (a nested build in `apps/web/vite.config.ts`). goald serves it at scope `/` with `Cache-Control: no-cache`, like the other unhashed root files, and the CSP's `worker-src 'self'` allows it. `apps/web/src/pwa/register.ts` registers it from `main.tsx` in production builds only: never under `vite dev`, and never in a `GOAL_API=mock` dev server.

The worker's routing is one pure function, `routeRequest` in `apps/web/src/sw/routes.ts`, tested in `routes.test.ts`. A bypass returns before `respondWith`, so the browser goes to the network as if there were no worker:

| Request | Route | What the worker does |
| --- | --- | --- |
| any non-GET; any cross-origin request | `bypass` | nothing |
| `/v1/*`, `/api/*` (the identity service's `/api/auth/*`, OAuth callbacks included), `/mcp/*`, any navigation to them | `bypass` | nothing: never cached, never answered with the shell |
| `/sw.js`, `/manifest.webmanifest` | `bypass` | nothing |
| a same-origin navigation to any other path (`/`, `/o/acme/f/sre/board`, `/device`, `/sign-in`, `/invite/…`) | `network-first-shell` | fetches it; only when the fetch rejects (offline) answers the cached shell (`/`) |
| `/assets/*` (content-hashed, immutable) | `cache-first` | answers from the cache, fetches and caches on a miss |
| `/favicon.svg`, `/theme.js`, `/icons/*`, `/apple-touch-icon.png` | `stale-while-revalidate` | answers from the cache and refreshes it behind the answer |
| any other same-origin GET | `bypass` | nothing |

Only responses that are `ok` and of type `basic` (same origin, not opaque or redirected) are cached.

**Why the API and auth are never cached.** `/v1` answers are the signed-in user's private data, and `/api/auth/*` is the sign-in, the session and the OAuth callbacks (`/api/auth/callback/google` is a top-level navigation that sets a cookie). A cached answer would show one person's data to the next, and a shell answered for `/api/auth/*` would break the sign-in redirect and the device-code page. So the worker never reads or writes those paths, and offline use of API data does not exist: the app opens offline, and its data needs the network.

**Cache versioning.** The cache is `goal-shell-<build id>`. The build id is a 16-hex-digit hash of every file the build writes (the assets carry their own content hashes, so a change to any file changes it), injected into the worker as `__BUILD_ID__`. `install` precaches `/` (the shell, fetched with `cache: 'reload'`) and does not call `skipWaiting`, so a new build waits. `activate` deletes every other `goal-shell-*` cache, then calls `clients.claim()`. The old build's cache stays until the new worker activates, so an open page keeps running on the build it loaded.

**Update prompt.** On load and on every `visibilitychange` to visible, the page calls `registration.update()`, which is how a phone that keeps the app open finds a new build. When a new worker is waiting (or has just finished installing under a controlling worker), a sonner toast says "A new version of Goal is ready" with a **Reload** action, through the app's `Toaster` in `__root.tsx`. Reload posts `{type: 'SKIP_WAITING'}` to the waiting worker; the worker activates, claims the page, and the page reloads once on `controllerchange`. The first worker a page gets (a first visit) is not an update and reloads nothing.

**Checking it by hand.** Build A, serve it (goald or `pnpm --dir apps/web preview`), open the app in Chrome, and install or add it to the home screen. Build B, deploy it, then open the app again: it shows the toast; tap Reload; the page reloads and runs build B (its `goal-shell-` cache name changes in DevTools › Application › Cache storage).

**Safe areas.** With `black-translucent` the page is drawn under the status bar, so the phone's top bar pads its top by `env(safe-area-inset-top)`, the drawer pads its top by that inset on top of its 8 px (`pt-[calc(8px_+_env(safe-area-inset-top))]`), and the shell pads its left and right by `env(safe-area-inset-left)` and `env(safe-area-inset-right)` for landscape. The bottom tab bar, the wizard footer and the drawer pad their bottoms by `env(safe-area-inset-bottom)`. In a browser tab every inset is 0, so nothing moves there. Use `calc()` with spaces around `+` (`calc(8px_+_env(...))`): without them the declaration is invalid CSS and is dropped.

The manifest and icons are checked by `apps/web/src/pwa/manifest.test.ts`, which reads the PNG sizes from their headers, and `apps/web/webui_test.go` checks the manifest's content type.

## Hosting

| Target | How |
| --- | --- |
| Laptop | `apps/web/dist` is embedded into `goald` with `go:embed`; one binary serves UI and API |
| AWS | `goald` serves it, or S3 + CloudFront with `/v1/*` routed to the ALB |
| Vercel | Static deploy of `apps/web/`, same-origin: rewrites send `/v1/*` and `/api/auth/*` to goald on AWS (phase 3, ADR 0007; no cross-site deployment); preview deployments per pull request run on the mock API and never sign in |

The UI holds no secrets. With sign-in on it signs in through goald's `/api/auth` (Better Auth, an httpOnly session cookie); on a laptop with `GOAL_AUTH=none` goald runs in single-user mode.

## Quality gates

- Biome for lint and format; `tsc --noEmit` for types; dependency-cruiser for boundaries (with `packages/`).
- The Biome config and the tsconfig bases come from `packages/config` (`@goal/config`). Each project's `biome.json` and `tsconfig.json` extends one of them and keeps only its own settings: `web`, `auth`, `worker`, `cloudflare` and `api-client` each extend the variant that matches their runtime. `api-client` has no Biome config, so it extends only the tsconfig base.
- Vitest for logic with real behavior (the trace built from events, which decisions an item allows); Testing Library for components when they carry such logic. No snapshot tests of markup.
- Playwright for the critical flows at 375, 768 and 1440 px, with axe accessibility checks.
- Budgets: initial JS under 250 KB gzipped; routes are code-split. Views loaded on first use go through `lazyRetrying` (`apps/web/src/shared/lazy.ts`), not bare `React.lazy`, which keeps a chunk that failed to arrive failed until the page reloads.

## Phone shell

Below 768 px (`phone-chrome.tsx`, MASTER.md "Phones", `screens/mobile/drawer.jpg`), `ShellFrame` draws three things and holds the state they share:

- **The top bar** (`PhoneTopBar`), sticky, 56 px plus `env(safe-area-inset-top)`. On its left a 44 px button with the Goal mark, named "Open menu" (`aria-haspopup="dialog"`, `aria-expanded`). It opens the drawer. Next to it the page's title: the page's last crumb from `TopBarSlot`, else the page's name from `usePageLabel` (the same registry as the desktop bar). On its right the page's actions. There are no factory squares and no crumb.
- **The tab bar** (`PhoneTabBar`), fixed at the bottom on organization pages (not on the New factory wizard, `ShellFrame tabs={false}`), named "Tabs": Needs you, Floor, Board, Items, More. Each target is `min-h-16` (64 px), and the bar pads its bottom by the safe-area inset. `main` leaves room for it (`pb-28`). Needs you is a disabled button with the tooltip "Not available yet" and `aria-disabled` (ADR 0016, decision 4); it is a button, not a span, so a keyboard user reaches the tooltip. Floor, Board and Items go to the open factory, or outside a factory to the last factory visited in this organization (`rememberFactory` and `lastFactory` in `shared/org.ts`, kept per organization id in localStorage, set by the factory route), else the first factory, else the Factories home. The current tab carries `aria-current="page"` from TanStack's Link. More opens the drawer.
- **The drawer** (`PhoneDrawer`), a Radix Dialog from the left, 320 px, labelled by the organization's name. It renders `SidebarContent` (`sidebar.tsx`): the same entries as the 256 px sidebar, with Close in place of Collapse. Focus is trapped while it is open. Escape, Close and the Goal mark return focus to the Goal mark, but a navigation (a link, or a switch of organization) closes it and leaves focus where the new page puts it. Any change of page closes it (`PageWatch`).

`usePhone()` decides which chrome renders, from `matchMedia('(max-width: 767px)')`; without `matchMedia` (jsdom) it is the desktop chrome. Only one top bar and one set of actions is in the DOM at a time. The sidebar and its content stay in the DOM from 768 px, so the drawer's list is a second copy only while it is open.

The phone's tests: `app/phone-chrome.test.tsx` (the title and actions, the drawer's focus and links, the tab targets and the fallbacks), `shared/org.test.ts` (`lastFactory`), and `e2e/phone-shell.spec.ts` plus the phone cases in `flows.spec.ts`, `knowledge.spec.ts` and `definition.spec.ts`.
