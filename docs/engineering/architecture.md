# Architecture

Goal is one Go daemon (`goald`), one PostgreSQL database, one versioned object storage bucket for factory definitions, short-lived agent containers and a static React UI. As built it runs on a laptop; phase 4 (planned, [ADR 0008](../adr/0008-portable-runs-connections-and-knowledge.md)) makes the same code run on local Docker Compose and on Cloudflare, which replaces the AWS and Vercel targets that were designed and never built. Decisions: [ADR 0001](../adr/0001-technology-stack.md) (stack), [ADR 0003](../adr/0003-hexagonal-architecture-and-deployment.md) (architecture and deployment), [ADR 0005](../adr/0005-factory-definitions-in-object-storage.md) (factory definitions in object storage).

## Hexagonal core

```
              ┌──────────────────────── goald ────────────────────────┐
  HTTP/SSE ──▶│ adapters/http ──▶  engine  ◀── domain                  │
  (UI, CLI)   │                      │                                 │
              │                    ports: Store  Sandboxes  Secrets    │
              │                           ObjectStore  Clock  CodeHost  │

              │ adapters: postgres  docker  envsecrets  github          │
              │           s3store (RustFS)  gateway                     │

  and Reaper, and replaces Sidecars in 4-11; new Connections, MasterKey; planned Minter, Knowledge,
  Embedder, SourceReader; s3store also on R2
```

### Ports

| Port | Purpose | Adapters |
| --- | --- | --- |
| `Store` | Items, events, leases, factories, runs; transactions | `postgres` |
| `FlowStats` | The read model of flow: an item's spans at stations (`item_spans`), its run in progress; the statistics phase 2.2-E derives from spans | `postgres` (the same `Store` type) |
| `Sandboxes` | One container per agent run, the run's dev box: create it for a run, exec a command in it (output streamed, exit code from the runtime), delete it; list every box, with its run and organization, for reaping (spec 4 §5.1) | `docker` (on the agents' network); `cloudflare` planned (4-21) |
| `Secrets` | Resolve `env:` references at the edge | `envsecrets`; platform settings only from phase 4, when organization credentials move into connections (planned) |
| `ObjectStore` | Objects in one bucket without versions (`Get`, `Put`, `PutIfAbsent`, `List`, `Delete`, `DeletePrefix`; `ObjectInfo` carries an ETag): factory definitions as immutable content-addressed blobs and the catalogs; phase 4 (planned) adds knowledge uploads | `s3store` (RustFS on a laptop; R2 on Cloudflare, planned) |
| `Connections` | An organization's connections and the connection kinds it sees (the platform's, synced at goald's start, and its own); secret values write-only, sealed with `MasterKey` under associated data binding organization, connection and key id; every change, test and use audited in its transaction, and each change and test the organization's stream event `connection` (spec 4 §5.3, §8.3); `Open` hands a connection's test its values without recording a use | `postgres` (00051, 00053) |
| `MasterKey` | Seal and open small secrets with the platform's master key (AES-256-GCM, a key id for rotation) | `masterkey` (`GOAL_MASTER_KEYS` or `GOAL_MASTER_KEY_FILE`) |
| `Knowledge` | An organization's knowledge sources, documents and chunks (4-16, 00054): sources reading connections, sync leases, documents replaced with their chunks, uploads, and one hybrid search over an explicit list of sources; every change people make audited in its transaction | `postgres` (pgvector `halfvec(1024)` with HNSW, a `simple` `tsvector`) |
| `Embedder` | Texts to embeddings of 1024 dimensions, one model per install | `openaiembed` (`GOAL_EMBED_URL`, `GOAL_EMBED_MODEL`, `GOAL_EMBED_KEY`; none: keyword search only) |
| `SourceReader` | A source's documents with versions, and one document's content | `knowledge.Uploads` (the bucket); planned: `gitdocs` (4-18), `confluence` (4-19) |
| `Clock` | Time, for deterministic tests | `sysclock`, fake |
| `Sidecars` | A run's stdio MCP servers, each in its own hardened container, used by the gateway | `docker`; removed in 4-11: stdio servers run inside the run's box |
| `Contracts` | Station outputs against the factory's JSON Schema contracts | `definitions` (over the bucket) |
| `ItemNotices` | A notice of every committed item event, for the realtime stream | `postgres` (`LISTEN goal_events`) |
| `Tenancy` | The install's organizations: list, resolve by slug or id, create, update, soft delete, purge; each change audited in its transaction | `postgres` (cross-org reads through `SECURITY DEFINER` functions) |
| `Audit` | An organization's append-only audit log | `postgres` |
| `DefinitionStore` | Factory definitions: content-addressed blobs, drafts and published versions (manifests), the current-version pointer; publish and restore in one transaction, each change audited | `postgres` over `ObjectStore` (blobs at `orgs/<org-id>/blobs/<sha256>`) |
| `DefinitionNotices` | A notice of every committed definition change, so every goald reloads and editors refresh | `postgres` (`LISTEN goal_definitions`) |
| `CodeHost` | Read, merge and clean up pull requests (GitLab merge requests), from goald, with a connection's credential | `github` (REST API), `gitlab` (REST v4), chosen by the connection's kind (`codeHost`; 4-13) |
| `SkillSource` | The skills.sh directory (`Search`) and a skill's folder at one commit (`Fetch`), for the operator's `goal catalog skills sync` only; goald never fetches third-party content | `skillssh` (skills.sh API + GitHub REST API) |

#### Phase 1 signatures

`internal/ports/ports.go` is the source of truth; this is the shape adapters implement.

- `Store`: `CreateItem`, `Item`, `Waiting` (pull order), `Leases`, `ClaimNext(Claim{Station, Slot, Now, ExpiresAt})`, `HeartbeatLease`, `RequeueExpiredLeases`, `FinishLostRuns`, `RunsOver(runs)` (those of the given runs that neither run nor hold their lease any more, for the reaper below; ids the organization has no run for are never over), `StartRun`, `FinishRun`, `Transition` (compare-and-set on station and state, fenced by the lease's `AcquiredAt`; releasing a lease records it in `lease_spans` with the transition's `Outcome`, which it requires; `TakeLease` instead removes the item's lease whatever its `AcquiredAt`, for a person's move, pause or send-back of an item in progress (E10); an optional `Audit` entry is written in the same transaction), `AppendEvents`, `ItemEvents(item, after, limit)` (paged history for the API). WIP is not counted: the unique `(factory_id, station, slot)` lease makes a claim beyond capacity fail with `ErrSlotTaken`. Phase 2 adds the reads behind the board and metrics: `ItemByNumber(factory, n)`, `ListItems(ItemQuery{States, Station, Before, Limit})` (newest first, paged by number), `StationLoads(factory)` (waiting, in progress and waiting for a person per station, counted from `work_items`; the board's `in_progress` of a station is the last two, `StationLoad.Busy`, so a human station holding a decision is not empty; the `station_wip` view is no longer read); 2.2-E moved its `FlowMetrics` to `FlowStats`. 2.2-D adds `SpendSince(factory, since)` for the weekly budget. 2.2-E adds the andon cord: `PullAndon(pull, by)` (the puller is `by.Ref()`; `ErrConflict` while the factory has an open pull, `ErrNotFound` for a factory the organization does not have), `ClearAndon(factory, by, note, at)` (`ErrNotFound` when none is open), `OpenAndon(factory)` (nil while the line runs) and `AndonPulls(factory, limit)` (newest first); a pull or a clear writes its audit entry (`andon.pulled`, `andon.cleared`) in its transaction. `andon_pulls` (migration 00032 adds `kind`, `station`, `cleared_by`, `note`, `data`) keeps every pull; `andon_pulls_open_key` allows one open pull per factory.
- `FlowStats` (2.2-E): `ItemSpans(item)` (in the order entered, the open one last) and `CurrentRun(item)` (the running run under the item's lease, its slot and the `usage` events it reported, or nil), `LiveTurns(factory)` (the same turn count for every item running under a live lease, by item) and `StationTimes(factory, since, until)` (per station: lease time held in the window, clipped to it, from lease spans and live leases, and their count; the items waiting at `until` and 24 h before, and since when the oldest of them waits; the gate verdicts and rejections in the window; the time items waited there in the window, clipped to it, and how many items did; plus the earliest lease of the factory, where busy shares begin to mean anything); and over a `FlowQuery{FactoryID, Since, Until, Type}` (`Type` "" for every work type), `FlowMetrics(q, longWaitsAt)` (done per UTC day, lead-time p50/p85 by linear interpolation, reworked, WIP now, spend of runs started in the window, and the items whose span waiting at `longWaitsAt` overlaps the window and lasted over `domain.LongWait`, 24 h) and `DoneByBucket(q, d, n)` (items done in `n` buckets of length `d` ending at `Until`, oldest first), and `ItemTimes(q)` (every item done in the window with its lead time and its closed spans' time by bridge component, `domain.ComponentOf`: waiting at a station, rework by the station that sent it back, waiting on a person, blocked, working; `domain.BridgeLeadTime` turns them into the lead-time bridge). Spans are kept by the `work_items` trigger of migration 00030 (`track_item_span`): a change of station, state or rework count closes the open span at `updated_at` (never before it opened) and opens the next, none once done or cancelled; a new rework round records the station the item left as `rework_by`. 00030 backfilled the spans of older items from their events. Every lease the store deletes is a `lease_spans` row (migration 00031, append-only): station, agent, slot, the item's rework round, acquired and ended, and its `domain.LeaseOutcome` (`advanced`, `rejected`, `escalated`, `blocked`, `released`, `expired`, `taken`; `Finished()` for the first three). The engine gives every transition that releases a lease its outcome (finish: advanced, rejected or escalated; block: blocked; shutdown and the weekly budget's stop: released); the sweep records `expired`. `porttest.Store` keeps the same spans in memory, and `storetest` checks both agree. `GateDecisions(factory, station, after, n)` tallies a gate station's last `n` verdicts (`gate_approved`/`gate_rejected`, on `item_events_verdicts_idx`) that came after `after` (the last andon clear): verdicts, rejections and the most frequent category or normalized reason (`domain.TallyGate`). `InboxItems(factories, limit)` (E11, replacing C2's `Store.WaitingHuman`) returns the open items that may need a person, waiting for a decision, blocked (with the reason of the latest `blocked` or `paused` event) or in the expedite lane, the most recently changed first, on `work_items_attention_idx` (migration 00033). `AgentStats(factory, agent, since, until)` (E12): the agent's finished lease spans that ended in the window (count, advanced, p85 duration), the advanced ones whose item then entered its next rework round from another station (labelled by that rejection's `category`, else its trimmed lower-cased reason, else a person's manual move back, `domain.VerdictLabel`), and its runs started in the window (spend, median turns of the succeeded, and their denied tool calls: `tool_denied` events and gateway calls with outcome `denied`). Human touches (4-23, spec 4 §4.9): a touch is one person's events on an item at one instant (`data.actor` `user:…`; never `created` or `lease_taken`, never API keys, agents or the engine), named by its most specific event and planned when it is a decision the line requires (`data.planned`, which approvals, rejections and merges carry, else an approval, gate approval or merge); `domain.TouchesOf` is the rule, the `item_touches` view of migration 00052 the same rule in SQL on `item_events_person_idx`. `ItemTouches(item)`, `TouchCounts(items)` (the cards'), and over a `FlowQuery` (whose `VersionID` keeps the items whose last run ran on it) `Touches(q)`, `OrgTouches(factories, q)` and `TouchesByBucket(q, d, n)`: the items finished in the window with their touches, tallied by `domain.TallyTouches` (per item mean and median, touchless share, planned and unplanned, by station, kind, reason and version) with the andon pulls people made (line stops). Each person event gets an `item_touch_labels` row from a trigger (`required_gate` when planned); `Store.LabelTouch(event, reason, by)` sets a touch's reason (audited `touch.labelled`, never an item event).
- `ItemNotices`: `Listen(ctx, deliver)` calls `deliver` for every committed item event (`ItemNotice{EventID, OrgID, FactoryID, ItemID, Number, Kind, Station, State, At}`, the state being the item's right after the event) until `ctx` ends. Every time it starts listening, the first time and after each reconnection, it first delivers a `Resync` notice, because events committed while it was disconnected are lost. The `postgres` adapter listens on a connection of its own (not a pooled one) and reconnects with backoff (100 ms doubling to 10 s); the `item_events` trigger (migration 00003) puts the item's number and state in the payload.
- `DefinitionStore` (2.2-B): factories (`CreateFactory`, `FactoryRecord(s)`, `DeleteUnpublished`, `SetPaused`), blobs (`PutBlobs`, `Blob` verified against its hash, `BlobSizes`), versions (`Version`, `VersionByNumber`, `Draft`, `Versions(factory, before, limit)`, `CurrentVersions`), the draft cycle (`OpenDraft`, `SaveDraft` compare-and-set on the revision, `DiscardDraft`, `Publish` guarded by the draft revision and the expected current version, `Restore` as a pointer move). Publish and restore move the open items of removed stations (`StationMoves`) or refuse with `*ItemsAtRemovedStationError`. Errors: `ErrNotFound`, `ErrConflict`, `ErrBaseMoved`, `ErrNameTaken`, `ErrUnknownBlob`, `ErrBlobCorrupt`. `DefinitionNotices.Listen` works like `ItemNotices` (`Resync` first) with `DefinitionNotice{OrgID, FactoryID, Kind: factory|draft|current|org, VersionID, Number, Revision, By}`. `porttest.Definitions` is the fake and `porttest/definitionstest` the conformance suite.
- `CodeHost` (4-13, spec 4 §5.5): `PullRequest(conn, url)`, `Merge(conn, url, Merge{Method, HeadSHA})` and `DeleteBranch(conn, url, branch)`, with `conn` a `domain.ResolvedConnection` whose rendered git login (`ResolvedConnection.GitLogin`) gives the host it serves and the token. The repository is the URL's own; a URL on another host than the login's is refused (`ErrNotMergeable`) before anything is sent, and so are the host's refusals. Both adapters send the token only to that host's API, follow no redirects and scrub it from every error. `github`: `https://api.github.com` for github.com, `https://api.<host>` for `*.ghe.com`, else `https://<host>/api/v3` (GitHub Enterprise Server); `github.Config.APIURL` overrides it (goald passes `GOAL_GITHUB_API_URL` until 4-14). `gitlab`: `https://<host>/api/v4`, merge requests `https://<host>/<namespace>/<project>/-/merge_requests/<iid>` (nested groups; the project id is the URL-encoded path), the `PRIVATE-TOKEN` header, `detailed_merge_status` `mergeable` (or, before GitLab 15.6, `merge_status` `can_be_merged`), squash with `squash: true`, merge with the project's own merge method; rebase is refused.
- `Sandboxes`: `Create(ctx, SandboxSpec{Org, Factory, Item, Run, Station, Agent, Image, Size, Env, Deadline}) (Sandbox, error)` (a second call for the run returns the same box; `Env` holds settings, never credentials), `List(ctx) ([]Leftover{Run, Org}, error)` and `Delete(ctx, run)` (idempotent; it ends the box's commands). `Sandbox.Exec(ctx, Exec{Argv, Env, Dir, Timeout}) (Process, error)`: the caller drains `Stdout()`, then `Wait()` returns the `ExitStatus{Code, TimedOut, StderrTail}` the runtime saw; cancelling `ctx` kills the command. `Env` is per exec, so each command gets only the credentials it needs. `porttest.Sandboxes` is the fake and `porttest/sandboxtest` the conformance suite; `porttest.Worker` plays the agent image on the fake for engine tests. The `docker` adapter labels every container with its run and organization (`goal.run`, `goal.org`); `SidecarSpec.OrgID` is labelled the same way, so `Delete` removes a run's sidecars too. `worker/README.md` ("Sandbox contract") is the contract from the box's side.
- `Secrets`: `Resolve(ctx, ref)` for literals and `env:NAME`. `Contracts`: `Validate(ctx, factory, contract, output)`, wrapping `ErrContractViolation` for bad output.
- **Repository host binding** (until runs get connections, 4-11): a definition chooses `runtime.repository.url`, but its token (`env:GOAL_GITHUB_TOKEN`) is the install's, so the token may go to the install's GitHub only. The engine hands it to the box's `goal-agent prepare` (as `GOAL_REPOSITORY_TOKEN`, read by git's credential helper for the URL's host) only for an https URL on one of `engine.Config.RepositoryHosts` (goald: the host of `GOAL_GITHUB_WEB_URL`, an origin, default `https://github.com`; host and port matched exactly, without case) whose reference `SecretPolicy` does not reserve; otherwise the run fails before any box. This is the protection that holds for versions already published; the credentials check (`repository-host-not-allowed`, 2.2-B §4.7) refuses such a definition earlier. The agent's own exec never gets the token. [ADR 0006](../adr/0006-workspaces-and-command-checks.md)'s fresh clone per run and branch per item still hold, inside the box.
- `Sidecars`: `Start(ctx, SidecarSpec{Run, Connection, Image, Command, Env, Network}) (Sidecar, error)`; a `Sidecar` is an `io.ReadWriteCloser` over the server's stdout and stdin, and `Close` removes its container. `Env` carries resolved values that adapters never log. The `docker` adapter's sidecars carry the run's labels plus `goal.connection`, so `Sandboxes.Delete` removes them with their run.
- `Clock`: `Now()` and `NewTicker(d)`.
- `ObjectStore` (no object versions, phase 4 PR 4-3): `Get(ctx, key)` (`ErrNotFound` for a missing key), `Put(ctx, key, body) (ObjectInfo, error)` (replaces the object), `PutIfAbsent(ctx, key, body) (ObjectInfo, created bool, error)` (writes only when no object is at key), `List(ctx, prefix) ([]ObjectInfo, error)` (by key), `Delete(ctx, key)` (gone for good) and `DeletePrefix(ctx, prefix)` (every object under a non-empty prefix; the organization purge's). `ObjectInfo` is `{Key, ETag, Size}`; `Object` adds `Body`. `porttest.ObjectStore` is the in-memory bucket (ETags from the content, `Writes(key)` for write-once checks).
- Per-task MCP gateway tokens are HMAC-signed (`domain.SignTaskToken`), so any instance can verify them without stored state. Their audience is `goal-gateway` (`aud`, `domain.TaskAudience`): `VerifyTaskToken` refuses a token without it (tokens from before it belonged to runs released at the restart), and the API refuses any task token (below).
- `internal/adapters/postgres` implements `Store` with pgx and sqlc (`queries/` compiled against `migrations/` into the private package `postgres/db`; `task sqlc` regenerates it). Wiring: `postgres.Open(ctx, url)` returns a `*pgxpool.Pool`, `postgres.Migrate(ctx, pool)` applies the embedded goose migrations under a per-schema advisory lock (safe when several instances start at once), `postgres.CheckAppRole(ctx, pool)` refuses a runtime role that row-level security would not bind, `postgres.New(pool)` returns the store, and `postgres.NewDefinitions(pool, objects, log)` the definition store (factory rows, versions, blobs); items and runs reference their factory row, and a run its definition version (`agent_runs.definition_version_id`). Every method is one transaction; locks are taken item first, then its lease or runs. `porttest/storetest` is the conformance suite both the fake and the adapter pass.
- **Organizations.** Every org-owned table (`factories`, `work_items`, `leases`, `agent_runs`, `item_events`, `andon_pulls`, `audit_log`) carries `org_id` (default `goal_org()`), composite foreign keys to its parents in the same organization, and the `org_isolation` policy; `station_wip` runs with the caller's rights. Events are appended with one batched `INSERT` per event, because `COPY` is refused under row-level security. Org-owned rows are bound to the organization of their transaction by row-level security: `domain.WithOrg(ctx, id)` puts the org in the context, the adapter runs `set_config('goal.org_id', id, true)` first in each such transaction, and the policies compare with `goal_org()`, which fails when it is unset. `Tenancy`'s cross-org reads (`goal_orgs`, `goal_org_by_ref`, `goal_active_orgs`, the purge) are `SECURITY DEFINER` functions pinned to the schema that return organization rows and ids only. `postgres.DefaultOrgID` is the organization rows from before organizations moved into. `porttest/tenancytest` is the conformance suite of `Tenancy` and `Audit`.
- **Database roles.** goald never connects as the bootstrap superuser. `goal_owner` owns the schema and applies migrations (`GOAL_MIGRATE_DATABASE_URL`, on a pool closed before goald serves); `goal_app` runs everything else (`GOAL_DATABASE_URL`) and owns nothing, so row-level security binds it, and `CheckAppRole` refuses a superuser, a `BYPASSRLS` role, a member of `goal_owner` or a table owner at startup. `goal_auth` runs the identity service (`auth/`, `GOAL_AUTH_DATABASE_URL`): `SELECT, INSERT, UPDATE, DELETE` on Better Auth's tables in schema `auth` and no table in `public`; the service refuses a superuser, a `BYPASSRLS` role, a table owner or a member of `goal_owner` or `goal_app` at startup. `internal/adapters/postgres/roles.sql` creates the three roles (idempotent, no `LOGIN`); `goal db init` (`postgres.InitRoles`, run by `goal up` every time, as the admin `GOAL_DATABASE_ADMIN_URL`, default compose's `goal` superuser) gives them `LOGIN` and the passwords `GOAL_PG_OWNER_PASSWORD`/`GOAL_PG_APP_PASSWORD`/`GOAL_PG_AUTH_PASSWORD` (dev-only defaults), grants the database and schema, and hands every object the bootstrap user owns to `goal_owner`, so a database from before the roles upgrades in place. goald applies the migrations at its start; `goal db migrate` (run by `goal up` after `goal db init`, before the auth service, whose tables they create) applies them the same way, as `goal_owner` with `postgres.Migrate`, so goald then finds nothing left. Migrations grant to `goal_app` and `goal_auth`, so `postgres.Migrate` applies nothing while either is missing ("role goal_auth is missing: run goal db init (goal up runs it)"). There are no default privileges: each migration grants `goal_app` what it needs on the objects it adds (`00004_app_role.sql` for those of `00001–00003`). Integration tests connect as compose's superuser and switch roles with the `role` startup parameter, so they never touch the roles' passwords.
- Model credentials reach tasks through `engine.Config.TaskEnv` secret references. Phase 4 (planned) replaces them with connections and drops the `ModelAuth` port that was planned here (below).

### MCP gateway

`internal/gateway` is an inbound HTTP component of `goald`, not an adapter: it reads factory definitions (`config.Factory`), which adapters may not. `gateway.New(Deps, Config)` returns an `http.Handler` that `goald` mounts at its MCP path. Its package comment is the reference; in short:

- **Auth.** Every request carries `Authorization: Bearer <task token>`; a missing, forged or expired token, or one without `aud: goal-gateway`, is 401, an agent the current definition no longer declares is 403, both without detail.
- **Listener.** Without `GOAL_GATEWAY_LISTEN` the gateway is `/mcp` on goald's one listener. With it, goald opens a second listener there that serves only `/mcp` (everything else 404), the main listener answers `/mcp` with 404, and `GOAL_GATEWAY_URL` defaults to `http://<GOAL_GATEWAY_LISTEN>/mcp` (a wildcard host becomes `127.0.0.1`), the only goald address agent tasks are given; goald refuses a `GOAL_GATEWAY_URL` that names the main listener then. The gateway listener may be off loopback (every request needs a task token) and is required off loopback once `GOAL_LISTEN` may be (phase 3, PR 3-9). Agents never reach that address themselves: they run on a network with no route to the host and reach the gateway through the egress proxy (below, [ADR 0009](../adr/0009-agent-network-isolation.md)), which serves exactly the gateway's path and forwards it to `GOAL_GATEWAY_URL`, a loopback one rewritten to `host.docker.internal`, which only the proxy resolves. Which setting a laptop needs depends on how the proxy reaches the host:
  - *Docker Desktop and OrbStack* forward `host.docker.internal` to the host's loopback, so the default single listener works. `goal up` sets no `GOAL_GATEWAY_LISTEN` (a fixed second port could only collide).
  - *Docker Engine on Linux* resolves `host.docker.internal` (the `host-gateway` extra host) to the bridge address, which a loopback listener does not serve, so runs reach no gateway on the defaults. Set `GOAL_GATEWAY_LISTEN` to the bridge address (`172.17.0.1:8090`, `ip -4 addr show docker0`) and keep `GOAL_LISTEN` on loopback.
- **Stateless towards agents.** The SDK's stateless streamable-HTTP mode: each request is verified and served on its own and opens short sessions with remote servers. The one exception is the registry of running sidecars (below), keyed by run: it lives in the `goald` that started them, so a run's MCP traffic must reach that instance. Phase 2 runs one `goald`, so it always does; running several needs requests routed by run id (it is in the token) or sidecars that any instance can reach; phase 4 (planned) runs stdio servers inside the run's box instead, which removes this state. A dead `goald`'s sidecars are orphans the reaper removes once their run's lease is swept.
- **Connections.** A task gets the connections in both its token and its agent's `connections`. Remote MCP servers (`type: mcp`, `transport: http`, https or loopback http) are served, with header values like `Bearer env:NAME` resolved through `Secrets` on the host. Stdio servers with an `image` are served as sidecars. Builtin (`knowledge`), `aws` connections and stdio commands without an image (they would run on the host) are reported unavailable (initialize instructions, the `goal/connections` `_meta` of `tools/list`, a logged warning) until their phase.
- **Sidecars.** A stdio connection's server runs in its own container per run (`ports.Sidecars`), started lazily by the run's first `tools/list` or `tools/call` that needs it, reused through one MCP session over its stdio for the rest of the run, and stopped when the engine reports the run ended (`engine.Deps.RunEnded` → `Gateway.EndRun`), after `SidecarIdle` (10 minutes) without requests, when its server exits, and at shutdown (`Gateway.Close`). `MaxSidecars` (16) caps one `goald`; past it, and when a sidecar fails to start, the connection is unavailable for that request only. The `env` values and `command` words that are secret references are resolved on the host and reach only the sidecar's environment and arguments, never the agent's container, and are scrubbed from results, errors, logs and events like header credentials. The image must be pinned (a version tag or a digest; `config.Pinned`): `goal factory validate` and `push` warn about an unpinned one, and the gateway reports it unavailable instead of starting it. The Docker adapter gives a sidecar the hardening of an agent task (read-only root with tmpfs `/tmp` as `HOME`, no capabilities, no new privileges, init, 1 CPU, 2 GiB, 512 PIDs), runs it as its image's user unless that is root (then as nobody), mounts nothing, and gives it no network unless the connection sets `network: true` (then the egress tools' network: public hosts through the egress proxy, never the host or a private address). The first start pulls the image within `SidecarStartTimeout` (5 minutes) and outlives the request that began it; pull large images ahead of a run, since the worker lists tools once at start.
- **Secret policy (host binding at run time).** A published version keeps its connections, so validation alone does not protect versions published before a rule existed. goald builds one `domain.SecretPolicy` from its settings (`settings.secretPolicy`: the reserved variables, and `GOAL_GITHUB_TOKEN` bound to `api.githubcopilot.com`) and passes the same value to authoring (`authoring.EnvReferences.Policy`, the credentials check) and to the gateway (`gateway.Config.SecretPolicy`), the engine (`engine.Config.SecretPolicy`, before it resolves the repository token for a box) and the code host (`github.Config.Policy`), which refuse a `runtime.repository.token` naming a reserved variable before resolving it (`domain.SecretPolicy.ForRepository`, `domain.ErrSecretReserved`), so not even the trusted GitHub host receives goald's own secrets. Before resolving a header value, a sidecar `env` value or a `command` word, the gateway checks each `env:NAME` reference against it for the url the value is sent to: a reserved variable goes to no connection, and a host-bound one only in the headers of an https connection to one of its hosts (scheme https, host matched without case, any port; no sidecar, whose network reaches any host). A refused connection is unavailable ("it references a secret this install does not send there"; `tools/call` on it is refused like an unknown tool): the refused reference is never resolved, no request reaches its server and no sidecar starts, and goald logs `gateway refused to send a secret` with the connection and the reference, never a value. Redirects are not followed (credentials are added per request). Phase 4's credentials carry the same host bindings.
- **Egress** ([ADR 0009](../adr/0009-agent-network-isolation.md) and its phase 4 amendment). compose.yaml keeps the agents network (`GOAL_SANDBOX_NETWORK`, default `goal_agents`: internal, no bridge address, so no route to the host, other networks or the internet) and its `goal-egress` service (`cmd/goal-egress`, `task egress:image`), on it and on compose's default network; `goal up` starts it with `GOAL_EGRESS_GATEWAY`, goald's gateway listener as the proxy reaches it (`host.docker.internal` for goald on this machine, `goald:8090` under `goal up --compose`). The Docker adapter checks the network exists and is internal before each container (one inspect) and runs boxes, agent tasks, networked sidecars and command checks on it, each with `HTTP(S)_PROXY` naming the proxy and `NO_PROXY` the proxy and the container's loopback. The proxy has one policy for every client: any destination whose resolved addresses are all public, by `CONNECT` or plain-http forwarding, and goald's `/mcp` and `/run` by its reverse path (a container's `gateway_url` is the proxy's: `http://goal-egress:3128/mcp`); it resolves every destination itself and refuses any name with a loopback, private, link-local (metadata), CGNAT or reserved address (`egress.Public`), so rebinding cannot reach the host. Refusals are 403s and `egress refused` log lines in the proxy's container. The proxy belongs to no run, so reaping leaves it alone. The worker turns off Claude Code's nonessential traffic.
- **Sandboxes on Docker** (`docker.Sandboxes`, spec 4 §5.1; the engine moves onto it in 4-7). One container `goal-box-<run>` per run of the run's image, labelled like task containers, uid 1000, every capability dropped, no new privileges, init, the size's CPU, memory and PID limits (small 1/2 GiB/1024, medium 2/4 GiB/2048, large 4/8 GiB/4096), a writable root filesystem with a tmpfs `/tmp`, nothing mounted, on the agents network; its process sleeps until the deadline, so a box nobody deletes ends by itself. `Exec` is `docker exec` with stdout streamed and the stderr tail kept; Docker cannot end an exec, so each one carries a `GOAL_EXEC_ID` marker and a cancel, a timeout or `Delete` (`rm -f` of every container of the run) kills its processes and their children found by that marker. `List` reads the `goal.run` labels.
- **Tools.** Named `<connection>__<tool>`. `tools.allow` and `tools.deny` entries of the form `<connection>__<pattern>` (`path.Match`) apply to gateway tools; deny wins, and a connection with allow entries serves only what they match.
- **Audit.** Every `tools/call`, denied ones included, appends a `gateway_tool_call` event (connection, tool, outcome, duration, request and response sizes) through `gateway.Events`, which `ports.Store` satisfies. Arguments, results and credentials are never recorded; resolved credentials are scrubbed from results, errors and logs.
- **Upstream protocol.** Upstream sessions negotiate the latest MCP protocol. On the 2026 protocol a server may require `Mcp-Param-*` headers mirroring annotated arguments (`x-mcp-header`; GitHub's server does), which the SDK adds only for tools the session has listed, so a call lists the upstream's tools first. The gateway's own `tools/list` result is `cacheScope: private` (it depends on the task's token).
- **Bounds.** Per-call and list timeouts, a cap on upstream response and agent request sizes, no redirects for credentialed requests.

### HTTP API

`api/openapi.yaml` is the contract ([ADR 0004](../adr/0004-frontend-and-monorepo.md)); `task api:gen` regenerates the Go server interface, models and client in `internal/api/gen` (oapi-codegen, pinned in `Taskfile.yml`) and the TypeScript types in `packages/api-client/src/schema.ts` (openapi-typescript); both are committed, and `task check` fails when the TypeScript side is stale. Every operation names the permission it needs in `x-goal-scope`, one of `api/permissions.yaml` (phase 3, spec 3 §8.2); `cmd/permgen`, run by `task api:gen`, checks both files together (an operation without a scope or with an unknown one, a permission whose roles contradict its level, a fresh permission for keys are refused) and generates `internal/api/permissions_gen.go` (`permissionRules`, `operationScopes`), and `task check` (`api:permissions-check`) fails when it is stale. `internal/api` implements the strict server over small interfaces (the engine, the store's reads, the organizations, the definitions cache, the stream feed, the clock, the `Authorizer`) and answers errors as RFC 9457 problem details (`Problem{title, status, detail?, code?}`, `code` kebab-case): 404 for unknown organizations (one identical body, `org-not-found`, for unknown and deleted ones), factories, items and runs (one fixed body each without detail, `factory-not-found`, `item-not-found`, `run-not-found`, which the resolvers also give for one the principal may not see), 400 for invalid requests, 409 when a rule is broken (a taken or reserved slug) or the item's state does not allow the action (a decision on an item not waiting for a human, a retry of an item that is not blocked, a merge away from a merge station or one the pull request refuses), 403 `forbidden` for a refusal of the `Authorizer` or of cross-origin protection.

Every request passes the same layers, outermost first: the `Host` check (`api.CheckHost` around goald's whole mux, SPA included: a `Host` naming none of `localhost`, `127.0.0.1`, `[::1]`, the `GOAL_LISTEN` host and `GOAL_PUBLIC_URL`'s host (default `http://<GOAL_LISTEN>` on loopback), on any port, is 421 Misdirected Request, so a page that rebinds its own name to the loopback address cannot pass cross-origin protection as same-origin; `/v1/health` and the agents' `/mcp`, which the egress proxy reaches as `host.docker.internal` and every request to which carries a task token, are exempt); inside `/v1`, the access log (`internal/api/accesslog.go`: one `api request` line per request with its operationId, status, request id, `principal` `user:<id>`, `service:<key id>` or `none`, `credential` `session`, `key:<id>` or `pat:<id>`, and `org_id`; never a path, cookie, token or email); a 1 MiB body cap; `http.CrossOriginProtection` (an unsafe method from a browser page of another origin is refused; `Sec-Fetch-Site: same-origin`, `Origin` equal to `Host`, and clients that send neither, such as the CLI, pass); a request id (`X-Request-Id`, the caller's when well formed, else new; echoed, and recorded by the audit log); the request's principal and actor (`internal/api/credential.go`: under `GOAL_AUTH=none` `domain.LocalPrincipal`, whose actor is `domain.LocalUser`; under `session` `parseCredential` reads a bearer API key, personal token or session token, else the session cookie of the install's scheme, a malformed one being `domain.ErrUnauthenticated`, and each operation's `scope` resolves it in the database (`identity.go`, `ports.Identity`), the credential first (401), then the organization (404); in every mode an `Authorization` header that is not a bearer API key or session token, an agent's task token above all, is 401 `unauthenticated` with `WWW-Authenticate: Bearer realm="goal"`, never the local user); then, per operation, the org middleware (`internal/api/org.go`: `Tenancy.Org(path {org})`, binding the request with `domain.WithOrg`, so row-level security scopes every store call) and the `Authorizer` seam (`internal/api/authz.go`: `AccessRequest{Principal, Operation, Permission, Org, Factory}`), which the resolvers `s.factory`, `s.definition`, `s.item` and `s.run` pass again with the factory; `refusal` turns a hidden resource into the unknown one's error, `domain.ErrUnauthenticated` into 401 `unauthenticated` (`WWW-Authenticate: Bearer realm="goal"`) and `domain.ErrReauthRequired` into 403 `reauth-required`. goald wires `api.AllowAll` only under `GOAL_AUTH=none`; `api.Permissions` (`internal/api/permissions.go`) is the real `Authorizer` over the generated table (spec 3 §8.4: membership and visibility first, then roles, a key's scopes and ceiling, and the fresh-session rule, `domain.FreshFor`), with the visibility helpers `s.visible(ctx, factory)` and `s.can(ctx, factory)` for lists and `can` fields. `internal/api/testdata/access.golden` records its answer to every operation for every kind of principal in two organizations (`TestAuthorize_TwoOrgMatrix`). Beside `/v1`, under `GOAL_AUTH=session` only, `api.AuthProxy` answers every path under `/api` on the main listener before the mux can redirect it: it forwards the identity service's allowlisted `/api/auth/*` endpoints to `GOAL_AUTH_UPSTREAM` (loopback http) and refuses everything else with 404 `not-found` ([spec 3 §5.5](../specs/3-identity-and-access.md): encoded or unclean paths refused, forwarding headers replaced by `X-Goal-Client-Ip` from `GOAL_TRUSTED_PROXIES`, 64 KiB bodies, 2/10/15 s timeouts and 503 `auth-unavailable`, `Set-Auth-Token` stripped, cross-origin protection, no credentials in its log). Under `none`, `/api/…` is the UI's 404.

Every route but `/v1/health` and `/v1/orgs` lives under `/v1/orgs/{org}` (the organization's slug or id). `{item}` is the item's id or `<factory>#<number>` (`goal#2`, the factory by name or id; `#` percent-encoded as `%23`), and every item carries its `ref`. `{factory}` is a factory's id or name, within the organization.

A decision's event names the decider (`actor`, the display name) and records `data.actor`, its ref (`user:local`).

**A person's control of an item in progress** (move, pause, send back; `engine.Move`, `Pause`, `Reject`): the transition takes the item's lease (`Transition.TakeLease`, lease outcome `taken`) and appends `lease_taken` (`data.action`) before the person's event, all in one transaction with the audit entry (`item.moved`, `item.paused`, `item.rejected`). The goald running the item stops its run at once when it made the change itself or when `engine.Interrupt`, which `cmd/goald` passes to `api.NewFeed` as a tap of every item notice, hears the `lease_taken` notice of an item it runs at that station under a lease acquired no later than the notice; any other instance finds out at its next heartbeat (`ErrLeaseLost`). Either way the run is finished as `cancelled` and nothing else moves the item. A conflict (the item moved meanwhile) is 409 `item-changed`.

An item card is `{id, ref, number, title, type, lane, station, state, class_of_service, rework_count, cost_usd, created_at, updated_at, age_seconds, agent, pr_url}`: `agent` is the lease holder's agent while the item is in progress, `pr_url` the `pull_request` field of the item's latest station output, `age_seconds` the time since creation (created to done for a done item), `slot` the copy working it (1-based) while in progress at a station that runs several, `turn` the turns its running run reported (its `usage` events), `summary` the `summary` field of its latest station output.

A board station's statistics come from `FlowStats.StationTimes` over the window (the last N UTC days, 1d to 90d): `busy_ratio` (agent stations: lease time over slots × the window, measured from the factory's first lease if that is later, at most 1; null without lease history), `send_back_ratio` (stations with a gate: rejections over the window's verdicts; null without verdicts), `queue_trend` (queue and agent stations: waiting now against 24 h earlier), `oldest_waiting_seconds` (since the longest-waiting item's open span began) and `done_today` (the done station: items done since UTC midnight).

The board's `line` describes the line as a whole: `status` (`stopped` while an andon pull is open, with that pull as `andon`; else `running`), `wip` (items in progress or waiting on a person at the stations with a wip limit, against the sum of those limits), `release` (`policy` push or drum-buffer-rope as configured, `enforced` false: goald releases as push until drum-buffer-rope enforcement, which is later work; the `drum`, its configured `flow.constraint` or else the constraint now, its `buffer` and the items `in_buffer`, queued or ready there), `expedite` (`limit` from `flow.expedite.wip`, shown and not enforced, and `in_use`, the open expedite items past the queue stations; null for a line without an expedite lane) and `budget` (the weekly budget, `Runtime.WeeklyBudget` over `SpendSince` the last 7×24 h; null without one). A card is `in_buffer` when it waits at the drum; `rope_held` is false until the rope is enforced.

The board's `constraint` is the definition's `flow.constraint` when it names a station (`constraint_source: configured`), else the agent station whose slots leases held the largest share of the board's window, measured from the factory's first lease (`detected`), else, before any lease history, the agent station with the most work per slot right now, `(waiting + in_progress) / min(agents, wip)`, ties to the upstream station (`snapshot`; null when no agent station has work): `domain.Line.Candidates` and `ConstraintOf`. The same rule names the drum of the long waits, the cards' `in_buffer`, the bridge's insight and the overviews' `constraint.busy`; it is computed on request from `FlowStats.StationTimes` (no cache: the engine does not use it while drum-buffer-rope is deferred). `GET …/constraint` reports the top three candidates over a range with their time-weighted queue, mean wait and service, and `domain.WaitSaved`, an M/M/c estimate of the wait one more slot would save. Metrics count items that reached done in the range (UTC calendar days, `from` and `to` included: at most 90 days, `to` not after today, the last 7 days by default; `window=Nd` names the last N days) and the cost of agent runs started in it, for one work type with `type` (one the factory declares, else 400); long waits are counted at the definition's `flow.constraint` when it names a station, else at the snapshot constraint; WIP is the items now neither done nor cancelled, the rework rate the share of the items done in the window that were sent back at least once.

Under `GOAL_AUTH=session` (the default) every `/v1` operation but the public ones needs a credential; under `none` goald listens on loopback only. The CLI (`goal run`, `follow`, `item`, `approve`, `reject`, `retry`, `merge`, `note`, `move`, `pause`, `andon [pull|clear]`, `factory pull|validate|push|publish|list|versions|restore`, `org list|use|create`, `key list|create|revoke`) uses the generated Go client in one organization: `--org`, else `GOAL_ORG`, else `org` in `$XDG_CONFIG_HOME/goal/config.json` (default `~/.config/goal/config.json`, mode 0600, `{"api_url", "org", "credential_store"}`; `goal org use` writes it), else the install's only organization (with `GOAL_API_KEY` or a key or personal token stored by `goal login --token`, its own, skipping the config file's); with sign-in on, it sends `GOAL_API_KEY` or what `goal login` stored for the API's origin (the OS keychain, or `credentials.json` beside the config with `--store file`; `cmd/goal/credentials.go`), only over https or to loopback, and exits 77 on a 401 or 403; a bare item number resolves when exactly one factory of the organization has an item with it (`--factory` otherwise). The web UI uses `@goal/api-client` (`packages/api-client`): `createGoalClient(baseUrl)` (openapi-fetch over the generated types) and `subscribe(baseUrl, {org, factory?}, handlers)` over the stream (`onItem`, `onFactory`, `onEvent` for the other names, `onResync`, `onStatus`).

#### Realtime stream

`GET /v1/orgs/{org}/stream` is `text/event-stream` and carries one organization's events only. Each committed item event is `event: item`, `id:` the event id, `data:` `{org_id, item_id, ref, factory_id, kind, station, state, at}` (`StreamEvent` in the contract); `?factory=` keeps one factory's. An organization's other events (`connection`, phase 4's `knowledge`, ...) arrive under their own names with their data object, from the `goal_org_events` channel (`pg_notify('goal_org_events', {org_id, event, factory_id?, data})` in the transaction that causes them; `ports.ItemNotice.Org`); a name that is not lowercase letters, digits and dashes is never written. `event: factory` (`FactoryEvent`: `{org_id, factory_id, kind, andon_id, at}`, kind `andon_pulled` or `andon_cleared`) is one of them: the `andon_pulls` trigger of migration 00032 notifies it when a pull is inserted or cleared. `event: connection` (`ConnectionEvent`: `{connection_id, name, change}`, change `created`, `updated`, `deleted` or `tested`) is another: the connections adapter notifies it in each change's transaction, and `postgres.Notices` reads it back from the change's audit entry. `event: resync` (`data: {}`) says events may have been missed, so the client re-reads what it shows; a `: heartbeat` comment comes every 15 s and `retry: 3000` opens the stream. There is no replay (`Last-Event-ID` is ignored): a client re-reads on every (re)connection, which `subscribe` signals as a resync.

```
item_events INSERT ── trigger notify_item_event() ── pg_notify('goal_events', {org_id, id, factory_id, item_id, number, kind, station, state, at})
an org's other event (phase 4) ───────────────────── pg_notify('goal_org_events', {org_id, event, factory_id?, data})
        │  (any goald instance, in the transaction that causes it)
        ▼
goald: postgres.Notices.Listen (one connection, both channels, reconnect + Resync) ──▶ api.Feed (fan-out by org) ──▶ each SSE client of that org on this instance
```

Each instance listens once and fans out to its own clients, each receiving only its organization's notices (and every resync), so `goald` stays stateless and any instance serves any client. A client that falls 256 notices behind has its stream ended (it reconnects and re-reads) so it never holds up the others; at shutdown the feed ends every stream before HTTP drains.

#### Merge stations

A human station may declare `action: merge` (schema: human stations only; until 4-14 the factory needs `runtime.repository`, whose token merges). `POST /v1/orgs/{org}/items/{item}/merge` (`goal merge <item>`) is `engine.Merge` (spec 4 §4.7, 4-13):

1. The item must be waiting at that station (409 otherwise), and its outputs must name at least one pull request (409 `cannot-merge` otherwise): `domain.Item.PullRequests`, the `pull_request` string and the `pull_requests` array of each station's latest output, https URLs only, in the line's station order, each once.
2. Each URL gets the first of the factory's connections (`engine.Deps.MergeConnections`) whose kind names a code host goald has (`engine.Deps.CodeHosts`, by `codeHost`) and whose git login is for the URL's host; a URL no connection serves refuses the whole merge before anything is merged (409 `no-code-host-connection`). Until 4-14 the one connection is goald's `repositoryConnections`: the factory's `runtime.repository.token` (refused when the install reserves it) as a connection of the platform's `github` kind on `GOAL_GITHUB_WEB_URL`'s host; 4-14 swaps that source for the organization's connections and nothing else.
3. For each pull request in turn, through its `CodeHost`: read it; one already merged is skipped; refuse (409 `cannot-merge` naming it, the item does not move) unless it is open and the host reports it mergeable. Then merge it (squash by default) at the head SHA just read, so the host refuses if the branch moved; never forced. Read it again and require `merged`. Then delete its head branch, only when it lives in the repository it merged into and is not its base branch; a failure there is logged, not fatal. Nothing else is ever deleted.
4. Approve the item in one transition with one `merged` event per pull request (`pull_request`, `sha`, `method`, `branch_deleted`) and an `approved` event by the request's actor.

The pull requests merged before a refusal stay merged and are skipped next time, so a retry after a partial failure is safe. Which repositories can be merged is the token's own scope. No credential reaches events, errors or logs.

### Factory definitions in object storage

Definitions are content, not code ([ADR 0005](../adr/0005-factory-definitions-in-object-storage.md) and its 2.2 amendment). The content lives in the bucket; the versions and the pointer to the running one live in PostgreSQL:

```
s3://<bucket>/
  orgs/<org-id>/blobs/<sha256>          every definition file (factory.yaml, agents/, skills/, contracts/, evals/), once per org, never overwritten
  catalog/templates/<name>/<version>/   curated starting points; catalog/skills/ (D) beside it
  orgs/<org-id>/knowledge/<sha256>      uploaded knowledge documents (4-16), written once, deleted with the last document holding them; catalog/connectors/ is dropped

PostgreSQL
  definition_versions   one row per draft or published version: manifest {path → sha256}, number, revision, author, publisher
  definition_blobs      the hashes each org has stored
  factories.current_version_id          the published version that runs; publish and restore move it in one transaction
  agent_runs.definition_version_id      the version a run started on, and finishes on
```

- **Content.** A blob's key is the lowercase hex SHA-256 of its bytes. It is written with a conditional put and never rewritten (an object already at the key is adopted only when it hashes to it, and replaced otherwise), so a version's tree is reproducible from its manifest alone and identical files are stored once across versions and clones. Readers verify the hash of every blob they fetch.
- **Versions.** A factory has at most one open draft, shared by its editors and saved with optimistic concurrency on its revision. Publishing makes it version N+1, moves `current_version_id` and writes the audit row in one transaction; a trigger NOTIFYs `goal_definitions`, and every goald reloads. Published versions never change; restore moves the pointer back, and numbers are never reused.
- **Runs.** A run keeps the version it started on (contract, checks, agent files, gateway tools); an item's next step uses the current version.
- `internal/config` loads a definition from any `fs.FS`, built from a manifest and its blobs or, for a local working copy, by `LoadDir`. Paths in `factory.yaml` resolve inside that tree only. `config.Check` reports every finding as a located `domain.DefinitionProblem` (stable kebab-case code, severity, the check that found it, the Visual section and model pointer, file, line and column, and machine-applicable fixes); `Load` fails on the blocking ones. `Factory.SecretUses` lists every secret reference of the removed forms with its place and purpose for the env: part of the connections check. Since 4-10 a definition names the organization's connections (`spec.connections` as names, `runtime.modelConnection`, `runtime.repository: {url, connection}`), `runtime.size`, `runtime.tools` (mise tool specs, `tool-spec-invalid`) and `knowledge.sources`; the forms phase 4 removed still load, so published versions run until the cutover (4-14), each a warning with a quick fix: `field-removed` (`runtime.runner`, `image`, `auth`, `secrets`, `knowledgeBase`), `env-reference-removed` (`runtime.repository.token`) and `connection-inline-removed` (inline and connector-form connections; the fix puts the organization's connection of the same name in its place). Authoring's connections check (`authoring.ConnectionsCheck`, check id `connections`, the `authoring.Credentials` extension point) reads the organization's connections and kinds through `ports.Connections` (names, kinds and non-secret fields; `domain.ConnectionKind.Outline` renders the env names and git host a run would get without a value) and reports `connection-unknown`, `connection-not-model`, `repository-host-mismatch`, `connection-env-conflict` and `knowledge-source-unknown` (against `authoring.KnowledgeSources`, which the knowledge base wires in 4-16; without it an organization has no source), each an error with its fixes.
- `internal/adapters/s3store` implements `ObjectStore` with the AWS SDK for Go v2: a custom endpoint with path-style addressing for RustFS, the standard credential chain on AWS. It uses no versioning API, so RustFS and R2 behave the same (ADR 0005, phase 4 amendment): `List` is `ListObjectsV2`, `Delete` removes for good, `DeletePrefix` removes each list page with one `DeleteObjects`, and `EnsureBucket` (used by `goal storage init`) only creates the bucket; a bucket that still has versioning on keeps working. `PutIfAbsent` is a conditional `PutObject` (`If-None-Match: *`, which S3 and RustFS support; 412 means the object is there and `HeadObject` reports it); a server answering 501 gets `HeadObject` then `PutObject`, harmless for content-addressed keys.
- `internal/adapters/postgres` implements `DefinitionStore` as `postgres.Definitions` (`NewDefinitions(pool, objects, log)`, over the `ObjectStore` port) and `DefinitionNotices` as `NewDefinitionNotices(connConfig, log)`. Blob objects are written before and outside the transaction that records them in `definition_blobs`; every other change locks the factory row first (then its versions, then its items) and checks that every manifest hash is one of the organization's blobs. Triggers keep published versions immutable and undeletable (except by `goal_purge_org`), the pointer on a published version of the same factory, and NOTIFY `goal_definitions` with `{org_id, factory_id, kind, version_id, number, revision, by}` (migration 00010).
- Editing goes through goald's API: the builder and the CLI (`cmd/goal/factory.go`) write the draft. `goal factory push <dir>` replaces the draft's tree (`PUT …/draft/tree` with the `expected_revision` it read; a factory the organization lacks is created from the folder, keeping its `metadata.id`) and refuses an open draft with changes unless it holds the folder's last pull or push (`--replace-draft` archives it), or a published version newer than the one `.goal/pulled.json` records unless that version holds the folder's files (`--force`); `--publish` sends the current version id it read as `expected_current_version_id`. `goal factory pull` reads a published version by number (so one pull never mixes two versions) or the draft, checking every file against its sha256. `goal factory validate` validates through goald (the open draft with the folder as overlay, or the folder alone); `goal validate` is the offline `config.Check`, which `task check` runs on the fixtures. The template catalog (`catalog/templates/<name>/<version>/`, `authoring.TemplateCatalog`) is written only by the operator's `goal catalog templates push`: once per version, files first and `template.yaml` last, which is when goald lists it; it refuses a definition with errors and a `metadata.id` other than the nil UUID.
- **Skills catalog** (`internal/builder`, 2.2-D). `catalog/skills/index.json` lists every skill (`owner/repo/skill`, the commit it is pinned at, its description from SKILL.md, installs, file and byte counts, and a sha256 over its files); `catalog/skills/<owner>/<repo>/<skill>/<commit>/` holds that commit's folder, written once, never overwritten or deleted (drafts may have vendored it). Only the operator's `goal catalog skills sync --file <sources.yaml> [--search q]… [--top n]` writes it, through `ports.SkillSource`: the folder is read from GitHub's git objects of the resolved commit (regular files only, at most 200 files and 1 MiB, valid relative paths, hidden files left out, each blob checked against its tree entry; only the configured hosts, no redirect off them, timeouts, tokens scrubbed from errors), checked again by the builder, then stored. goald only reads it: the parsed index is cached by the object's ETag and re-checked at most every 5 minutes, a malformed index reads as empty (logged `builder.skills_index_invalid`), and every folder served is checked against its index entry's hash. A draft vendors a skill under `skills/<skill>/` with `skills[].origin` (`skills.sh:<owner>/<repo>@<skill>#<commit>`).
- **Transition (2.2-B, ended in 4-3).** The pre-2.2 layout, one prefix of mutable files per factory (`factories/<id>/`, then `orgs/<org-id>/factories/<id>/`), was imported once as v1 of each factory by the releases before phase 4, which read object versions to do it. The import and `internal/factorystore` are gone; the prefixes left in old buckets are never read and can be removed by hand. `postgres.Migrate` refuses (`ErrLegacyImportPending`: "start the previous release of goald once") a database where a live organization's import is still pending (`legacy_import_pending`, 00039) or that is from before 00039, so goald never starts on one; migration 00050 drops the record.

### Wiring

Manual constructor injection. `cmd/goald/main.go` reads the environment (`cmd/goald/settings.go` lists every variable), builds each adapter, passes them to `engine.New(...)` and starts the HTTP server. No container, no globals, no `init()` side effects.

```
settings (env) ─┬─ envsecrets.New ───────────────────────────────┐ Secrets
                ├─ postgres.Open(migrate URL, goal_owner) → Migrate → close
                ├─ postgres.Open(goal_app) → CheckAppRole → New ───┤ Store, Tenancy, Audit
                ├─ s3store.New → postgres.NewDefinitions(pool, objects) ┤ DefinitionStore
                ├─ definitions.New(definition store, tenancy, load, GOAL_DEFINITION_CACHE_BYTES) ─┐
                │      Contracts, gateway.Definitions (the run bundle's agent files) ◀─┘
                ├─ codeHosts: github.New(GOAL_GITHUB_API_URL), gitlab.New() ┤ CodeHosts (by kind's codeHost)
                │      repositoryConnections(secrets, policy, GOAL_GITHUB_WEB_URL's host) ┤ MergeConnections (until 4-14)
                ├─ docker client (GOAL_SANDBOX_NETWORK: compose's agents network)
                │      docker.NewSandboxes(network) ───────────────┤ Sandboxes
                │      docker.NewSidecars(network) → gateway.New(defs, secrets, store, sidecars; secret policy)
                │      secret policy: settings.secretPolicy, also authoring's credentials check
                └─ sysclock.Clock ────────────────────────────────┤ Clock
                                                                  ▼
                        engine.New(Deps{..., Orgs: tenancy, RunEnded: gateway.EndRun}, Config{Image: GOAL_AGENT_IMAGE,
                          GatewayURL: docker.BoxGatewayURL(GOAL_GATEWAY_URL), GatewayKeyRef, TaskEnv, MaxRuns, RepositoryHosts, SecretPolicy})
   load hook: every reload → engine.SetLines(lines, each with its OrgID, VersionID, Number, Paused)
   postgres.NewNotices(pool's conn config) → api.NewFeed(…, eng.Interrupt) ItemNotices for /v1/orgs/{org}/stream; the engine hears lease_taken
   postgres.NewDefinitionNotices(pool's conn config) → defs.Listen ─ reloads on goal_definitions
   http.ServeMux: /v1/ → api.New(engine, store (Items, Orgs), defs, api.AllowAll{}, feed, clock)    /mcp → gateway
   GOAL_GATEWAY_LISTEN: a second listener with only /mcp → gateway; the main mux answers /mcp 404 (routes)
   goroutines: engine.Run (ticks + lease sweep + reaping), defs.Listen, definitions refresh (GOAL_REFRESH_EVERY), feed.Run, HTTP (each listener)
   startup: Refresh; engine.Run's first pass sweeps leases, then deletes the boxes of runs that are over
   shutdown: HTTP, then the engine, then gateway.Close (stops every sidecar)
   SIGTERM: HTTP shutdown, engine context cancelled → runs stopped, items released to their queue
```

The definitions cache (`internal/definitions`) holds the current published version of every factory of every organization `Tenancy.ActiveOrgs` lists, read from `DefinitionStore` (manifests in PostgreSQL, each file a blob verified against its hash). It reloads an organization's current versions on every `goal_definitions` notice of a publish, restore, pause or resume (`Listen`; every goald within a second), drops a deleted organization's lines on the notice `DeleteOrg` sends in its transaction (kind `org`; the engine then cancels and releases the runs it has there, and `Version` serves no version of an organization that is not live), everything on a resync, every `GOAL_REFRESH_EVERY` (30s) as a safety net, and an organization when the API is asked for a factory it does not know whose current version the store has and the cache lacks (a publish whose notice has not arrived; one reload per organization for the lookups that miss together, a typo or a draft-only factory reloads nothing, and a store failure on that path answers 404). Names match without case, as in authoring. A version that does not load in this goald keeps the previous one in use. Runs pin their version: the engine records `agent_runs.definition_version_id`, the gateway token (`v` claim) carries it, and contracts, the run bundle's agent files and gateway tools are read by version id (`Validate(ctx, version, …)`, `AgentFiles`, `Version`); versions no longer current stay in an LRU bounded by `GOAL_DEFINITION_CACHE_BYTES` (64 MiB) and load from the store on a miss. The next move of an item after its run follows the current line, matched by station id. A paused factory (`factories.paused_at`) is a line with `Paused`: the engine releases and claims nothing there, and its runs in progress finish. Every read (`Factories`, `Lookup`, `Version`, contracts, agent files) sees only the organization in its context.

**Engine across organizations.** Each `domain.Line` carries its `OrgID`, and every store call the engine makes for a line, the run's included, is bound to it (`domain.WithOrg`); `Submit` and the decisions find only factories of the organization in their context (another's is `ErrNotFound`). `Tick` releases queue stations line by line, then claims with two-level round-robin: in each pass every organization with work claims at most one item, trying its factories in turn and their agent stations in line order, until nothing more can be claimed or the instance runs `GOAL_MAX_RUNS` runs (0: no cap). The order of organizations and of each one's factories rotates every tick; the tick counter and the run count are local scheduling hints, not state. `SweepLeases` requeues expired leases once per organization `ActiveOrgs` lists, so leases on factories no longer loaded are swept too.

**Reaping.** A claim's box (and, until 4-11, its runs' sidecars) is deleted when the claim ends, however it ends; a goald that dies leaves them behind. Several goald instances may share one sandbox backend (two on a laptop, or one restarted next to another), so no instance removes what another may still be using. `engine.ReapOrphans` lists every box (`Sandboxes.List`) and asks the store which of their runs are over (`Store.RunsOver`, in the organization the box is labelled with); only those boxes are deleted. A run is over once it no longer runs and no longer holds its lease (the lease, fenced by `AcquiredAt`, is the source of truth; checks and a retry run under it after the first run ended, in the box named after it). Another live instance's runs heartbeat their leases, so they are never over. A dead instance's leases expire and `SweepLeases` requeues them and fails their runs, so any instance reaps their leftovers at its next reap; a run whose lease a person took is over once `FinishLostRuns` cancelled it. Boxes of runs the store does not know (another deployment's on a shared host), of an organization that is not active or of none, and of an organization the store fails to answer for are left alone. `engine.Run` reaps right after its first sweep at startup and then every `ReapEvery` (`LeaseTTL`/2, one minute by default), so a dead instance's orphans go within about `LeaseTTL` + `ReapEvery` of its last heartbeat, and a restarted instance's own earlier orphans the same way (instances keep no identity across restarts). A deleted organization's leftovers from an instance that died before it noticed the deletion stay until removed by hand.

**Weekly budget.** A line whose `runtime.budget.weeklyUsd` is set has its spend read once per tick (`Store.SpendSince(factory, now − 7×24h)`: the cost of the runs started in the rolling window, UTC, no time zone; `dailyUsd` is display-only). At or over the cap (`domain.Runtime.WeeklyBudget`) its agent stations claim nothing, while queue stations still release and human decisions still move; `onExhausted: stop` also cancels the runs this instance has in progress there (a per-run cancel the engine keeps for its own runs), and their items return to their queue with `agent_cancelled {reason: budget}`. Claims resume when the window moves past old runs or a publish raises the cap. It is not an andon pull: nobody clears it. A line without a weekly budget reads nothing. Transitions log `budget_exhausted` / `budget_resumed` (factory, spend, cap, policy) with the gauge `goal_factory_budget_exhausted` (1/0) as an attribute until goald exports OpenTelemetry metrics. A spend read that fails skips that line's claims for the tick. Spend is the cost runs record when they finish and nothing is reserved at claim time, so a line can overshoot its cap by at most its agent-station slots × 2 (a run and its retry) × the per-run cap (`perItemUsd`, or an agent's own); D §4.2 has the example.

**Andon cord.** A person pulls it (`engine.PullAndon`, a reason of 1–500 characters) to stop a factory's line and clears it (`ClearAndon`, an optional note) to restart it; nothing pulls or clears it automatically in 2.2 (the rework-rate pull is later work; the API shows each gate's tally and warning). Each tick reads every running line's open pull (`Store.OpenAndon`) and a stopped line releases and claims nothing; its runs in progress finish and move on, submissions still enter the first station and every human decision still acts. A pull that cannot be read counts as open for that tick. A pause, an open pull and a used-up weekly budget combine without precedence, none lifting another: pause and pull each stop releases and claims, the budget stops claims only, and its stop policy cancels runs even on a paused or stopped line. The pull and the clear log `andon pulled` / `andon cleared` (factory, kind, reason, by).

### Identity and access (phase 3, as built)

[Phase 3](../specs/3-identity-and-access.md) and [ADR 0007](../adr/0007-identity-better-auth.md) add people. Sign-in is on by default (`GOAL_AUTH=session`, `defaultAuth` in `cmd/goald/settings.go`, which `goal up` follows).

- **Two processes, one origin.** `auth/` (Node 22, Hono + Better Auth pinned exactly, four plugins: email one-time codes, organizations with members and invitations, the device flow for `goal login`, bearer; Google optional) listens on loopback only (`GOAL_AUTH_LISTEN`, default `127.0.0.1:8081`): beside goald on a laptop (`goal up` runs `node auth/dist/server.js` and Mailpit), on Cloudflare (phase 4, planned) as a container that only goald reaches, through the control Worker. goald serves everything on `GOAL_PUBLIC_URL` and `api.AuthProxy` forwards an exact allowlist of Better Auth paths under `/api/auth/*` to `GOAL_AUTH_UPSTREAM` (forwarding headers dropped, `X-Goal-Client-Ip` written by goald from `GOAL_TRUSTED_PROXIES`, `X-Goal-Proxy-Secret` with `GOAL_AUTH_PROXY_SECRET`, without which the service answers nothing but its health check, encoded and unclean paths refused, 64 KiB, timeouts and 503 `auth-unavailable`, `Set-Auth-Token` stripped, Goal bearers answered 401 and never forwarded, no secrets in its log). The organization paths Better Auth would own (`/organization/create`, `/update`, `/delete`) are disabled in it. Its origin and CSRF checks are on whatever `NODE_ENV` says. The SPA gets a Content-Security-Policy (`web/csp.txt`).
- **Credentials, checked in PostgreSQL per request.** `credential.go` reads a bearer value (an API key `goal_sk_…`, a personal token `goal_pat_…`, or the Better Auth session token `goal login` holds) or else the session cookie of the install's scheme (`goal.session_token`, `__Secure-` over https); an agent's task token, or anything else, is 401. `postgres.Identity` resolves it through `SECURITY DEFINER` functions (`goal_principal`, `goal_api_key`, `goal_personal_token`) for the path's organization: the user or key, the session times, the org role and factory roles, a key's scopes, ceiling and factories, a token's scopes. No JWT and no cache: a removal, demotion, revocation or expiry applies on the next request, and streams end on `goal_access` notices, at expiry and on resync. goald holds no Better Auth secret.
- **Authorization from one table.** `api/permissions.yaml` defines every permission (who holds it, whether keys may, whether a personal token may (`pat`), whether it needs a sign-in within 10 minutes); `cmd/permgen` generates goald's table and `auth/src/access.gen.ts`, and each OpenAPI operation names its permission in `x-goal-scope`. `api.Permissions` checks a personal token's scopes first and fails closed, then membership and visibility, then roles, a key's scopes and ceiling, and the fresh rule (403 `reauth-required`; never for a token, which gets `forbidden`). Owners and admins hold every factory permission; members only what their factory roles (viewer ⊂ approver ⊂ editor) give. Unknown or invisible organizations, factories and items are the unknown one's 404; missing credentials 401; missing permissions 403. `internal/api/testdata/access.golden` records every operation's answer for every kind of principal in two organizations.
- **Keys and personal tokens.** An API key is an organization's service account (`service:<key id>`, "<name> (API key)"), within its creator's rights and a role ceiling, optionally restricted to factories, ≤ 90 days. A personal token is a member's own credential in one organization, at most the owner's current roles ∩ its scopes, never fresh, never platform admin, created only from a fresh browser session (403 `browser-session-required` otherwise); its writes record `via: pat:<id>`. Both are shown once (`Cache-Control: no-store`), stored as SHA-256, revoked at once, and refused at `/api/auth` and at the gateway.
- **Ownership of data.** Better Auth's tables live in schema `auth` (generated SQL committed as goose migrations `00040`–`00041`; `task auth:schema-check` fails on drift; `auth migrate` is never run), written only by the role `goal_auth`; `goal_app` reads them only through definer functions. goald alone creates, renames, deletes and purges organizations (both rows in one transaction, `goal_provision_org`); platform admins (`platform_admins`, a Goal table) create them. Factory roles, API keys and personal tokens are Goal tables under RLS. Membership changes reach `audit_log` through triggers with the actor the auth service stamps from the session; sign-ins, codes and device approvals go to the install's `auth_events` (`goal admin events`), cleaned daily by `goal.auth.cleanup` under an advisory lock.
- **Bootstrap and recovery.** While no user exists only `GOAL_BOOTSTRAP_OWNER_EMAIL` may sign in; that first user becomes a platform admin and owner of every live organization (`goal_claim_bootstrap`). Rows from before sign-in keep `user:local` and read "Local user (before sign-in)". `goal db recover-admin <email>` and `recover-owner <org> <email>` need only the database (goald may be stopped), create the user if needed and are audited.
- **Logs.** One `api request` line per `/v1` request names its principal and credential by id (`user:<id>`, `service:<key id>`, `pat:<id>`, `key:<id>`) with its operation, status, organization and request id, never a path, cookie, token or email; refused keys and tokens are counted (`goal_api_key_verifications_total`), not written to `auth_events`.
- **Fail closed.** `GOAL_AUTH=none` (the single local user, everything allowed) is chosen explicitly, only for a loopback listen, and warns at startup that every request, agents' included, is the local user; it never comes from an invalid credential. A non-loopback listen needs `session`, an https `GOAL_PUBLIC_URL` and a separate listener that serves only the agents' `/mcp` gateway, whose task tokens carry `aud: goal-gateway` and are accepted nowhere else. Under `session` goald refuses to start unless the identity self-check passes, and, without stopping, follows the auth service from its start: it logs that it waits for it, warns only when it still does not answer after 30 seconds (signed-in people keep working through an auth outage), and once it answers logs who signs in first while nobody has. `goal up` starts the auth service again, with a backoff, when it stops by itself. `goal up` refuses, before it starts goald or the auth service, without `BETTER_AUTH_SECRET` (distinct from `GOAL_GATEWAY_KEY`), without `GOAL_BOOTSTRAP_OWNER_EMAIL` while nobody has signed in, or without the auth service's build, naming `GOAL_AUTH=none` as the way to keep the local user. A `Host` other than the public URL's is refused (DNS rebinding). goald and the auth service each get only their own variables, and goald's reserved list keeps the auth service's, `GOAL_API_KEY` and `GOAL_DATABASE_ADMIN_URL` out of factory definitions. The threat model with the test of each control is spec 3 §11.1; dependency policy and the patch SLA are in `SECURITY.md`.

### Phases 4 to 6 (planned, not built)

Designed in [spec 4](../specs/4-connections-runs-and-knowledge.md), [spec 5](../specs/5-continuous-learning.md), [spec 6](../specs/6-goal-mcp-server.md) and [ADR 0008](../adr/0008-portable-runs-connections-and-knowledge.md); only what is marked built (with its PR) exists in the code, and the sections above stay the description of what runs today.

- **Runs in sandboxes.** `ports.Sandboxes` (create a run's container, exec in it, delete, list for reaping) replaces `Runner`, `Task`, `Workspaces`, `Checker`, `Sidecars` and `Reaper`, with adapters `docker` and `cloudflare` (an HTTP client of a small control Worker under `deploy/cloudflare/`). One container per run is a disposable dev box: public internet, private, loopback and metadata addresses refused ([ADR 0009](../adr/0009-agent-network-isolation.md) amendment), the repository cloned inside it, tools installed with mise from the repository's config and `runtime.tools`, checks run in it by exec with runtime exit codes. One base image, `goal-agent`; `runtime.image` goes. Autoscaling is the existing lease slots, zero boxes when idle.
- **Connections.** Built in 4-8: connection kinds are data (`schema/connection-kind.schema.json`; the platform's in `internal/connkind/kinds/`, upserted at goald's start through `goal_sync_platform_kinds`; `domain.ConnectionKind.Render` makes a run's env, git login and MCP server from a connection's values); a connection is an org row (00051) with its secret values sealed under the platform master key (`ports.MasterKey`, AES-256-GCM, key id for rotation, `goal db rekey` reseals under the active key), write-only and audited (`ports.Connections`); goald refuses to start while a connection is sealed under a key id it lacks, and without any key serves everything but connections with secrets. Built in 4-9: the API (`internal/api/connections.go`, tag `connections`: kinds, connections, rename, test) behind `connection:read` (members, keys, personal tokens) and `connection:manage` (owners and admins, a fresh sign-in, never a key); `goal connection`; a connection's test sent from goald through `egress.PublicDialer` (public addresses only, 10 s, no redirects; `GOAL_ALLOW_PRIVATE_UPSTREAMS=true` lifts it on a loopback goald), its outcome audited and stored; a connection named by a factory's current version (`config.Factory.ConnectionNames`) is neither renamed nor deleted. Planned: a run's box receives its connections' values as environment variables and uses them directly: APIs, CLIs, stdio MCP servers and remote MCP servers (a header rendered from those variables, `Authorization: Bearer ${DD_API_KEY}`); AWS gets STS credentials minted per run (`ports.Minter`). Built in 4-13: `CodeHost` is chosen by the kind (`github`, `gitlab`) and the merge station merges every pull request an item's outputs name (Merge stations above); its connections are the repository token's until 4-14. `GOAL_TASK_ENV`, `GOAL_GITHUB_TOKEN` and `env:` references in definitions go.
- **Gateway.** Goal's MCP server for runs: Goal's own tools (`knowledge__search`, `knowledge__read`, later item tools) and the run bundle (`GET /run`), authorized by the task token. It proxies no connection; its sidecars, upstream forwarding and secret policy go. OAuth connections and approval-gated calls (deferred) may route through it when they arrive.
- **Knowledge base.** Built in 4-16 (the core): one per organization, upload, synced and live sources (00054, `ports.Knowledge`, `postgres.Knowledge`, `porttest.Knowledge`, conformance suite `knowledgetest`). `internal/knowledge` holds the ingestion loop (`Ingestor`: `GOAL_KB_WORKERS` workers per goald, default 2, each claiming a due source in any active organization with a 10-minute lease renewed every third of it; listing, fetching only new or changed versions, `Extract` of text, Markdown, HTML, JSON and YAML, the heading-aware `Chunk` of about 2,048 characters with a 256-character overlap that only the embedding sees, embedding in batches of at most 64 texts and about 40,000 padded tokens, unseen documents deleted, the next sync scheduled; a goald killed mid-sync records nothing and its lease ends), uploads (`Uploads`: `orgs/<org-id>/knowledge/<sha256>` written once with `PutIfAbsent`, deleted with the last document holding it; also the upload sources' `SourceReader`) and `Searcher` (embeds the query, keyword search alone without a model or when it fails). A search is one SQL statement: the 50 nearest chunks of the current model by cosine distance (`hnsw.iterative_scan = relaxed_order`) and the 50 best by `ts_rank(tsv, any of the words, 1)`, both over the named sources only, fused by reciprocal rank (k = 60, `domain.FuseRanks`). Embeddings: `openaiembed`, default model Workers AI's `@cf/baai/bge-m3` (spec 4 §17 q2). Compose's PostgreSQL is `pgvector/pgvector:0.8.7-pg18-trixie`; `goal db init` creates the extension. Planned: the API, CLI and the gateway's `knowledge__search` and `knowledge__read` (4-17), the `gitdocs` and `confluence` readers (4-18, 4-19), the screens (4-20).
- **Human touches per item.** Built in the API (4-23, `FlowStats` above): `Item.touches`, `ItemCard.touch_count`, the board's and the overview's headline, `getTouchMetrics`, `getOrgTouchMetrics` and the touch reason; the screens (4-24: the Floor's headline and Touches panel, the factory tiles, the Board header, stations and cards, the Item's list with its reason select; frontend.md) and the CLI (`goal status`, which reads `getOrgTouchMetrics`, or `getTouchMetrics` with `--factory`, beside `getMetrics`; `goal item` writes the item's touches to stderr beside its JSON).
- **Targets.** Local Docker Compose with goald, the auth service, the egress proxy and agents in containers; Cloudflare with goald and the auth service as Containers behind the control Worker, R2 and a managed PostgreSQL over a direct connection. Terraform holds only the platform's own infrastructure.
- **Phase 5, continuous learning (Jonah).** When an item finishes with touches, a retro run proposes facts for the organization's Learned knowledge source, edits to the definition and regression eval cases (`evals/cases/`); a draft is evaluated against the current version with runs pinned to each (`engine.RunTask`, deterministic expectations first, an advisory judge rubric second, a learning budget); one review list decides, auto-publish only on no regression and only for prompts and skills; touches per version show whether a change helped. `internal/jonah` is a goald loop, not a service.
- **Phase 6.** Goal's MCP server at `/v1/mcp` for outside clients: OAuth through Better Auth's OAuth provider, MCP and client-metadata plugins, or API keys and personal tokens created for the MCP audience; each tool is one OpenAPI operation run in-process with the caller's principal.

## Scale and failure

| Concern | Approach |
| --- | --- |
| Horizontal scale | `goald` is stateless; run N instances behind a load balancer. |
| Work distribution | Each instance claims items with `FOR UPDATE SKIP LOCKED`; leases with heartbeats; expired leases return to the queue. |
| Singletons | Constraint detection, intake schedules, kaizen and Jonah schedules run under `pg_try_advisory_lock(<job key>)`, so exactly one instance runs each. |
| Realtime | Each instance `LISTEN`s on `goal_events` and streams to its own SSE clients; no sticky sessions needed. |
| Idempotency | Every engine step is keyed by (item, station, attempt) and safe to retry. |
| Connections | `pgxpool` per instance; RDS Proxy or PgBouncer in transaction mode when instances × pool size grows. |
| Event volume | `item_events` is append-only; partition by month when it passes ~50 M rows. |
| IDs | Generated in Go as UUIDv7, so the schema works on managed PostgreSQL versions without `uuidv7()`; the column default is a convenience for manual SQL only. |
| Shutdown | SIGTERM stops claiming, finishes or releases leases, then exits within the platform's grace period. |
| Observability | Structured `slog` JSON to stdout, OpenTelemetry traces and metrics; Claude Code's OTel events are joined to item traces. |
