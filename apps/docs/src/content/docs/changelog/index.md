This page lists the changes a person using Goal would notice, newest first, grouped by ISO week. Each entry links its pull request on [github.com/byFrederick/goal](https://github.com/byFrederick/goal). Refactors, CI and tooling changes are left out. The list starts with the changes merged to main from 2026-09-17; the repository's history begins on 2026-10-23.

## Week of 2026-11-02

- Menus, popovers, dialogs and toasts have a visible edge again in the dark theme: their ring is white at 8%, as the design system says, instead of black on a near-black page.
- An answer, a note, or a tool call a person approved or denied is no longer lost when the next run fails before its agent starts, for example when preparing its box times out. The run after it, such as the one a person starts with Retry, now carries it in its brief, and an approved call is still granted to it. Before, the agent could ask the same question again ([#896](https://github.com/byFrederick/goal/pull/896)).
- The assembly page's Plan says what each waiting part waits for, as its Board card does: the parts it needs, a merge turn, or CI with its finished and total checks and an ⓘ for its commits and checks. Each part from `GET …/items/{item}/parts` carries `waiting`, the same object `GET …/items/{item}` answers, or null ([#849](https://github.com/byFrederick/goal/pull/849)).
- **The standing rules' scopes are renamed.** `connection:read` is now `standing_rule:read` ("See standing rules" in the New key and New token dialogs) and `connection:manage` is now `standing_rule:manage`, because connections are gone and the scopes only cover standing rules. Who holds them is unchanged. Existing keys and tokens were moved over to the new names. A client that creates a key or token with an old name gets 400 `scope-not-allowed`; reload a web page opened before the update.
- The New key and New token dialogs now call the scope that lists standing rules "See standing rules" instead of "See connections".
- **Factory webhook endpoints and items' `source` are gone from the database.** Migration 00138 drops the old endpoints' sealed secrets, kind and factory, and items' `source`; every webhook now belongs to the organization, with a sender and a secret, and its name is unique there. A database must first run ADR 0040's release; on one that did not, migration 00138 refuses to run, changes nothing, and goald does not start until that release has run once ([#873](https://github.com/byFrederick/goal/pull/873)).
- **The factory webhook routes are removed.** `/v1/orgs/{org}/factories/{factory}/webhooks` and the routes under it (create, delete, rotate the secret, and the delivery log) answer 404, and `POST /hooks/{webhook}` serves only organization webhooks. No webhook answer has `kind` any more; an organization's webhook answers its `sender`. Use `/v1/orgs/{org}/webhooks` and `goal webhooks` ([#856](https://github.com/byFrederick/goal/pull/856)).
- **`GET …/factories/{factory}/intake` no longer answers `sources`.** Use `origins`, which counts the items created in the `window` by person, plan, trigger and follow-up (ADR 0040). `items`, `from` and `to` now count every one of the factory's newest items, including items created before Goal recorded where they came from, which they used to leave out.
- **`goal webhooks create --kind` is gone.** Use `--sender`: `--kind github` is `--sender github`, and `--kind generic` is `--sender standard`, which is also the sender when you give none. Passing `--kind` now prints the usage, like any unknown flag ([#855](https://github.com/byFrederick/goal/pull/855)).
- Home's row and the Floor's header no longer flash a green **Running** for a line that needs a model key. They show a grey placeholder until Goal has read the published version, then **Running** or **Needs a model key**; if the read fails, they show **Running**.
- The update toast no longer stays on screen with a Reload button that does nothing. It closes when a newer version replaces the one it offered, and Reload reloads the page when that happens.
- Runs on Cloudflare now record peak memory. Before, it was always empty, because the box's root cgroup has no memory counters. The worker reads its own cgroup first, then the root cgroup, then the machine's memory in use from `/proc/meminfo`, and its finished line says which with `memory_source` (`cgroup` or `machine`).
- The Floor's flow figures no longer show a red 0 under Throughput when no item finished in either range, and any change of 0 reads in grey instead of green or red. "No target set" stays next to a change.
- Home's row for a published line that has no model key now says **Needs a model key**, as the Floor does, instead of a green **Running**. In onboarding, the Code card's text wraps between words at 375 px instead of splitting "repository" in the middle.
- The Floor's Where work waits card no longer suggests one more agent that saves under an hour of lead time (or under a tenth of it), or at a station whose WIP limit already caps its slots. A spend under $1 a day reads "Under $1 more a day" instead of "$0".
- On the Floor, a line without repositories says "done" instead of "merged" at its Done station and in Throughput by week, and Throughput by week starts at the factory's first week instead of 12 weeks back.
>- A new version of Goal is ready now shows only when a newer build than the page runs is waiting. After a deploy, a tab that already loaded the new build no longer shows the toast on every page.
- **Connections, connection kinds, `goal connection` and `goal credential` are gone.** Migration 00135 drops the connection and connection kind tables, the standing rules that were revoked while keyed by a connection, and the connection fields of standing rules and knowledge sources. A database must first run a release that converts connections to secrets (ADR 0037); on one that did not, migration 00135 refuses to run, changes nothing, and goald does not start until that release has run once. The `/credentials` answers keep their shape, with no users and zero connection counts. Use `goal secret` for what `goal credential` did ([#809](https://github.com/byFrederick/goal/pull/809)).
- API keys, the sign-up domain and an item's touches show people by their current name, as the sidebar does, instead of their user id or the name they had when they acted. Someone who has left the organization shows as "A former member". This covers `created_by` and `revoked_by` of API keys, the sign-up domain's `set_by`, and the touches of an item and of its teardown ([#870](https://github.com/byFrederick/goal/pull/870)).
- The onboarding preview no longer asks you to pick a template while a factory you already chose loads, and the Intake step names starter triggers in words, such as Daily open tickets, instead of by id.
- The API returns each run's CPU time, peak memory and box size: `cpu_seconds`, `peak_memory_bytes` and `box_size` on `GET …/runs`, `GET …/runs/{run}` and an item's runs, each null when the box reported no value or the run predates them. `GET …/spend` adds `usage`, the median and 90th percentile CPU seconds and peak memory of the window's runs by factory, agent or station, and box size, so you can see which agents and stations use the most and whether a box size fits ([#817](https://github.com/byFrederick/goal/pull/817)). The Runs page shows CPU, Peak memory and Box from 1440 px wide, with — when the box couldn't measure a value ([Read the Board, the item Timeline and Runs](/docs/guides/read-the-board-timeline-and-runs/)). Spend has a Box usage section with the median and P90 CPU and memory by agent or station, per box size ([Read Spend and box usage](/docs/guides/read-spend-and-box-usage/), [#847](https://github.com/byFrederick/goal/pull/847)).
- On the Floor, a line without repositories says "done" instead of "merged" at its Done station and in Throughput by week, and Throughput by week starts at the factory's first week instead of 12 weeks back.
- **The API's connection and connection kind routes are removed.** `/v1/orgs/{org}/connections` (list, create, read, change, delete, test and the repositories listing) and `/v1/orgs/{org}/connection-kinds` answer 404; use `/access` for what runs reach and the secrets API for their credentials. The `connection:browse` scope is gone, so an API key or personal token can no longer be given it. Search answers no connections group, and `goal search` prints items, agents and factories. Spend's `model_connections` lists only the secret a factory's `runtime.modelKey` names. Standing rules keep their routes and the `connection:read` and `connection:manage` scopes.
- **A standing rule in the API no longer has `connection_id` or `connection`.** Both were always null after migration 00135. `factory_id`, `environment` and `server` are now always set, and `goal standing-rules list` names each rule's tool as `<environment>/<server> <tool>` ([#854](https://github.com/byFrederick/goal/pull/854)).
- On the Floor, the New item row in How work gets in is at least 44 px tall on a phone, and the ", or press C" hint no longer shows on touch devices. The Finish setting up checklist now says "First item done" instead of "First item merged", since a line without code never merges anything.
- A factory made with Start empty, when the catalog has no blank template, now names its end station Done, as the starter templates do. Before, the station had no name, so the Line step showed an empty Name field and the preview labeled it "done".
- Onboarding on a phone keeps the current step's label in view in the step bar, so "First item" is no longer cut off. When saving the Code step's token needs a fresh sign-in and you cancel it, the step now says so in one sentence and offers Sign in again, which saves and tests the token after you sign in. A station with no WIP limit shows No limit in its WIP field, in onboarding's Line step and in the factory editor.
- The preview on the Code step of setting up a factory keeps the factory card and its line, as the later steps do, instead of asking you to pick a template again. The Intake card now reads "New item, CLI and API" after any triggers that are on, and just that when none is.
- The Floor's Finish setting up checklist shows your factory's code choice instead of a GitHub connection: "No code", "Code, read only, 1 repository" or "Code, read and write, 2 repositories". It counts as done whichever you chose, because a factory without code is valid. How work gets in no longer shows Label an issue, which nothing implemented.
- Two new guides explain how to connect code. Connect code to a factory covers `runtime.repositories` with one repository, several or an owner's every repository, read and write access, `default`, an agent's `code`, a lane whose agent writes the fix, teams that only read, factories with no code and read-only tokens. Connect GitHub covers the organization webhook an owner adds once, repository webhooks for a personal account, the `github-read` and `github` tool templates, and adding a GitHub Enterprise or self-managed GitLab host. Factory settings now describes `runtime.repositories` next to the `runtime.repository` shorthand.
- Publishing warns when an agent that only reads code, or a check, can call GitHub MCP tools that write, judged by what the server marked read-only in the environment's last test (`github-tools-not-read-only`), or when that server hasn't passed a test (`github-tools-unknown`). A check whose agent uses only read-only GitHub tools no longer gets the general `check-tools-not-read-only` warning for that server ([#696](https://github.com/byFrederick/goal/pull/696)).
- An item can name the repositories it works on when you file it: `goal run --repo`, repeatable, or `repositories` when you submit through the API. Each value is an entry's name, `owner/name`, `host/owner/name` or an https URL that one of the factory's `runtime.repositories` entries covers; one that matches none is refused with a problem that quotes it, and an item takes at most 10. Items answer with their `branch`, and a submitted item and `GET …/items/{item}` with their repositories and how each joined ([#699](https://github.com/byFrederick/goal/pull/699)).
- A new item's branch names its factory: `goal/<factory>/<number>-<slug>`, such as `goal/acme-web/42-fix-the-login-page`, so two factories working in one repository never share a branch. The branch is kept when the item is filed, so renaming the item or its factory later never moves it. Existing items keep the branch they have, `goal/<number>-<slug>` ([#690](https://github.com/byFrederick/goal/pull/690)).
- New trigger offers Check with an agent next to Schedule, and lists the factory's tools as what a check can look at. Continue opens a blank trigger in the definition instead of a missing page. The dialog's suggestions, and the onboarding Intake step's starter triggers, are now the definition's disabled triggers from the API, and the step lists `goal run` among the ways work is always on.
- An organization's webhook answers when GitHub's ping last arrived (`pinged_at`) and the events to choose in the sender's settings (`setup_events`, and `setup_all_events` when a trigger takes every event), read from the enabled triggers of the factories it is open to. GitHub's ping no longer keeps a row in the delivery log. Each delivery in the log shows its event, its receipt (accepted, duplicate or refused), how many duplicates it counted, and its evaluation by each factory: created with the item, such as `acme#88`, skipped with the reason, or failed with the error. A factory's own delivery log shows only that factory's evaluation ([#664](https://github.com/byFrederick/goal/pull/664)).
- The page error card says "goald is not answering" only when goald is unreachable: the network failed, or it answered 502, 503 or 504. A crash in the page itself now reads "This page hit an error", with Reload and the detail behind an ⓘ. On a knowledge source at 390 px, the Files table scrolls in its own container, so Reads, 7 days can be reached. Floor's Activity entries wrap to a second line, so the actor and the station always show. An assembly's Spend shows only what was spent, because the per-item budget limits one task, so parts times it was not a budget.
- Kept tests now run. Every proposal that reaches a kept test's station is tried on it, once, or three times for a model proposal, and its `tried.kept_tests` shows each try as running, passed, failed or error. The publish dialog's route, `…/draft/kept-tests`, starts the kept tests the draft reaches and reads their results; a failing test warns and never blocks a publish, and a draft with a tried proposal's exact content reuses its tries. Each kept test shows its last result, and `goal test keep`, `goal test list` and `goal test rm` manage them from the CLI ([#590](https://github.com/byFrederick/goal/pull/590)).
- Tries of a proposal on past items are graded by a grader, a model checked first on each item's original and final results. When it misreads either one, that item's tries are `unknown`. A try whose run failed is `not_fixed`. `GET …/jonah/proposals/{number}` shows the grader's two hit rates as `tried.grader`, and `tried.cost_usd` includes the grader's checks ([#595](https://github.com/byFrederick/goal/pull/595)).
- A past item can be kept, at a station it passed the first time, as a test the item must keep passing there. The API lists, keeps and removes kept tests (`…/jonah/tests`); there is no CLI or screen for them yet, and publishing does not run them yet ([#584](https://github.com/byFrederick/goal/pull/584)).
- The organization policy's Use secrets values are `environment` and `off`. `attached_only` is still accepted in the API (`use_credentials`) and is saved as `environment`. The environment's MCP card lists each tool's standing rules with Revoke, and the sidebar search shows Secrets where it showed Connections.
- Connections are gone from the app. An agent's page has an Environment select instead, the Agents page shows each agent's box and the factory's environments, and Factory settings shows the repository's token with a "Token works" chip, the model key and one chip per environment. Onboarding's Code step takes a repository address and a token, saves the token as a secret and tests that Goal can clone and push before you continue; no app is needed. A synced knowledge source reads with a secret. Needs you, Members, Spend, Intake, Models and Webhooks say secrets and servers where they said connections and credentials. The Access and secrets page replaces Connections in the docs ([#506](https://github.com/byFrederick/goal/pull/506)).
- Credentials is now Secrets, with a list, a page for each secret, and Import. New secret opens a side sheet where you paste a value; nobody can read it back. A secret's page shows where it is used, its activity, Replace value, its settings and Delete, which is disabled while anything uses the secret. Import takes a `.env` file or YAML, shows what would happen first, and replaces or skips names that exist. The old `/credentials` addresses open Secrets.
- The Board's Expedite lane is one yellow box per column again, all at the same top and height, labelled just Expedite in the first column. From 1280 px wide every station fits without scrolling sideways. The caption with the lane's use stays gone, and on a phone the lane shows only the Expedite chip.
- The Agents page shows each agent once per station, even when a route sends several lanes to it. The card's label lists every lane it takes, and items with no lane read "no lane".
- On the agent's Overview, Why review sent work back shows each reason in sentence case on one line, with the full text in a tooltip, and a solid red bar. Settings values are regular weight, Skills shows the first seven with a + N more chip, and the stat strip keeps four figures on one line from 768 px up.
- The Agents page line fits at 1440 px without sideways scrolling. Stations use sentence-case names, the constraint station is marked with a yellow dot, work-in-progress bars use colour only for meaning, lane labels line up with their cards, and primary buttons are near-black.
- Factory settings has Save changes in the top bar, shows every section open, adds a read-only Badge row, shows the repository with its connection and a Change button, and marks the section in view in the "On this page" list.
- The agent's page shows the agent's name in the top bar, with Bake off this agent, Open prompt file and Save changes there, and its tabs are an underline row with the tasks finished this week on Runs.
- New trigger shows its sources as plain icons, keeps its title and step on one line, lists suggestions one per row, and shows a Connect link to Connections for GitHub when the organization has no GitHub connection. The top bar reads Intake > New trigger.
- Intake and Webhooks show their place in the top bar, Intake uses the same page width as the other pages, and neither scrolls sideways on a phone. The Webhooks empty state no longer repeats New webhook.
- Factory settings shows the factory's purpose (metadata.purpose). Intake records where each submitted item came from: people in the browser, the CLI or a personal token, or an API key. Its headline counts only items with a known source, so older items submitted before this change drop out of it ([#415](https://github.com/byFrederick/goal/pull/415)).
- Models and policies has a breadcrumb and an ink Save changes. Tool policy shows Ask a person in orange and Allowed in green, the Harness option you pick has an ink border, denied commands are neutral chips, and the page shows a skeleton while it loads.
- The Agents page shows how many items are at each station now, with a bar against its WIP limit. The agent's page has Reset to default beside the prompt and beside an agent's own model.
- The agent prompt editor has Reset to default, which restores the running version's prompt file into the draft, and New trigger offers suggested triggers under Or start from a suggestion ([#352](https://github.com/byFrederick/goal/pull/352)).
- Publish shows a check and the version that is running once a version publishes. A station you drag settles into its new row, and new triggers and agents fade into their lists. Pages that are loading show the shape of their content ([#352](https://github.com/byFrederick/goal/pull/352)).
- The Jonah and Agent tabs use a pill that slides to the tab you open. Definition sections are a plain list beside the form. Agents, Judges and Bake-offs lose their icon tiles and explanatory cards ([#352](https://github.com/byFrederick/goal/pull/352)).

## Week of 2026-10-26

- Goal sends notifications by email and Slack, and a daily digest. Each person chooses their channels on their account page; Slack direct messages use one secret an organization admin picks ([Set up notifications](/docs/guides/set-up-notifications/), [#341](https://github.com/byFrederick/goal/pull/341)). An owner can also limit sign-up to one email domain: Members' "Only emails at a domain" lets a verified address at that domain sign up and join as a viewer, and `PUT /v1/orgs/{org}/settings/signup-domain` sets it.
- The docs site is served at `/docs`, with search and `llms.txt` files for agents ([#342](https://github.com/byFrederick/goal/pull/342)).
- Jonah reviews run in goald. Look for improvements now, and `goal jonah look`, start a review at once, and a review is held back once Jonah's recent runs have used its budget ([Jonah](/docs/concepts/jonah/), [#323](https://github.com/byFrederick/goal/pull/323), [#317](https://github.com/byFrederick/goal/pull/317)). The button was disabled in between, until the review loop shipped.
- The desktop sidebar resizes from 216 to 400 px by dragging its right edge or with the arrow keys; letting go below 160 px folds it into the rail, and double-clicking the edge resets it to 256 px ([Navigate and shortcuts](/docs/guides/navigate-and-shortcuts/), [#327](https://github.com/byFrederick/goal/pull/327)).
- A landing assembly that is sent back to build hears a rework note, to fix what the rejection asks for and push to its integration branch, instead of the landing note, which only the landing station gives ([#310](https://github.com/byFrederick/goal/pull/310)).
- A run's prepare step retries the network git steps (the clone, and the base branch's push and fetch) up to 3 attempts after dropped connections, and limits each attempt to `GOAL_GIT_ATTEMPT_TIMEOUT` (300 seconds by default). Before, a dropped GitHub connection could hang prepare for minutes and then fail the run ([#253](https://github.com/byFrederick/goal/pull/253)).
- The Floor shows the andon panel for the line, a Hands-off tile with the share of work no person touched, its trend and its change against the range before, Needs you, Where work waits, Throughput by week and Activity cards, and a Today, 7 days or 30 days window. Where work waits can show what one more agent at the constraint would give, in lead time and daily spend, and Add a build agent raises that station's agents by one in a draft for you to review and publish. Activity reads `GET …/factories/{factory}/activity`, a factory's latest milestone events ([The andon](/docs/concepts/andon/), [#195](https://github.com/byFrederick/goal/pull/195), [#211](https://github.com/byFrederick/goal/pull/211), [#218](https://github.com/byFrederick/goal/pull/218), [#154](https://github.com/byFrederick/goal/pull/154), [#165](https://github.com/byFrederick/goal/pull/165)).
- A factory definition can have an optional `starter.item`, the item onboarding submits once for a factory with no items ([#231](https://github.com/byFrederick/goal/pull/231)).
- GitHub connections listed the owners and repositories they could reach, so a person could pick code to connect ([#136](https://github.com/byFrederick/goal/pull/136)). Connections have since been removed; a factory's repositories are set in `runtime.repositories` ([Connect code to a factory](/docs/guides/connect-code/)).
- The interface was revamped on 2026-10-27. It has new colours and fonts from the design system, one 256 px sidebar that collapses to a 60 px rail, a top bar with a breadcrumb and the page's actions, a phone layout with a top bar, a drawer and a five-tab bar, and C to open New item with a factory picker ([Navigate and shortcuts](/docs/guides/navigate-and-shortcuts/), [#128](https://github.com/byFrederick/goal/pull/128), [#129](https://github.com/byFrederick/goal/pull/129), [#130](https://github.com/byFrederick/goal/pull/130), [#131](https://github.com/byFrederick/goal/pull/131), [#140](https://github.com/byFrederick/goal/pull/140), [#156](https://github.com/byFrederick/goal/pull/156), [#158](https://github.com/byFrederick/goal/pull/158), [#159](https://github.com/byFrederick/goal/pull/159), [#160](https://github.com/byFrederick/goal/pull/160), [#168](https://github.com/byFrederick/goal/pull/168)). Home, the Items list and the item page, the Board (and its phone layout), the Definition editor and its publish screen, Factory settings, Knowledge, Members, organization settings, API keys, sign-in and device approval were restyled to the new screens ([#191](https://github.com/byFrederick/goal/pull/191), [#193](https://github.com/byFrederick/goal/pull/193), [#194](https://github.com/byFrederick/goal/pull/194), [#197](https://github.com/byFrederick/goal/pull/197), [#201](https://github.com/byFrederick/goal/pull/201), [#202](https://github.com/byFrederick/goal/pull/202), [#203](https://github.com/byFrederick/goal/pull/203), [#204](https://github.com/byFrederick/goal/pull/204), [#205](https://github.com/byFrederick/goal/pull/205), [#206](https://github.com/byFrederick/goal/pull/206), [#208](https://github.com/byFrederick/goal/pull/208), [#210](https://github.com/byFrederick/goal/pull/210), [#212](https://github.com/byFrederick/goal/pull/212), [#213](https://github.com/byFrederick/goal/pull/213), [#217](https://github.com/byFrederick/goal/pull/217), [#223](https://github.com/byFrederick/goal/pull/223), [#250](https://github.com/byFrederick/goal/pull/250), [#280](https://github.com/byFrederick/goal/pull/280)).
